### P1｜[OneLA: Scaling Linear-Attention Decoding to Large Beams in Generative Recommendation](https://arxiv.org/abs/2609.12399)

**论文、机构与场景**

arXiv 预印本 2609.12399v1，作者来自香港大学、快手科技与北京大学，面向快手工业级生成式推荐（SID 序列大 beam 解码）的解码系统优化。

**核心方法**

OneLA 用单个共享 post-prefill 循环状态 Sctx 加紧凑 append-only 的 GDN Transition Record（GTR，含 α、δ、k）表示所有 beam 状态，只按投影重放分支特有转换，不物化每条 beam 的 d_v×d_k 完整状态矩阵；用轻量 ancestry index 解耦逻辑 beam 演化与物理记录位置，beam 剪枝/重排/扇出只复制索引而不搬移 GTR；并实现 fused shared-context GPU kernel，将投影重放保持在片上并跨 beam 复用 Sctx；评测基于 0.8B Qwen3.5（6 层 full attention + 18 层 GDN），全模型设 R=4、W=256、prompt 1K/5K、输出 3–7 token；算子套件覆盖 405 个形状（R=4/8/16、W=128/256/512、T=2–6、九种循环几何）。

**主要创新或优化点**

生成式推荐需大 beam 解码产生数百候选，使线性注意力的循环状态存储与带宽成为新的扩展瓶颈；该工作给出共享状态+紧凑转换记录+祖先索引+融合 GPU kernel 的可复现系统方案，直接压缩解码时延与显存/DRAM 开销。

**关键结果**

全模型 decode-forward GPU 时间相对 Controlled FullState 降低 1.54–2.46×，覆盖全部评测 prompt 与输出长度，且一致优于 vLLM FullState/ReplaySSM；算子级中位加速：相对 vLLM 与 SGLang FullState 为 40.5×/42.5×，相对两条 ReplaySSM 路径为 17.5×，相对 FlashInfer 与 TensorRT-LLM 为 41.5×/46.3×；405 个算例相对 FP32 FullState 最大绝对输出误差 4.88e-4；R=4、W=512 的 Qwen 几何下循环状态路径延迟降低 39.7×/35.4×，持久状态容量降低 56.5×/20.3×，状态写入降低 127×，DRAM 流量 161 MiB（相对 FullState 76.9×、ReplaySSM 39.9×）。

**与你的关联**

对生成式召回线上服务的大 beam 解码、线性注意力/SSM 推理引擎实现、显存与带宽瓶颈优化有直接参考价值，可作为 GR serving 侧的复现基线。

**可信度**

technical_report

**风险或局限**

仅离线评测，无线上 A/B、生产部署或 QPS/成本指标；基线为受控实现与开源 serving 框架；输出长度仅 3–7 token，强依赖“长共享 prompt + 短分歧后缀”假设，长解码、多轮或 prompt 极短场景未验证；未披露业务侧指标（CTR/GMV/召回质量）与端到端成本变化，收益归因集中在时延、显存与 DRAM 流量。


### P1｜[Recommendation Retrievers Need Verifiers: Universal Generative Reranking for Sequential Recommendations](https://arxiv.org/abs/2609.12270)

**论文、机构与场景**

Meta MRS 的 arXiv 预印本（arXiv:2609.12270v1）研究多阶段推荐系统中首阶段召回短名单的覆盖率问题，用 post-hoc verifier 把相关物品提升进被下游排序消费的前缀；在 Amazon Reviews（Industrial/Office）商品推荐与 YaMBDa 音乐推荐上评测。

**核心方法**

冻结召回器、只对其 top-K 候选池（Amazon 100、YaMBDa 1000）重排：2 层 2 头宽 128 因果 Transformer verifier 按物品标识 token（4 级 RQ 语义 ID + 4 头 hash ID）的自回归对数似然打分，再以加权 RRF（κ=60）与原序融合并保留原序尾段；训练只用 next-token 交叉熵监督每个非 padding 前缀位置，不需要采样负样本、in-batch 负样本或候选池；召回器冻结以避免破坏其广召回目标，推理只对池内候选重算并与其他阶段解耦；结果：Amazon Industrial Recall@10 提升 SASRec +6.2%、GRU4Rec +8.1%、NextItNet +8.4%，Office 为 +9.9%/+10.8%/+14.5%；YaMBDa-5B 上三者 +25.3%/+27.3%/+29.8%。

**主要创新或优化点**

在召回与精排之间插入轻量输出侧验证器，不改召回器、不重建索引即可把被下游消费的小前缀 Recall@k 抬高，为多阶段链路提供低成本的召回池重排/短名单提升方案。

**关键结果**

YaMBDa-50M/500M/5B 上 NextItNet 的 Recall@10 相对提升 +14.4%/+24.2%/+29.8%，作者归因于目录稀释：目录越大，召回池内可回收的相关物品越多；Amazon 上同一 verifier 配方提升全部三个序列召回器与 LLM 生成式召回器 MiniOneRec，但强召回器提升最小（MiniOneRec 仅 +2.6%/+4.6%）；标识通道消融：YaMBDa-500M 上 hash-only 已接近全量（SASRec 4.75 vs 4.88 Recall@10，语义-only 4.38）；小目录 Amazon 上语义 ID 更好；内容对照中 +C 召回器单独更差（3.47 vs 4.16），内容-only 召回器被 verifier 提升 +247–289%。

**与你的关联**

直接对应推荐系统首阶段召回短名单质量与召回-粗排衔接问题；接口仅需召回器状态与固定物品 token 化，可复用到现有自注意力/RNN/卷积/生成式召回模型，评测与消融设计也可借鉴。

**可信度**

technical_report

**风险或局限**

全部为离线 Recall@k 评测，无在线 A/B、生产部署、时延或成本数据，多阶段收益未在生产链路验证；verifier 只重排冻结召回器的 top-K 池，无法召回池外物品；池大小 K 与融合权重 w 依赖验证集调参，强召回器上提升有限；Amazon 目录仅数千物品且未过滤已看历史项，YaMBDa 无文本、MiniOneRec 无法适用；未与完整精排或价值模型对比。


### P2｜[Preference-Drift-Aware Subsequence Learning and Hierarchical Context Fusion for Long-Sequence Generative Recommendation](https://arxiv.org/abs/2609.12556)

**论文、机构与场景**

arXiv 论文 v1，标题为 Preference-Drift-Aware Subsequence Learning and Hierarchical Context Fusion for Long-Sequence Generative Recommendation，作者 Fei Li、Qingyun Gao、Jianzhe Zhao、Guibing Guo、Beibei Kong、Lei Cheng、Chengxiang Zhuo、Zang Li，机构未披露；场景为长序列用户交互序列自回归生成下一物品表征的生成式推荐。

**核心方法**

方法用多维偏好漂移信息学习可微软子序列边界，并以带软分配权重的线性注意力将子序列内物品聚合为偏好一致表征，以避免全长序列注意力开销；再用 cross-attention 捕捉近期交互与相关子序列上下文依赖，最后通过门控融合将近期物品表征与全局子序列上下文合并为目标表征；摘要称现有全长序列建模随长度增加算力持续增长且精度饱和甚至被噪声拖累，目标感知上下文检索则受语义一致但偏好不一致噪声与上下文不完整影响。

**主要创新或优化点**

长序列生成式推荐的效率与偏好漂移建模是当前召回侧重要问题，该工作把软子序列边界、线性注意力聚合与层次上下文融合组合起来，提供一条可参考的技术路线。

**关键结果**

摘要称在推荐准确率与计算效率上一致优于现有基线，但未给出具体数据集、指标数值或线上 A/B；摘要给出的是定性结论，未披露效率提升倍数、序列长度上限或延迟指标。

## 序列建模与兴趣表征

### P0｜[ChronicleRec: Pre-training Temporally Anchored Tokens for Lifelong User Modeling](https://arxiv.org/abs/2609.12375)

**论文、机构与场景**

Tencent Inc.（微信广告）与 University of New South Wales 合作的 arXiv v1 预印本（arXiv:2609.12375），面向微信朋友圈广告 pCVR 预测的超长用户行为序列建模，实验用公开 KuaiRand-27K 与腾讯内部 AdLive 直播广告数据。

**它解决的旧问题**

把 lifelong user modeling 从逐候选 target-attention 检索（SIM/ETA/SDIM/TWIN 范式）改为一次性、目标无关、可缓存的时间锚定 token 预训练，并给出微信朋友圈广告七天线上 A/B 与生产部署证据，属超长序列精排的工程路线变化。

**核心方法**

将超长行为序列一次性压缩为按时间锚点排序的 Chronicle Tokens：近/中/远三段 recency-aware 多粒度合并（近端最近 100 条 1:1 保留，中段 kernel/stride=8/4，远端 10/10），查询 token 与合并序列交错，由因果编码器使每个 token 只摘要其时间锚点之前的历史；多分支多时间跨度设计用 δj={0,100,300,600,1000} 分别屏蔽最近若干条行为，配合 mask-and-predict 的 Chronicle Alignment 预训练把压缩历史对齐近端意图；P=11 个默认查询 token，分支前缀加权拼接后送入共享排序头；Chronicle Tokens 与候选无关，可离线/异步计算并按用户缓存（KV Cache/特征库）后供下游排序模型复用，把超长序列编码与在线候选打分解耦；线上部署于微信朋友圈广告 MixFormer 排序模型的 NS-Token 与 S-Token 通路。

**主要创新或优化点**

把 lifelong user modeling 从逐候选 target-attention 检索（SIM/ETA/SDIM/TWIN 范式）改为一次性、目标无关、可缓存的时间锚定 token 预训练，并给出微信朋友圈广告七天线上 A/B 与生产部署证据，属超长序列精排的工程路线变化。

**关键结果**

GAUC：KuaiRand 上 Multi-ChronicleRec 0.5580，距 Full-Attn 0.5601 差 0.0021，高于 VISTA 0.5518 与 Short-Attn 0.5307；AdLive 上 0.8034，对 Full-Attn 0.8071、VISTA 0.7995、Short-Attn 0.7950；AdLive 消融：去 Chronicle Alignment −0.0086、去 recency-aware merge −0.0076、去因果掩码 −0.0074、去 multi-branch −0.0072、去 deep supervision −0.0039 GAUC；查询交错+因果相对末端+双向提升 0.0144/0.0104；微信朋友圈广告 pCVR 七天线上 A/B：GMV +1.61%，95% 置信区间 [0.678%, 2.547%] 不含零；训练显存 28.0GB、620.3 分钟，约为 Full-Attn（49.1GB、2997.0 分钟）的 4.8 倍加速。

**收益归因**

主要来自 以目标无关、可缓存的 Chronicle Tokens 替代逐候选超长序列检索，降低长序列建模成本并提升精排效果（线上 GMV +1.61%）；次要因素为 serving_efficiency；long_sequence_compression；cacheable_user_representation；pretrain_transfer。

**与你的关联**

直接对应广告/短视频精排的超长行为序列建模与算力瓶颈：可缓存用户表征替代在线 per-candidate 检索，可迁移到自有特征库或 KV 缓存链路，兼顾效果与延迟。

**风险或局限**

线上仅给出 GMV +1.61% 与置信区间，未披露分流设计、延迟/QPS、推理与缓存写入成本、实验时长之外的稳定性细节；离线精度仍低于 Full-Attn，评测只用点击/转化标签，未见其他业务指标、第三方复现或公开线上数据；AdLive 为腾讯内部数据不可复现；arXiv v1 未见同行评审或正式发表信息（模板会议页眉）。

### P0｜[InitGen: Candidate Generation for Interaction Initiation in Intelligent Assistants](https://arxiv.org/abs/2609.11953)

**论文、机构与场景**

InitGen 是 arXiv 论文（arXiv:2609.11953v1，cs.IR），作者来自华中科技大学与 OPPO AI Center，场景为 OPPO 小布助手在用户尚未表达意图时，于助手启动瞬间生成候选查询的交互发起（interaction initiation）候选生成模块。

**它解决的旧问题**

给出了在无显式意图、无预定义候选池的生成式候选场景下，处理反馈粒度不匹配与部分反馈的完整工业做法：集合级而非单条级偏好对齐、用下游排序分作为反馈置信度权重、按用户活跃度重加权、滚动窗口日更；并附可信线上 A/B 与消融，是可迁移到生成式候选链路的参考。

**核心方法**

方法上以 Qwen2.5-1.5B 为底座，先用历史交互数据做 SFT，再用集合级加权 KTO（WKTO）对齐：把 K 条候选查询作为一次序列化输出联合生成，权重为用户活跃度权重 w_u 与下游排序分权重 w_r 的几何平均；反馈只来自经下游过滤与排序后曝光的子集，因此以整个生成查询集为对齐单元（集合内有任一点击记为正），无曝光查询的请求被剔除；排序分只缩放对齐信号强度，不作为优化曝光或排序的目标；已全量部署于小布助手（服务超 1.5 亿月活），用 vLLM 在 20 张 A100 80GB 上服务，峰值超过 12K QPM 时集合生成延迟约 150ms，低于 180ms 预算；滚动窗口按日离线更新，不增加线上延迟。

**主要创新或优化点**

给出了在无显式意图、无预定义候选池的生成式候选场景下，处理反馈粒度不匹配与部分反馈的完整工业做法：集合级而非单条级偏好对齐、用下游排序分作为反馈置信度权重、按用户活跃度重加权、滚动窗口日更；并附可信线上 A/B 与消融，是可迁移到生成式候选链路的参考。

**关键结果**

线上 A/B（相同流量分配、下游过滤排序不变）：曝光 3,810,832→4,492,970（+17.9%），点击 36,263→72,328（+99.5%），CTR 0.95%→1.61%（相对 +69.1%），七天逐日均为正增益；逐级配对线上消融：加入地理与用户画像上下文 +11.6%，再加活跃度权重 w_u +5.7%，再加排序分权重 w_r +19.6%，再加滚动日更 +20.1%；w_u 的增益集中在低 CTR 用户群（0.78%→0.85%，+9.0%），高 CTR 群基本持平；效率：一天内 QPM 从约 1K 升至峰值 12K 以上，延迟集中在约 150ms，峰值流量下未出现持续延迟上升。

**收益归因**

主要来自 集合级加权 KTO 对齐（含活跃度权重 w_u 与排序分权重 w_r）叠加上下文输入与滚动日更，提升生成候选质量，使更多候选通过下游过滤并被点击；作者以逐级线上配对 A/B 归因，未完全解耦各组件交互效应；次要因素为 曝光候选点击率显著提升（0.95%→1.61%）；生成候选的曝光量提升 17.9%；严格延迟预算下可服务（约 150ms，20×A100，峰值 >12K QPM）。

**与你的关联**

与生成式候选产生、LLM 对齐和线上反馈闭环直接相关：集合级对齐单元、下游排序分作置信度权重、活跃度重加权、滚动日更都是可复用的工程手段；但输出是面向用户展示的自然语言查询而非 item/SID，与短视频/电商 item 级召回链路不完全对应。

**风险或局限**

实验限于 OPPO 小布助手单一产品与场景，CTR 定义为点击/曝光候选查询，非通用的 item 级推荐指标；消融采用分时段逐级配对 A/B（每个变体只与前一代比较，非同期同窗对照），上下文、权重与滚动更新之间存在时间混杂，归因不彻底；数据集、代码、完整 prompt 与加权超参 c 的取值未公开，且依赖内部画像与下游排序分，复现性受限。


### P2｜[Enabling and Understanding Personalization in AI-Generated Advertising Imagery](https://arxiv.org/abs/2609.12697)

**论文、机构与场景**

arXiv:2609.12697v1，作者Victor Kolominsky-Rabas、Leopold Müller、Claudius Budcke、Claas Christian Germelmann、Niklas Kühl，机构未披露；场景为从客户数据自动生成个性化广告图像。

**核心方法**

提出一个基于AI的个性化广告图像生成框架，直接从客户数据生成图像，区别于传统静态产品匹配与文本/基础图像修改的动态创意优化；开展两阶段被试内实验，N=100名参与者，覆盖4种产品、3个个性化水平（按使用客户数据的数量与具体程度划分）；参与者对每张图像评测广告态度、产品态度与购买意愿三项结果指标。

**主要创新或优化点**

指出生成式广告图像个性化存在中等强度最优的非单调效应，且诡异感是压制高个性化收益的主导机制，为生成式广告创意的个性化强度设计提供实证依据。

**关键结果**

参与者能感知不同个性化水平的差异，中等个性化水平的AI生成广告图像评价最高；高个性化提升感知个性化，感知个性化与三项结果指标正相关；高个性化同时提升感知诡异感（creepiness），诡异感与结果指标负相关并在总效应中占主导。

**与你的关联**

对生成式广告创意系统的个性化强度调节与用户体验风险控制有直接参考价值，可用于创意生成策略与投放强度设定。

**可信度**

peer_reviewed_paper

**风险或局限**

仅N=100被试内实验，4种产品，非线上真实广告A/B，无法支撑真实CTR/CVR/GMV结论；未披露生成模型架构、训练数据与生成质量细节，可复现性有限；结果基于主观问卷（态度与购买意愿），非实际行为转化指标。


### P2｜[I Am AdMan: A Pipeline for Automatic Generation of Personalized Advertising Imagery](https://arxiv.org/abs/2609.12694)

**论文、机构与场景**

arXiv 论文 AdMan，作者来自 Victor Kolominsky-Rabas 等，机构未披露；场景为将客户数据转化为 persona 并自动生成个性化广告图像。

**核心方法**

方法为多智能体流水线：客户数据转 persona，条件于产品参考图生成个性化广告图，并用 LLM judge 做自动质量把控；实现两种模型配置，覆盖四个产品、六个名人 persona 定性检查与 100 个真实客户档案，产出 1745 条广告；评估结合专家焦点小组定性分析与 artifact-rate 定量评估，非线上 A/B 或生产部署。

**主要创新或优化点**

展示把客户画像系统性转化为可规模化的 AI 生成广告创意，并引入 LLM judge 做创意质量控制，属于生成式广告创意与反馈闭环的前沿探索。

**关键结果**

定性结果显示流水线可生成照片级真实且个性化的广告图；效果随产品复杂度与模型配置差异显著；摘要未披露具体 artifact rate 数值、CTR/CVR 或转化指标。

**与你的关联**

与广告创意生成、个性化素材生产及 LLM 质量把控相关，但不在召回/排序链路，与核心搜广推排序工作关联偏弱。

**可信度**

**风险或局限**

仅离线专家评估与 artifact-rate，无线上 A/B 或转化指标；效果对产品复杂度和模型配置敏感，泛化性未验证；摘要证据，PDF 未核验，具体指标与 judge 可靠性未知。

## 今日最值得立项的实验

### 可缓存Chronicle Tokens替代逐候选超长序列检索

- 假设：在自有精排模型上用与候选无关、可离线缓存的Chronicle Tokens承接超长行为序列，可在不牺牲GAUC的前提下显著压缩训练/推理显存与长序列编码成本。
- Control：现有per-candidate target-attention长序列检索通路（SIM/ETA范式），保持特征与排序头不变。
- Treatment：按时间锚点三段recency-aware合并+因果编码器生成Chronicle Tokens，离线/异步计算并写入用户KV缓存，排序头只读缓存表征。
- 保持变量：训练数据窗口、候选集、排序头结构、损失函数、离线评测口径保持一致。
- 离线指标：GAUC/AUC；Recall@k前缀；训练显存峰值；单step训练时间；长序列编码延迟与缓存命中率
- 线上 Guardrail：线上pCVR/GMV不劣于基线；服务P99延迟与QPS不下降；缓存写入与失效链路不引入额外故障

### 召回头部前缀的verifier重排

- 假设：在冻结召回器后接轻量生成式verifier按物品token似然重排top-K池，并用加权RRF融合，可不重训召回、不重建索引地提升被下游消费前缀的Recall@k。
- Control：冻结召回器原序直接截断给下游。
- Treatment：对召回top-K池用2层因果Transformer verifier打分，加权RRF（κ=60）与原序融合并保留原序尾段。
- 保持变量：召回器权重、候选池大小K、下游排序链路与评测数据完全不变。
- 离线指标：前缀Recall@10/Recall@50；NDCG@k；verifier打分延迟与打分吞吐
- 线上 Guardrail：召回池外物品不被丢弃导致总覆盖率下降；线上CTR/GMV不劣化；融合权重w与K不在验证集上过拟合

### 生成式召回大beam解码的共享状态优化

- 假设：对SID自回归大beam解码用共享post-prefill状态+紧凑转换记录替代逐beam物化状态，可在等精度下显著降低解码时延与显存/DRAM开销。
- Control：现有逐beam FullState或ReplaySSM解码路径。
- Treatment：共享Sctx+append-only GTR+ancestry index，融合共享上下文GPU kernel，按投影重放分支特有转换。
- 保持变量：模型结构与权重、prompt长度、beam宽度W与重放R、输出长度对齐评测。
- 离线指标：decode-forward端到端GPU时间；循环状态显存容量；DRAM流量与状态写入量；beam输出的数值误差
- 线上 Guardrail：输出的SID候选与基线数值误差在可接受范围；线上召回质量指标不下降；长prompt/短后缀假设外场景延迟不退化


## 一句话总判断

本期主线从逐候选在线检索转向目标无关可缓存的用户表征与大beam解码系统优化：ChronicleRec用时间锚定Token把超长序列编码与候选打分解耦，OneLA用共享循环状态压缩生成式召回解码开销，二者共同指向长序列/大beam场景的服务成本与显存带宽瓶颈。第二主线是召回与下游之间的轻量校验层开始成型：verifier重排短名单、InitGen集合级对齐用下游排序分作反馈权重，均为不改召回器/索引的低成本增益手段。需注意线上证据仅ChronicleRec与InitGen具备，其余多为离线或摘要级结论。
