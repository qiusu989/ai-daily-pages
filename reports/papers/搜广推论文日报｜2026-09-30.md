## 生成式召回

### P1｜[FineSID: Scalable and Efficient Semantic Identifier Learning for Generative Recommendation](https://arxiv.org/abs/2609.36670)

**论文、机构与场景**

- **机构：清华大学、华为诺亚方舟实验室、中国科学技术大学**
- 作者：Song-Li Wu、Weinan Gan、Zhaocheng Du、Xianquan Wang、Jingyi Wang
- 来源：arXiv:2609.36670v1（PDF 标注 AAAI 2027 版权）
- 场景：生成式推荐中的语义标识（SID）量化学习与下一物品预测

**核心方法**

- FineSID 的核心是全局-局部量化 GLQ：LRQ 对所有码字计算 softmax 软分配，并用 STE 让前向使用 GAQ 的 Top-1 硬索引、反向传播软梯度，避免死码字。
- GAQ 用码字使用频率的 EMA 自适应调整更新率，使用越少的码字更新率越高，从而将欠利用码字拉向高密度语义区域。
- QSCM 增加双向量化语义一致性损失，对齐连续物品表征 z 与离散 SID 重构 z_hat
- 总目标为 L_rank + L_GLQ + L_QSCM，在 RQ-VAE 三层码本每层 256 码字上训练 T5 自回归推荐模型。

**主要创新或优化点**

- 针对生成式推荐中 Top-1 硬分配导致的 SID 碰撞和码本塌缩，提出不依赖启发式初始化或后处理的全码本优化，能改善长尾物品 SID 质量并降低训练时间，对生成式召回物料 tokenization 有直接参考价值。

**关键结果**

- Table 2：在 Instrument/Scientific/Game 三个公开数据集上，FineSID 的 Recall@10 分别为 0.0703、0.0514、0.1031，均显著高于 CAR（0.0624、0.0455、0.0947）等基线，p<0.01 或 p<0.0001。
- Figure 2：FineSID 码本利用率 100%、balance rate 0.4812
- 在码本大小 256 到 4096 的扩展实验中维持最优利用率。
- Table 5：相比最强基线 CAR，FineSID 训练收敛时间减少超过 50%（Game 9.3h vs 24.5h、Instrument 4.8h vs 13.3h、Scientific 3.7h vs 11.9h）。

**收益归因**

- 主要：离线实验中 GLQ/QSCM 带来的全码本梯度传播与语义对齐：提升码本利用率、降低 SID 碰撞并加快训练收敛；线上部署收益未核实。
- 次要：训练收敛更快，训练时间相比 CAR 减少超过 50%
- 次要：长尾物品性能提升
- 次要：对初始化策略和码本大小扩展更鲁棒
- 次要：推理时间未增加且部分数据集更快

**与你的关联**

- 与用户关注的生成式推荐、SID 学习、RQ-VAE 替代方案及召回阶段物料 tokenization 直接相关；可作为评估是否替换现有 Top-1 量化方案的候选。

**风险或局限**

- 全部结果来自公开离线数据集与离线全排序评测，未提供线上 A/B、生产部署或工业规模流量验证。
- 主要实验使用 T5 6 层 backbone 和 K=3、每层 256 的码本
- 虽补充 Qwen-1.5B/3B/7B 实验，但工业级超大目录和长序列场景未验证。
- 收益归因集中在 SID 量化学习阶段，未证明与现有工业生成式召回系统端到端集成后的 QPS、延迟和成本收益。


### P2｜[GRP v0.1 Technical Report](https://arxiv.org/abs/2609.36688)

**论文、机构与场景**

- **机构：Snap Inc.（首页署名 GRP Team, Snap Inc.）**
- 作者：Wenfeng Zhuo, Vincent Xue, Charles Wei, Cong Ni, Ruiming Lu, Jiwen Ren, Mo Li, Peng Yang, Xufei Wang, Dongheng Li, Jiacong He, Yi Song, Yufei Fan, Mikhail Obukhov, Yiwen Chen, Yvette Liu, Yin Ye, Chengjie Wu, Mingtao Zhang, Jinchao Ye, Lili Zhang, Chunhui Zhu
- 来源：arXiv 2609.36688v1
- 场景：工业推荐系统多阶段级联（召回/排序/服务）的生成式端到端推荐探索

**核心方法**

- GRP 将检索、排序与奖励建模合并到单一 encoder-decoder 模型中，生成多模态 Semantic ID 作为候选表示。
- 排序模块与生成模块联合训练，冻结后的排序模块为强化学习后训练提供奖励信号。
- 提出 mGRPO，在奖励优化中加入 reference-anchored margin，以保持已记录目标（logged targets）的似然。
- 离线实验覆盖历史编码、模型容量分配、事件选择、tokenization 与奖励判别等维度
- 服务优化使端到端检索延迟降低 69%。

**主要创新或优化点**

- 少数公开披露的生成式统一检索-排序-奖励框架，含线上 A/B 与延迟指标，可观察生成式召回在工业级渐进部署中的真实收益与边界。

**关键结果**

- 服务优化使端到端检索延迟降低 69%。
- 仅作为召回源的线上对比中，view time 提升 0.46%，shares 提升 0.77%（相对 production）。
- 结合 early-ranking bypass 与替换较弱来源的对比中，view time 提升 0.82%，shares 提升 2.56%，平台级 guardrail 保持中性。

**收益归因**

- 主要：生成式统一检索-排序框架带来线上 view time 与 shares 提升，并降低检索延迟
- 次要：RL 后训练保持 logged targets 似然
- 次要：服务优化取得 69% 端到端检索延迟下降

**与你的关联**

- 与生成式召回、Semantic ID、RL 后训练及多阶段级联替换方向直接相关，可用于判断渐进式部署路径。

**风险或局限**

- 排序质量与多项推荐指标仍存在未弥补的差距（摘要自述 remaining gaps）。
- 线上收益为个位数百分比，且部分对比依赖 early-ranking bypass 与来源替换的组合条件。
- 多模态 Semantic ID 与奖励判别的具体实现细节、数据规模与训练成本未在摘要中披露
- PDF 未核验。


### P2｜[OneLatent: Latent Reasoning for Efficient Foundation Recommendation Models](https://arxiv.org/abs/2607.26621)

**论文、机构与场景**

- **机构：未披露**
- 作者：Hao Jiang, Peiru Du, Pengfei Yao, Mengting Li, Siyuan Lou, Kuo Cai, Sheng Yu, Qiang Luo, Jian Liang, Ruiming Tang, Fei Pan, Peng Jiang, Wenwu Ou
- 来源：arXiv 2607.26621v3
- 场景：快手本地服务广告推荐，基于 FRM 的基础推荐模型推理

**核心方法**

- 提出 OneLatent 隐式推理框架，将显式 CoT 推理轨迹压缩为若干可学习 latent token，实现 Latent-Reason-then-Answer 推理，避免生成冗长推理文本。
- 引入 Multi-View Adaptive CoT（MV-ACoT），从多视角生成多样化教师监督，并按实例自适应调整推理复杂度。
- 在预训练 FRM 上采用三阶段 latent-token 对齐范式，将对齐后的 CoT 轨迹逐步内化为可学习 latent token。
- 采用多阶段 curriculum 后训练策略，激活 latent token 推理以适配下游推荐任务，并开发了面向实时 FRM 推理的生产服务系统。

**主要创新或优化点**

- 该工作针对 LLM 基础推荐模型中显式 CoT 推理开销大、模板僵化的问题，用可学习 latent token 内化推理，并报告了 SID 指标、吞吐与线上收入提升，属于生成式召回与推理效率方向的实质进展。

**关键结果**

- 在快手工业规模数据集和公开 Kuaishou LLM-Rec benchmark 上，OneLatent 一致优于显式 CoT 方法与传统基线。
- 相比 FRM 的 Think 与 No-Think 变体，SID@64 分别提升 17.44% 与 9.33%。
- 在线推理吞吐相比显式 CoT 提升超过 17 倍
- 快手本地服务广告线上 A/B 显示相对 OneRec、OneReason 等强基线估算带来 9.6% 收入提升。

**收益归因**

- 主要：通过 latent token 内化显式 CoT，减少推理轨迹生成，在保持推荐效果的同时降低在线推理开销。
- 次要：SID 生成指标提升
- 次要：在线推理吞吐提升
- 次要：广告收入提升

**与你的关联**

- 与检索/推荐系统生成式召回链路相关，latent reasoning 压缩思路可迁移到 SID/item-token 空间的候选生成与推理加速。

**风险或局限**

- 线上 A/B 收入提升为论文自述的估算值，缺少独立审计
- 吞吐 17 倍亦为作者报告结果，需复现验证。
- 机构信息未在候选元数据中披露，且未提供 PDF 正文核验，作者单位与部署细节无法确认。
- 摘要级证据为主，MV-ACoT 教师信号质量、latent token 可解释性与跨场景泛化性未在摘要中量化说明。

### P0｜[HELIX: Purified and Unified - Rethinking Feature Interaction and Sequence Modeling for Large-Scale Recommendation](https://arxiv.org/abs/2609.37183)

**论文、机构与场景**

- **机构：TikTok（Data - Global E-Commerce Recommendation Video Team）**
- 作者：Yuntao Zheng、Miao Zhang、Yadong Ding 等
- 来源：arXiv:2609.37183v1
- 场景：TikTok 电商视频推荐精排，联合预测 CTR/CVR/GMV 等多目标并输出最终排序分

**核心方法**

- HELIX 将非序列特征、用户侧 U-only 行为序列与候选相关 U×C 序列分别 token 化为三路流
- SeqFormer Encoder 先将 U-only 历史编码为候选无关的可复用 K/V cache。
- MixFormer 交替执行对 U×C 序列的 cross-attention 与 Mixup-PerToken-FFN（MPTF）做特征交互
- SeqFormer Decoder 再反复从可复用 cache 检索并继续 MPTF。
- 架构强制从可复用序列状态到候选条件 mix-tokens 的单向信息流，使 user-side 序列计算可跨候选/样本摊销，支持 M-FALCON 与 user-level training。

**主要创新或优化点**

- HELIX 提出统一特征交互与序列建模的精排架构，并在 TikTok 电商视频推荐全流量 A/B 中取得约 6% 人均 GMV 提升，对工业精排模型结构设计与序列计算摊销有直接参考价值。

**关键结果**

- 离线对比 RankMixer+Transformer baseline，HELIX-L 的 CTR AUC +0.21%、CVR AUC +0.17%，参数 358M，每样本训练 FLOPs 35.28G。
- HELIX-S/M/L/XL/XXL 联合 scaling 后 CTR/CVR AUC 随算力持续提升，CTR log-log 拟合 R²=0.925，CVR R²=0.994
- XXL 相对 HELIX-S CTR +0.45%、CVR +0.27%。
- TikTok 电商视频推荐全流量随机 A/B 中，HELIX-L 相对 RankMixer+Transformer 生产 baseline 提升人均 GMV +5.9932%、人均点击 +2.0591%、人均付费订单 +6.0964%、GPM +5.4624%。

**收益归因**

- 主要：统一特征交互与序列建模的 backbone 提升排序质量，并通过可复用用户侧 K/V cache 摊销序列计算。
- 次要：M-FALCON 与 user-level training 降低 user-side 序列计算成本
- 次要：Pyramidal query compression 与变长执行减少 padding 和计算
- 次要：联合 scaling 特征交互与序列建模带来可预测的排序收益

**与你的关联**

- 直接关系大规模推荐精排的模型结构、长序列建模、特征交互与训练/服务摊销，可指导精排 backbone 与 serving 优化。

**风险或局限**

- 离线与线上实验均在公司内部工业数据集和 TikTok 电商视频场景进行，未提供公开数据集或第三方复现实验。
- 线上 A/B 只有相对提升，未披露绝对值、置信区间或显著性检验细节
- 基线为 RankMixer+Transformer 生产版本，迁移性待验证。
- 论文为 arXiv 技术报告，未见同行评审
- 结论中跨级联复用生成式召回/粗排/精排共享 cache 未给出实验验证。

### P2｜[ReMem: Rethinking Perception and Memory in Long-Context Recommendation Agents](https://arxiv.org/abs/2609.37311)

**论文、机构与场景**

- **机构：香港理工大学、南洋理工大学（首页明确列出：Haohao Qu 与 Chun Hin Chan、Wenqi Fan 属香港理工大学，Haohao Qu 同时标注南洋理工大学，Yongcheng Jing 与 Dacheng Tao 属南洋理工大学；Shanru Lin 标注香港理工大学，邮箱为公共域名 gmail.com 不能佐证）**
- 作者：Haohao Qu、Yongcheng Jing、Chun Hin Chan、Shanru Lin、Wenqi Fan、Dacheng Tao
- 来源：arXiv:2609.37311v1
- 场景：长上下文推荐 Agent 的搜索、排序与评判三类任务

**核心方法**

- ReMem 不再解析原始 HTML，而是通过截图观察物品页面并用 OCR 工具抽取结构化多模态信息，以实现类人且平台无关的物品感知。
- ReMem 引入按时序演化的动态记忆，采用 chunk-wise 顺序记忆更新策略，在任意长上下文下线性推理复杂度并保持固定大小记忆。
- ReMem 提出 multi-memory GRPO 变体，将最终答案的 advantage 传播到所有对最终回复有贡献的中间对话。
- 论文在三个数据集上对比现有推荐 Agent 基线，覆盖 searching、ranking、judging 三类推荐 Agent 任务。

**主要创新或优化点**

- 该工作把推荐 Agent 的感知从 HTML 解析改为 OCR 多模态感知，并用固定大小动态记忆加 multi-memory GRPO 处理超长用户历史，属于 LLM 增强推荐中对话/Agent 方向的新方法组合。

**关键结果**

- 在三个推荐 Agent 任务上平均提升 5.16%。
- 在三个数据集上的实验结果均报告优于 state-of-the-art 基线。
- 长上下文推理为线性复杂度且上下文长度有界。

**收益归因**

- 主要：通过 OCR 多模态感知与有界动态记忆降低长上下文推荐 Agent 的感知脆弱性与推理成本
- 次要：multi-memory GRPO 的信用分配策略可迁移到多步 Agent 训练

**与你的关联**

- 与 LLM 增强排序和对话推荐相关，但场景是用户侧生成式推荐 Agent，与大规模召回/粗排/精排链路距离较远，偏方向参考。

**风险或局限**

- 摘要只给出平均 5.16% 提升，未披露各任务、各数据集的分项指标与置信度。
- 无在线 A/B 或生产部署证据，全部为离线数据集实验。
- 机构信息未在候选元数据中披露，且未提供 PDF 正文核验。
- 推荐 Agent 的 searching/ranking/judging 任务定义与工业推荐系统精排目标差异较大。


## 训练优化与蒸馏

### P0｜[Soft Curriculum Learning for Optimizing Fresh and Generalized Recommendations](https://arxiv.org/abs/2609.35783)

**论文、机构与场景**

- **机构：Google**
- 作者：Arnab Bhadury、Siyan Zheng、Anlan Yu、Palaksh Rungta、Jiawei Li、Changping Meng、Dapeng Hong、Chuan He、Onkar Dalal
- 来源：arXiv 2609.35783v1（RecSys '26 论文，DOI 10.1145/3773078.3831923）
- 场景：短视频平台工业级连续训练下的检索（SASRec 式序列检索、双塔）与大规模排序模型训练

**核心方法**

- 方法核心为 Soft Curriculum Learning：不做动态数据拒绝，全部样本进入流水线，仅用 loss annealing 与 in-graph 权重系数在 TPU/GPU 核内调制样本难度，避免 CPU-bound 数据过滤导致的加速器饥饿与吞吐下降。
- 难度 d 有两路定义：一路基于历史 engagement 分位数（engagement 越高难度越低），一路基于 SNGP（Spectral-normalized Neural Gaussian Process）预测不确定度归一化。
- 两种课程权重策略与循环节奏：Hard-Example Warmup 用 w=1-α·d·(1-p)，Bidirectional Difficulty Scaling 用 w=1+α·(2p-1)·(2d-1)，训练进度 p 按 sub-day 区间循环重置（p=step mod X / X），而非使用全局一次性课程。

**主要创新或优化点**

- 给出了工业级连续训练场景下用损失加权（而非丢弃样本）实现课程学习、缓解流行度反馈回路的可部署方案，并在检索与排序两条链路给出线上 A/B，说明软课程可在不牺牲训练吞吐的前提下提升冷启动与新鲜内容消费，对训练侧去偏具有直接工程参考价值。

**关键结果**

- 排序模型 7 天线上 A/B：Eng-bi 变体 User Satisfaction +0.54%、User Engagement +1.89%、User Growth +0.11%、User Retention +0.15%
- 冷启动视频年龄 Bucket1/2/3 消费 +5.70%/+2.99%/+2.72%，SNGP-bi 为满意度 +0.42%、Bucket1 +4.71%。
- SASRec 式序列检索两周线上 A/B：检索 engagement +7.7%（冷启动 Bucket1/2/3 为 +0.27%/+0.69%/+0.61%），但离线 MAP@K 全部略低于基线（MAP@1 0.009537→0.009123，MAP@50 0.02364→0.02290）。
- 对比实验：按天数据拒绝的 Global Curriculum（1 天/3 天过滤易样本）离线与线上均为负向（线上满意度 -0.71%/-0.72%）
- 双塔检索离线 MAP@K 全面提升（MAP@1 0.16348→0.17133，MAP@200 0.33316→0.36566）。

**收益归因**

- 主要：通过损失退火与 in-graph 权重实现软课程学习，在不丢弃样本、不牺牲系统吞吐的前提下打破流行度反馈，提升整体满意度与冷启动/新鲜内容消费。
- 次要：训练侧流行度偏差缓解
- 次要：保持 TPU/GPU 训练吞吐
- 次要：批内难度归一化降低 A/A 方差

**与你的关联**

- 命中搜广推核心问题中的排序/召回训练优化与流行度偏差、冷启动内容分发，可借鉴其难度定义、权重公式与批内难度归一化来降低 A/A 方差。

**风险或局限**

- SNGP 不确定度难度仅在排序模型 serving 时计算，检索阶段因对全量物料计算昂贵而只用 engagement 难度，两阶段难度口径不一致。
- SASRec 式检索离线 MAP 全面下降，作者以测试集 head-heavy 解释，但离线与线上指标方向相反，收益归因仍有不确定性。
- 线上 A/B 未披露流量规模、显著性检验细节及 α、frequency 的选参过程
- 课程权重原生抬高 A/A 方差，需批内难度归一化（批均值权重固定为 1）缓解。

### P2｜[Do Evidence-Reading Diagnostics Improve Interface Selection in Small LLM Recommenders?](https://arxiv.org/abs/2609.37472)

**论文、机构与场景**

- **机构：未披露**
- 作者：Han Chen, Yingrui Li
- 来源：arXiv:2609.37472v1
- 场景：小型指令微调 LLM 在四个推荐域上选择推荐接口（history-only prompting、带协同证据 prompting、score fusion）

**核心方法**

- 基线选择器用可观测特征与六个稳定性 prompt（变化措辞与候选顺序）在三个接口间做选择，每个请求排序八个候选
- 增强选择器额外加入六个 evidence-reading prompt 抽取的特征，要求模型比较 support counts
- 评测设置：六个小型指令微调 checkpoint、四个推荐域、按时间顺序评估、3426 个评测用户

**主要创新或优化点**

- 给出负面/零效应证据，说明行为诊断测量不必然带来接口选择收益，并以预先设定的 0.005 提升目标与置信区间作判定，对 LLM 评测方法论有参考价值。

**关键结果**

- 每域每 checkpoint 在验证集选定一次接口后 NDCG@5=0.5524，基线选择器 0.5447，增强选择器 0.5428
- 加入诊断特征使 NDCG@5 变化 -0.0019（95% 区间 [-0.0046, 0.0004]），区间含零且上界低于 0.005 提升目标
- 检索相似用户证据相比按活跃度匹配的随机用户对照提升 0.0999 NDCG@5

**收益归因**

- 主要：未核实
- 次要：诊断评估方法论参考
- 次要：接口选择策略的负面证据

**与你的关联**

- 若团队计划用 LLM 行为诊断或 evidence-reading probe 指导推荐接口/策略选择，该结果提示需先验证增量收益是否超过既有可观测特征。

**风险或局限**

- 仅在测试的选择器与候选集设定下成立，作者明确限定结论范围
- 诊断特征增益的置信区间上界低于分析计划的 0.005 目标，属未达预设阈值的负结果
- 证据仅来自论文摘要，未核验 PDF 正文与机构信息

## 今日最值得立项的实验

### 软课程损失加权对照动态数据拒绝的连续训练消融

- 假设：在连续训练排序模型中，用loss annealing与in-graph权重按难度调制样本（全部样本保留），可在不损失训练吞吐的前提下提升冷启动视频消费与满意度，且效果优于按天过滤易样本的Global Curriculum。
- Control：现网连续训练排序模型，按天动态拒绝易样本的Global Course Curriculum（保留全部其余训练配置）。
- Treatment：同一模型改为Soft Curriculum，难度按历史engagement分位数或SNGP不确定度定义，w=1-α·d·(1-p)或w=1+α·(2p-1)·(2d-1)，训练进度p按sub-day区间循环重置，并做批内难度归一化（批均值权重固定为1）。
- 保持变量：同一训练样本与时间窗、同一特征与模型结构、同一TPU/GPU硬件与吞吐口径、同一评测切分与线上A/B流量配比、同一α与frequency选参预算。
- 离线指标：离线AUC/GAUC与冷启动Bucket1/2/3消费相对对照变化；连续训练多天吞吐（步/秒）与加速器利用率，确认无CPU-bound数据过滤饥饿；A/A方差对比：同数据重复实验权重扰动下的指标标准差
- 线上 Guardrail：线上满意度、User Engagement、User Growth、User Retention四项须至少不劣于现状，任一显著下降即回退；冷启动Bucket1消费提升需在7天窗口内同向且不伴随长尾/头部结构失衡；A/A方差上升超过设定阈值时须先完成批内难度归一化再评估

### SID全码本软分配量化替换Top-1硬分配的离线对照

- 假设：在RQ-VAE式SID学习中，用LRQ全码字softmax软分配+STE前向硬索引、GAQ频率EMA更新率与QSCM双向量化语义一致性损失，可提升码本利用率与长尾物品召回，并加快训练收敛，且推理时间不增加。
- Control：现有Top-1硬分配SID量化方案（含启发式初始化或后处理），同码本层级K=3、每层256码字、同T5自回归推荐主干。
- Treatment：替换为FineSID的GLQ+QSCM总目标L_rank+L_GLQ+L_QSCM训练，保持SID分配结果用于同一自回归生成式推荐预测下一物品。
- 保持变量：同一公开或内部物品内容语义嵌入、同一数据集与时间顺序切分、同backbone与训练步数预算、同一全排序评测协议与beam设置。
- 离线指标：Recall@10与NDCG@10相对对照变化，须分全量与长尾物品切片报告；码本利用率与balance rate，以及死码字数量；训练收敛时间（小时/epoch）与推理时延、SID碰撞率
- 线上 Guardrail：码本利用率提升不得以热门物品召回下降为代价，全量Recall@10不得低于对照；新增软分配与一致性损失带来的显存与单步训练耗时须在既定预算内，否则需调整码本规模；离线结论不得直接外推线上，必须先在小流量A/B验证候选覆盖与延迟

### 可复用user-side K/V cache与跨候选摊销的序列计算对照

- 假设：在精排精排backbone中，把U-only行为序列先编码为候选无关的可复用K/V cache，再由MixFormer对U×C序列做cross-attention与MPTF特征交互，可在同等参数与FLOPs口径下提升多目标AUC，并支持user-level training降低序列重复计算。
- Control：现有RankMixer+Transformer式精排baseline，逐候选重新计算user-side序列编码。
- Treatment：改为HELIX式三路流：SeqFormer Encoder先产出U-only可复用K/V cache，MixFormer在U×C序列上交替cross-attention与MPTF，SeqFormer Decoder反复从cache检索，保持单向信息流。
- 保持变量：同一训练样本与特征集合、同一候选集与标签口径、同一参数规模与每样本训练FLOPs预算、同一硬件与serving延迟口径。
- 离线指标：CTR AUC与CVR AUC相对baseline变化，以及多目标GMV相关离线一致性；每样本训练FLOPs、序列编码重复计算次数与user-level training下的吞吐；scaling拟合：不同模型规模下AUC随算力的log-log斜率与R²
- 线上 Guardrail：线上人均GMV、人均点击、人均订单、GPM四项须同向且不低于现状，任一显著下降即回退；K/V cache失效/过期策略须定义，缓存命中率过低时不得以摊销收益宣称结论；跨级联共享cache未经验证，不得在同一实验中直接下探到召回/粗排


## 一句话总判断

本期主线是精排backbone的序列计算摊销与训练侧去偏：HELIX用可复用U-only K/V cache统一特征交互与序列建模并在TikTok电商视频精排全流量A/B报告约6%人均GMV提升，Soft Curriculum Learning用不丢样本的损失加权在TPU/GPU核内实现课程学习并给出检索/排序双线上A/B，两者共同点是把优化从数据/样本过滤转向计算图内调制。生成式召回侧，FineSID针对Top-1硬分配的码本塌缩给出全码本软分配方案，GRP与OneLatent分别从统一检索-排序和latent推理压缩两个方向推进工业级生成式部署，但后两者PDF未核验或线上数字为估算值。工程判断：HELIX与Soft Curriculum有PDF核验且线上A/B可对照，是最低成本验证路径，但均为公司自报、缺置信区间；生成式方向应优先在离线复现FineSID的码本利用率与Recall@10，摘要级论文的收益数字不可作为工业结论。
