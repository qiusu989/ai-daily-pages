### P0｜[OneTrans-V2: Unifying Retrieval, Pre-rank, and Fine-rank with One Transformer in Industrial Recommender](https://arxiv.org/abs/2609.28589)

**论文、机构与场景**

- **机构：字节跳动 ByteDance（Global E-Commerce）**
- 作者：Hannan Cao、Jun Guo、Haolei Pei 等 21 人，首页署名为 ByteDance Global E-Commerce Recommendation Foundation Team
- 来源：arXiv:2609.28589v1（cs.IR）
- 场景：大规模工业电商推荐系统召回-粗排-精排三级级联

**核心方法**

- 把召回、粗排、精排建模为同一个因果 Transformer 的三个任务联合训练，候选无关的用户行为序列只编码一次为共享用户上下文，各阶段用阶段可见性掩码追加自有 token 并使用 token 专属参数（mixed parameterization）。
- DCGR 在生成物品前先预测决策前缀（购买档位 z_oc、花费档位 z_aov、发现度 z_disc、供给类型 z_ad），再以其为条件自回归生成三级 SID
- 用在线可调的业务 offset β 调整决策分布，使一个生成模型覆盖多目标召回通道。
- 用稀疏 MoE（细粒度路由专家+共享专家、sigmoid 路由）扩容并以 μP/Depth-μP 稳定训练
- SNT 按用户终身行为序列组织训练样本、一次编码被多次曝光复用
- 精排对粗排做同一模型内知识蒸馏（教师 logit 截断）。

**主要创新或优化点**

- 首个把召回-粗排-精排整条级联统一进单个 Transformer 并在大规模工业系统给出线上 A/B 与部署吞吐结果的工作，说明级联级统一可同时改善质量与效率，对推荐/广告链路架构演进有直接参考价值。

**关键结果**

- 线上 A/B（大型工业推荐系统，用户级 50% 分流）：OneTrans-V2 L 单模型替换 OneTrans-GR/OneTrans-Lite/OneTrans 三级级联后，人均 GMV +9.74%，用户活跃天数 +0.25%。
- 同硬件预算下三级端到端 QPS 为被替换级联的 3.2×
- SNT 带来 4.4× 训练加速（论文自报）。
- 离线：OneTrans-V2 L 检索 HR@1 0.0923 相对 OneTrans-GR 0.0545 提升 69.36%，粗排 CTR UAUC +4.65%、精排 CVR UAUC +3.42%，代价为 662 GFLOPs/请求（级联 275）。

**收益归因**

- 主要：论文归因于级联级统一：一次编码共享用户上下文、三阶段联合训练与精排到粗排的模型内蒸馏；作者报告线上 A/B 人均 GMV +9.74%（未独立复现）。
- 次要：吞吐与算力效率：同硬件端到端 QPS 3.2×、训练提速 4.4×
- 次要：跨阶段一致性：inversion rate 降低 6.7%、top-10 coverage +31.4%、top-50 coverage +13.5%
- 次要：生成式召回：单一 DCGR 覆盖主通道、发现与广告三类目标通道

**与你的关联**

- 做推荐/广告排序链路（召回/粗排/精排）的架构统一、用户长序列跨阶段共享编码、生成式多目标召回、跨阶段蒸馏或训练/推理效率优化时，本文的共享上下文+阶段掩码、模型内蒸馏、SNT、μP+MoE 与解码/内核优化方案可直接借鉴。

**风险或局限**

- 结果全部来自单一工业系统（字节电商）的生产日志与在线流量，作者称离线绝对值与 OneTrans 等不可比，未提供公开数据或代码复现路径。
- 主要离线增益来自更大算力的 OneTrans-V2 L（662 vs 级联 275 GFLOPs，约 2.4×），S 版本收益明显更小，收益与算力投入未完全解耦。
- DCGR 的三目标 A/B 是通道间比较而非系统整体增益归因，论文自述其只衡量目标覆盖
- 决策条件下的 classifier-free guidance（权重 w）尚未部署，属未来工作。


### P0｜[UNIQUE: A Unified Retrieval and Ranking System for Large-Scale Feed Recommendation](https://arxiv.org/abs/2609.23718)

**论文、机构与场景**

- **机构：北京航空航天大学、百度、香港城市大学（据首页 affiliation 与邮箱后缀）**
- 作者：Zhuang Liu, Yongkang Fu, Zuodong Yang, Guangxing Chen, Zonggang Wu, Yuqi Lu, Shouke Qin, Shantao Li, Maolin Wang
- 来源：arXiv 2609.23718v1（同时为 RecSys '26 论文，DOI 10.1145/3773078.3831936）
- 场景：Mobile Baidu 首页信息流、发现页与短视频推荐的大规模召回-排序链路

**核心方法**

- 方法：以单层扁平码本替代 RQ-VAE 式层次量化，码本由反馈感知的 DSSM 双塔学习（多任务用户塔 + 共享物品塔，正样本与批内随机重配负样本对比），使码向量吸收点击、时长、完播等行为后验信号。
- 结构：早融合编码器把用户多粒度行为前缀（1 个画像 token + 100 短期 + 200 中期 + 200 兴趣）与候选物品 token、候选语义码 token 放入同一 Transformer，用 target-attention split 限制 target 间交互，单次前向同时产出码 logits 与多目标分。
- 平衡量化与推理：按批内使用频率相对均值 r_j 调整分配距离（d_j=||z̄-e_j||²·r_j^τ）抑制头部码过载
- 线上码本 16,384 码，检索生成 N=100 个码、每码取 M=30 个物品，约 400 张 NVIDIA L20 + TensorRT FP16。

**主要创新或优化点**

- 给出一条已被生产验证的路线：用单层扁平量化 + 早融合共享编码器统一生成式语义码召回与 target-aware 排序，并给出可横向对照的线上 A/B（观看时长 +0.96%、分发量 +1.08%）、P99 89 ms / MFU 44.23% 与码本资源均衡（方差 1510.85→389.57）指标，可作为‘替代层次量化’与跨阶段联合建模的技术判断依据。

**关键结果**

- 线上 A/B（一周全量、作者报告 p<0.05）：总观看时长 +0.96%，总分发量 +1.08%，用户留存 +0.70%
- 分群中新用户观看时长 +1.44%、高活跃用户 +1.11%。
- 离线 KuaiRand-Pure（27,285 用户 / 7,583 物品）：HR@10 0.0575、HR@50 0.1510、NDCG@10 0.0310、NDCG@50 0.0473、CTR-AUC 0.7252，优于最强基线 UniGRF-HSTU（HR@10 +12.52%、AUC +0.0084）。
- 生产系统指标：P99 89 ms、P80 35 ms、在线推理 MFU 44.23%、峰值约 10,000 QPS
- 单层码本把头部码资源占比方差由 1510.85 降至 389.57。

**收益归因**

- 主要：按作者报告，收益主要来自统一早融合共享表征 + 单层扁平量化：缓解层次量化误差累积与召回-排序信息损失，线上总观看时长 +0.96%、总分发量 +1.08%（未独立核实）。
- 次要：长尾与冷启覆盖：作者报告类目覆盖率 +23.3%、Shannon 熵 +13.0%、长尾候选占比 +25.7%，长尾曝光份额 1.04%
- 次要：服务效率：一套早融合编码同时产出码 logits 与排序分，P99 89 ms、在线 MFU 44.23%、约 $0.0013/千次请求

**与你的关联**

- 直接命中搜广推召回-排序核心：生成式语义码召回、层次量化误差累积与长尾/冷启表征、召回-排序阶段信息损失、线上延迟与 MFU 成本约束，方法与指标可迁移到自有信息流/短视频召回链路。

**风险或局限**

- 线上增益绝对值偏小（观看时长 +0.96%、分发量 +1.08%），且为 Mobile Baidu 单一平台、作者自跑内部 A/B，无第三方复现或跨平台验证。
- 公开离线验证仅 KuaiRand-Pure（7,583 物品），只报 CTR-AUC 单一排序指标，未给 relevance/时长/完播等多目标离线结果，论文自述该基准仅为 sanity check。
- 部署时间表述不一致（引言写 Since February 2026，实验节写 Since January 2026），且平衡强度 τ、量化正则等关键超参未给出具体取值。

### P2｜[From Interests to Semantic IDs: Retrieval-Grounded Credit Assignment for Generative Recommendation](https://arxiv.org/abs/2609.29983)

**论文、机构与场景**

- **机构：Emory University、Microsoft、Cornell University（首页明确列出；邮箱域名 @emory.edu、@microsoft.com、@cornell.edu 佐证）**
- 作者：Mengdan Zhu, Yufan Zhao, Yao Zhao, Sophie Di, Tao Di, Yulan Yan, Sridhar Iyer, Liang Zhao
- 来源：arXiv:2609.29983v1
- 场景：Amazon Reviews 三数据集上的 SID 生成式推荐

**核心方法**

- 将每条 rollout 的推理 trace 结构化为历史摘要、兴趣假设集合与最终 SID，用冻结检索器把每个兴趣假设当作目录查询独立执行验证。
- 奖励改为检索 grounded：任一条查询在 top-K 内检索到目标即给予 rollout 奖励，并用 per-query hit 指标把信用定位到具体兴趣假设 span。
- 信用按 span 级分配：只有单独命中的兴趣假设获得正检索优势，检索通道不更新最终 SID span，因此共享同一 SID 奖励的 rollout 可获不同更新。

**主要创新或优化点**

- 它把生成式推荐的稀疏精确匹配奖励替换为可独立核验的检索命中奖励，缓解组内零优势与同奖励同优势两个信用分配失败模式。

**关键结果**

- 在三个 Amazon Reviews 数据集上取得一致的 SID 推荐提升。
- 在 Video Games 数据集上的 oracle 分析显示，在生成的兴趣中选出目标相关查询可同时提升 recall 与 ranking。

**收益归因**

- 主要：未核实
- 次要：未核实

**与你的关联**

- 对使用 GRPO 类 RL 训练 SID 生成式召回的团队，提供了不依赖在线 A/B、仅离线可验证的兴趣级信用分配方案。

**风险或局限**

- 机构信息在输入中未披露，无法追溯实验室背景。
- 摘要级证据，未提供具体离线指标数值、基线对比与消融细节。
- 仅三类 Amazon 数据集，无工业线上 A/B 或生产部署证据。


### P2｜[Geometry-Aware Hyperbolic Residual Quantization](https://arxiv.org/abs/2609.26342)

**论文、机构与场景**

- **机构：Universiteit van Amsterdam, Amsterdam, Netherlands**
- 作者：Alessio Colombo, Melika Ayoughi
- 来源：arXiv 2609.26342v1
- 场景：层级化离散潜空间中的残差量化，含推荐任务评测

**核心方法**

- 方法针对欧氏残差向量量化（RVQ）在双曲空间的朴素扩展问题，提出几何感知的双曲残差量化。
- 前向传播提出 Hyperbolic Residual Aggregation，在 Poincare 球上恢复残差量化的 telescoping 行为。

- 次要：超球面几何建模

- 次要：TikTok 线上部署经验

- 把 LLM 重排的收益多数归因于 oracle 候选注入而非模型能力，说明低召回区间下提升检索比升级重排器更关键，对推荐评测协议设计有直接影响。

**关键结果**

- 在三个域八个数据集上，真实检索在 K=100 时仅覆盖 2–19% 的相关物品，决定任意闭候选重排器的 top-k NDCG 上界
- 在真实检索下，提示工程、168 倍参数规模扩展、序列模型、监督神经重排、LoRA 微调、混合检索、score-aware prompting、LLM+CF 融合均未在主 Amazon 数据集上显著优于协同过滤基线
- 文本感知检索在一个数据集上提升召回，但端到端 NDCG 未提升
- 提供上游 CF 分数主要使 LLM 复现 CF 顺序

**收益归因**

- 主要：评测协议与召回上界约束，可校正 LLM 重排收益归因
- 次要：检索侧投入优先级判断
- 次要：离线评估指标校准

**与你的关联**

- 可直接用于校正当前 LLM 重排/评测流程中的候选注入式评估偏差，并指导在低召回区间优先投入检索侧优化。

**风险或局限**

- 结果为离线离线复现与留一评估，未提供线上 A/B 或生产系统验证
- 仅在 Amazon 公开数据集上测得，召回区间与结论未必外推到高召回、富特征或在线反馈的生产系统
- 仅摘要级证据，未核验 PDF 正文与机构信息


### P2｜[Tie Handling Is Part of the Evaluation Protocol: An Order-Invariance Audit for Tie-Heavy Recommender Scores](https://arxiv.org/abs/2609.26977)

**论文、机构与场景**

- **机构：四位作者均标注 Independent Researcher，邮箱为 gmail.com 公共域名，无法推断所属机构**
- 作者：Chengkun Guo、Han Chen、Yilin Zhu、Yingrui Li
- 来源：arXiv:2609.26977v1（FRAME'26 Workshop @ RecSys 2026，已接收版本）
- 场景：离线采样 top-k 推荐评测中精确分数平局对 NDCG/Hit Rate 的影响审计

**核心方法**

- 方法：保持每行候选物品、标签与分数不变，仅更换平局处理规则
- 候选行按“相关物品在前 + 30 个采样负例”构造，稳定排序沿用输入顺序，使相关物品赢下所有平局。
- 形式化 row-order invariance：在不改变物品身份、标签与分数的前提下置换输入候选会改变最终排序，则该评测器不满足该性质
- 确定性 hash 平局（种子 + user ID + item ID，item ID 兜底）满足该性质。
- 推导相关物品在平局块内均匀随机排列时的 E[Hit@k] 与 E[NDCG@k] 解析公式，并给出六项报告清单：候选集、排序前候选顺序、平局比例、平局规则、置换检验、敏感性分析。

**主要创新或优化点**

- 证明离线采样式 top-k 评测中平局规则是未声明的排序特征：同一候选与分数下 NDCG@10 可相差约 0.55–0.68，会直接扭曲模型对比结论与可复现性。

**关键结果**

- Amazon Beauty & Personal Care 30,000 行：评分加权属性重叠分 NDCG@10 由输入顺序平局的 0.8474 降到 hash 平局的 0.1702，Hit@10 由 0.9997 降到 0.3526
- 99.94% 的行存在跨越 top-10 边界的平局。
- MovieLens 25M + Tag Genome：标签-属性重叠分 NDCG@10 由 0.8380 降到 0.2332，Hit@10 由 0.9390 降到 0.4358
- item popularity 几乎不变（0.5905→0.5905）。
- 均匀随机平局下的解析期望 0.1693 与 100 个独立 hash 种子均值 0.1694±0.0012 接近
- 残差化 Amazon 分数仅 0.39% 行存在精确平局，NDCG@10 变化 0.0004。

**收益归因**

- 主要：离线评测协议的可复现性与指标有效性；线上收益未核实
- 次要：降低实验对比中的假阳性提升
- 次要：提供可落地的评测报告清单与置换检验方法

**与你的关联**

- 对搜索/推荐/广告团队：需在离线评测协议中显式规定并报告平局处理（确定性 hash 或平局期望），并做置换检验，避免评测器实现差异导致的错误选型结论。

**风险或局限**

- 仅覆盖两个公开数据集、单相关物品、30 个采样负例的离散属性分数，未估计该问题在真实 benchmark 或生产系统中的发生频率与量级。
- MovieLens 只保留聚合结果，行级候选与分数数组缺失，无法做行级与置换分析
- 全目录评测未做实证。
- Amazon 属性为词法元数据代理，分数族作为组件而非完整生产推荐模型评估，结论不能直接外推到线上系统。

### P0｜[IDProxy: CTR Prediction with Multimodal LLMs for Cold-Start Recommendation at Xiaohongshu](https://arxiv.org/abs/2603.01590)

**论文、机构与场景**

- **机构：Xiaohongshu Inc.、上海交通大学、复旦大学（依据首页 affiliation 与邮箱后缀）**
- 作者：Yubin Zhang、Haiming Xu 等
- 来源：arXiv:2603.01590v2 / RecSys '26 industry paper
- 场景：小红书 Explore Feed 内容推荐与展示广告的 CTR 冷启动预测

**核心方法**

- Stage 1 用 InternVL MLLM 编码笔记文本与图像，取末层 token hidden states 经 attention pooling 和 MLP 投影到 ID embedding 空间，并用带 in-batch negatives 的对比损失对齐归一化后的 ID embedding。
- Stage 2 用 k-means 将 MLLM 多层 hidden states 聚为三个层子组，经轻量多粒度 adaptor 和 residual gating 融合 coarse/fine proxy，并将 proxy 注入 CTR ranker 的 item ID 槽位以复用特征交叉与 target attention。
- Stage 2 冻结 MLLM，用 CTR cross-entropy 端到端训练 adaptor 与 ranker
- 部署时离线训练一次 adaptor，与 MLLM 打包为 IDProxy 生成服务，新 item 实时生成 proxy 写入在线存储供排序管线取用。

**主要创新或优化点**

- 在大规模内容平台冷启动场景中，用 MLLM 图文代理嵌入替代或增强 ID embedding，并通过线上 A/B 验证 CTR 与业务收益，对推荐和广告排序有直接工业参考价值。

**关键结果**

- 离线相对小红书生产 Base 的 ΔAUC：Stage1 +0.05%，Stage1+2 无结构复用 +0.08%，完整 Stage1+2 +0.14%
- 作者称 0.0010 的 AUC 绝对提升通常视为实际显著。
- 线上 5 天 ΔAUC：全局笔记 +0.12% 至 +0.15%，新笔记 +0.23% 至 +0.32%，新笔记提升约为全局的 2 倍。
- 线上 A/B（1% 显著）：Content Feed 的 Time Spent +0.22%、Reads +0.39%、Engagements +0.5%
- Display Ads 的 Impression +1.28%、ADVV +1.93%、COST +1.73%、CTR +0.23%。

**收益归因**

- 主要：MLLM 图文代理嵌入对齐 ID 空间，缓解新 item 冷启动，提升 CTR 排序与线上业务指标。
- 次要：冷启动新笔记 AUC 提升
- 次要：内容推荐与展示广告业务指标提升
- 次要：多粒度 MLLM hidden states 复用

**与你的关联**

- 直接关联搜广推 CTR 精排、物品冷启动和多模态 LLM 表征；coarse-to-fine 对齐与将 proxy 注入 ID 槽位的做法可迁移到推荐/广告排序系统。

**风险或局限**

- 对齐目标仅用 in-batch negatives 的对比损失，未系统比较最优传输或回归等其他对齐目标。
- MLLM 对齐到静态 ID embedding，未与 CTR 模型做端到端联合优化
- 作者计划未来用 LoRA。
- 生产实现细节因保密省略，线上 A/B 只报告相对提升，未披露绝对 AUC、流量规模和置信区间细节。

## 本周方法趋势

- 级联级统一成为独立方向：OneTrans-V2 单模型统一召回-粗排-精排，UNIQUE 用早融合共享编码同时产码与排序分，链路内信息损失被显式当作优化对象而非工程约束。

## 本周最值得做的实验

### 可缓存目标无关用户表征替代逐候选长序列检索（对照 MuSeR 分层压缩与 LIGE-GR 复用 CF 表征）

- 假设：用与候选无关、可离线缓存的分段压缩用户表征替代逐候选 target-attention 长序列检索，可在精度基本持平下降低训练显存与推理延迟。
- Control：现有精排链路：逐候选在线计算用户长历史序列（SIM/TWIN 式）。
- Treatment：接入候选无关的压缩用户表征（近期高分辨率、中远期下采样）并按用户缓存复用，排序头仅处理候选交互。
- 保持变量：候选池与特征体系、训练数据与步数、序列长度上限与采样口径保持一致。
- 离线指标：GAUC/AUC；训练显存峰值与单步耗时；推理 p99 延迟；与 full-attention 的精度差
- 线上 Guardrail：线上 p99 不超过 SLA；缓存写入与存储成本在预算内；核心排序 A/B 不下降；冷启与低活用户 GAUC 不劣化

### SID 粗层监督与扁平码本对照（对照 Guided SID 与 UNIQUE）

- 假设：用业务属性标签监督 SID 粗层或改用单层扁平码本，可在前缀召回指标上优于现有层次 RQ-VAE 构造。
- Control：现有语义 SID（三级 RQ-VAE）作为唯一标识通道，生成式召回器冻结。
- Treatment：分别实验：a) 粗层属性标签引导；b) 单层扁平码本。二者均用同一生成检索骨干解码。
- 保持变量：相同骨干、相同训练监督与数据、相同后续排序模型与候选池规模。
- 离线指标：Recall@1/10/20 前缀覆盖率；MRR@10；SID 合法率与 collision@1；码本使用均衡度
- 线上 Guardrail：重排与解码延迟增量在预算内；标识版本切换期线上指标稳定；长尾与冷启物品召回不下降

### listwise 解码在现有精排候选集上的增量验证（对照 LIGE-GR 的 b=1/b=6 配置）

- 假设：在固定百量级候选池上引入上下文感知序列解码与到达概率加权价值，可在 itemwise 打分基础上带来额外消费与互动增益。
- Control：现有 itemwise 精排打分与贪心排序（对应 LIGE-GR b=1 基础配置的等价物）。
- Treatment：在候选内加入因果 Transformer 前缀建模与 beam 解码，beam width 分别取 1 与更大值对照。
- 保持变量：相同候选池、相同价值模型输入特征、相同流量分配与实验周期。
- 离线指标：离线 NDCG/列表级效用；候选内重复度与主题多样性；每请求端到端延迟与额外算力占比
- 线上 Guardrail：端到端延迟增量不超过预算；新内容/新鲜度指标不回退（LIGE-GR 报告 72 小时内新视频 -0.66%）；播放量等既有指标不出现负向


## 一句话总判断

本期最实质的方法变化是级联级统一与生成式召回的路线分化：OneTrans-V2 把召回-粗排-精排压进单个 Transformer 并给出线上 GMV +9.74%、QPS 3.2×，LIGE-GR 则从 itemwise 平滑升级到 listwise 且保留配置级回退，二者都强调复用共享表征而非加大骨干。生成式召回侧出现明确对立路线——UNIQUE 的单层扁平码本与 Guided SID 的属性标签监督粗层，共同质疑 RQ-VAE 层次量化的误差累积，但线上证据仍以厂商自报为主。评测侧的两篇协议论文（召回天花板、平局处理）提示此前部分重排与排序结论可能被评测实现放大，迁移前应按各自日志与分流口径复验。
