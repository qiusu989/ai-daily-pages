## 生成式召回

### P0｜[ICEGR: An Intent-Coherent End-to-End Generative Retrieval Framework for E-commerce Search](https://arxiv.org/abs/2608.29652)

**论文、机构与场景**

论文《ICEGR: An Intent-Coherent End-to-End Generative Retrieval Framework for E-commerce Search》，WSDM '27 投稿，作者主要来自百度（第一作者 Jiayi Tuo 等），合作单位含北京航空航天大学与中国人民大学；应用场景为百度电商搜索的商品召回。

**它解决的旧问题**

在工业电商搜索中验证端到端生成式召回可落地：跨 SID 构造、监督微调与偏好优化保持 query-intent 一致，并把离线召回增益转化为线上 CTR/订单/GMV 收益，同时给出可参考的推理成本（67×L20、2200 QPS、156 ms）。

**核心方法**

方法含三部分：IA-SID 在量化成 SID 前融合 query-product 对比学习、共点击关系统计图传播与历史查询意图画像；SQE-SFT 用多粒度合成查询统一 query-to-SID 两阶段微调；RCPO 只在语义相关候选间做 margin-adaptive 偏好优化；实验用近三个月百度电商搜索日志（12.8M 查询、14.6M 商品），0.5B 骨干模型、8B 电商适配 embedding、三级 RQ-KMeans 各 1024 码，基线为生产生成式召回模型 ProdGR；线上以 0.5B 模型、20% 流量做两周 A/B，ICEGR 的 top-k 结果直接插入最终展现列表；部署集群 67 张 NVIDIA L20，beam size 50，峰值 2200 QPS、平均延迟 156 ms。

**主要创新或优化点**

在工业电商搜索中验证端到端生成式召回可落地：跨 SID 构造、监督微调与偏好优化保持 query-intent 一致，并把离线召回增益转化为线上 CTR/订单/GMV 收益，同时给出可参考的推理成本（67×L20、2200 QPS、156 ms）。

**关键结果**

离线（20,000 条测试查询）：Recall@20 由 0.4247 升至 0.5169（+21.7%），MRR@20 0.1982→0.2509，NDCG@20 0.2318→0.2935（+26.6%）；消融显示 SQE-SFT 贡献 76.7% 的 Recall@20 累计增益，RCPO 17.7%，IA-SID 5.6%；线上 A/B 相对提升：CTR +3.52%、订单量 +15.96%、GMV +7.53%，另有 Show PV +8.84%、长点击率 +5.27%、商品落地页 PV +8.75%；绝对数值因保密未披露；人工盲评 top-5 相关率 0.87，固定 β 的 DPO 变体仅 0.58；SQE-SFT 对 Low 曝光商品 Recall@20 增益最大（+36.2%），Tail +21.2%，Mid/Hot 依次递减。

**收益归因**

主要来自 query-to-SID 监督覆盖扩展（SQE-SFT 贡献 76.7% 的 Recall@20 累计增益）；次要因素为 意图感知的 SID 构造（共点击关系建模 + 查询意图画像融合）；相关性约束下的业务偏好优化（RCPO）；CTR/订单/GMV 与曝光量同步提升，且满足线上吞吐与延迟约束。

**与你的关联**

对生成式召回与多级级联架构并行合并的路线选择、SID 构造方式，以及在召回阶段用 DPO 类偏好优化注入业务信号均有直接参考价值。

**风险或局限**

只与内部生产基线 ProdGR 对比，因数据与基础设施私有而无法与外部生成式召回系统直接比较；离线以用户点击为 ground truth，存在曝光偏差；线上结果只报相对提升，无绝对指标、置信区间与流量分配细节，A/B 仅覆盖 20% 流量、为期两周；合成查询与真实用户查询分布存在 mismatch（Tail 增益低于 Low）；基于点击/支付/GMV 的偏好信号仍可能放大流行度与商业偏差，本文仅以相关性约束与分桶评测缓解。


### P2｜[LoopMemGR: From Behavior Logs to Evolving Memory for Generative Recommendation](https://arxiv.org/abs/2607.27647)

**论文、机构与场景**

论文身份与机构：arXiv 2607.27647v2，替换版，作者含 Hui Qian、Changfa Wu、Chang Liu、Binbin Cao、Jian Wu、Yuliang Yan、Han Zhu、Bo Zheng、Shiye Wang；机构未披露，据候选摘要场景为生成式推荐，实验使用工业淘宝数据集。

**核心方法**

核心问题：现有生成式推荐采用 history-as-context 范式，每次请求从行为历史重建用户偏好，但丢弃系统侧已有的推荐决策，形成记忆不对称，无法跨请求复用偏好验证信号、负向证据与历史探索信息；方法：提出 LoopMemGR 闭环推荐经验记忆框架，在常规行为日志外维护推荐经验日志记录过去的推荐—反馈轨迹，通过 recency、frequency、global 三个互补视图抽取请求相关经验信号；输出形式：将抽取信号压缩为固定数量的 experience tokens，在有限输入预算下条件化生成式骨干网络，生成 Semantic ID 序列候选。

**主要创新或优化点**

针对生成式推荐中系统侧推荐决策与反馈未被跨请求复用的记忆不对称问题，提出可压入固定 token 预算的经验记忆闭环，为生成式召回引入历史探索与负向证据信号提供了一种实现路径。

**关键结果**

在工业淘宝数据集上的实验表明闭环经验积累与多视图经验抽取有效，但摘要未给出具体指标数值或提升幅度。

**与你的关联**

与生成式召回/Semantic ID 推荐方向相关，其经验记忆与多视图抽取机制可迁移到需要跨请求复用决策反馈的推荐链路，但未涉及具体工业部署或在线收益。

**可信度**

peer_reviewed_paper

**风险或局限**

摘要仅报告工业淘宝数据集上的有效性，未披露具体指标、提升幅度或在线 A/B 结果；无正式接收信息，仅 arXiv 替换版，未经同行评审确认；缺少与既有生成式召回方法在同等实验设置下的量化对比细节。

SafeGEO 是 arXiv 论文（cs.IR/cs.AI），作者来自多个机构，具体所属未在摘要中披露。

与搜广推相关性中等：聚焦生成/排序阶段的安全与鲁棒性，非核心算法创新，评测方法可参考但需验证迁移性。

### P2｜[A Multi-Source Ensemble Approach to Candidate Generation for Alternative Vacation Rental Property Recommendations](https://arxiv.org/abs/2609.05748)

**论文、机构与场景**

Syed Mohammed Arshad Zaidi、Eric Rincon 与 Shayan Hassantabar（Expedia Group, Austin, TX）发布 arXiv 论文 arXiv:2609.05748，场景是度假租赁平台中用户查看参考房源时生成替代房源候选集。

**核心方法**

核心方法是多源召回融合：IBKNN（Jaccard audience overlap+amenity boost）与 GNN 嵌入各自检索，经业务硬规则过滤后按 rank-normalized max 融合，再用 LightGBM 轻排为每个参考房源产出约 top-300 候选并传给下游重排器；实验在 2M+ 活跃度假房源及 90 天用户交互数据上进行，时间切分 2025-03 至 05 训练、2025-06 测试；GNN 在含 LHS/RHS 双属性节点、user、interaction 和 label 的异构图上做非对称链路预测；作者披露数据专有、无代码与模型开源，GNN 训练依赖 Kumo AI 商业平台，全文仅离线评估，无在线 A/B；所有混合收益与下游排序提升均以离线指标报告。

**主要创新或优化点**

在超过 200 万房源的度假租赁平台验证 GNN 与 CF 互补：混合召回显著提升 Recall@300（+14.8%），并对候选池到下游精排的效果传导做归因分析，揭示 recall-conversion gap，可作为多源召回、冷启动与两阶段链路设计的工业参考。

**关键结果**

混合系统相对强基线（IBKNN+Hotel2Vec）Recall@300 从 39.9% 升至 45.8%（相对+14.8%），Recall@10 仅 7.8% 至 7.9%，收益集中在候选池后段；GNN 单独相对 Hotel2Vec 召回相对提升 48–68%（各 K）；检索级单源表现显示 IBKNN 早段领先（R@100 28.5% vs 25.0%），GNN 在 K=500 反超（49.2% vs 48.5%）；混合候选池让同一架构 Final Re-Ranker 的 Booking NDCG@5 测试集 0.365 vs 0.345、验证集 0.369 vs 0.361，但每个 ranker 在自己的池上重训，不能单独归因候选池。

**与你的关联**

方法与 item-to-item/相似物料多路召回、GNN 显式特征介入和冷启动直接相关，轻排负采样与 rank-normalized 融合细节可迁移；但场景是海外 OTA 度假租赁，物理约束与国内短视频/电商差异较大，需自行验证。

**可信度**

technical_report

**风险或局限**

无在线 A/B，全部离线；单月测试窗口且无置信区间，作者提示 Recall@10 等小差异需谨慎；+14.8% 同时包含候选源替换（Hotel2Vec 到 GNN）与融合策略变化（顺序优先改为 rank-normalized max），不能单独归因 GNN；未做 source overlap/oracle-union 及按交互稀疏度、房龄分层的冷启动量化；ground truth 来自已曝光 booking，存在曝光偏差且多样性仅定性。

### P2｜[LLMAR: A Tuning-Free Recommendation Framework for Sparse and Text-Rich Industrial Domains](https://arxiv.org/abs/2604.16379)

**论文、机构与场景**

arXiv:2604.16379v3，作者来自日立研发集团（Hitachi, Ltd. Research and Development Group）与 Hitachi Power Solutions，被 PILA '26（KDD 2026 同期 workshop）接收；应用场景为建筑/维护现场风险预测与专用物料采购等 B2B 稀疏、文本丰富域的推荐。

**核心方法**

方法为三阶段 tuning-free 框架：时间滑窗把用户历史切成 bundle，由 LLM 生成“潜在动机”标注并向量化（Inference-Driven Annotation）；再用 Exploitation、MMR 多样性、社交扩展三路动机检索合成搜索查询（Dual-Retrieval）；最后 Reflection Loop 让 LLM 自检并重写查询，用 RRF 融合多查询检索结果（Algorithm 1: DenseRetrieval(I, Q_search) → C_ranked）；全程不做参数训练：生成用 Qwen3-235B-A22B-Instruct-2507，嵌入用 Cohere Embed Multimodal v4.0，均经 Amazon Bedrock 调用，支持异步批处理与隔夜批量预测；离线评测用时间序 8:1:1 切分与全量排序（不做负采样），基线为 LightGCN、SASRec、SASRecF，数据集为 MovieLens-1M、Amazon Pantry 与自建工业数据集 ISR（1,340 用户 / 2,340 物料 / 密度 1.49%）。

**主要创新或优化点**

在 ID 协同过滤因共现稀疏而失效的文本丰富域，给出“LLM 动机标注 + 查询生成 + 检索前 Reflection 自校正”的免训练召回路线，并把成本压到约 $1/千用户量级，是 LLM 增强召回在 B2B 工业场景的一次完整系统化尝试。

**关键结果**

ISR 工业数据集上相对 SASRecF 提升 +54.8% Recall@10、+54.6% nDCG@10（nDCG@10 0.0688 vs 0.0445），并在所有数据集上取得最高 Coverage 与最低 Pop@10；公开数据集上不及 SASRecF：ML-1M nDCG@10 0.1015 vs 0.1131，Amazon Pantry 0.0545 vs 0.0619；消融（ML-1M）：去掉 Reflection 使 nDCG@10 下降 38.3%，去掉 Exploration 使 Pop@10 上升 61.8%；Qwen3-235B 下成本约 $0.9–1.7/千用户，延迟 2.0s（首轮）/ 3.4s（含 Reflection）。

**与你的关联**

可参考其“检索前查询精炼 + 自校正”思路用于冷启动/稀疏场景的 LLM 语义召回；但与短时视频、直播、电商广告的高密度 ID 主链路距离较远，直接迁移价值有限。

**可信度**

peer_reviewed_paper

**风险或局限**

无线上 A/B 或生产部署；唯一显著优势来自不公开的 ISR 私有数据集，公开数据集上反而弱于 SASRecF，增益难以复现；延迟 2.0–3.4 秒/用户，不适合毫秒级实时 B2C；性能依赖物料文本元数据质量，元数据贫乏或高度同质时失效；历史切分用固定时间窗，未系统验证阈值 τ 与迭代上限 T_max；物料库仅数千级，未证明大规模目录下的可扩展性。

### P2｜[CoRA-NAS: Coarse Ranking and Anchor-Residual Refinement for Neural Architecture Search](https://arxiv.org/abs/2609.11884)

**论文、机构与场景**

arXiv 论文 CoRA-NAS（Coarse Ranking and Anchor-Residual Refinement for Neural Architecture Search），作者 Yifan Yang、Zhaoyan Wang、Zheng Gao、Xiaoyu Li、Jiaojiao Jiang，机构未披露；应用场景为神经架构搜索中的零成本代理与架构精度排序。

**核心方法**

方法为两阶段：CoRA-Rank 用等权 log-rank 共识聚合容量与初始化结构代理，并加 target-free 共识门控；CoRA-Refine 在该先验上采样 anchor，外推其早期验证曲线，再用 ExtraTrees 模型传播学习到的残差修正；精修成本约为完整训练候选集的 1%，且不使用全训练架构-精度标签拟合排序器；跨搜索空间使用单一配置，仅空间特定架构编码不同；在 NAS-Bench-201、NAS-Bench-101、TransNAS-Bench-101 与 NATS-SSS 上 CoRA-Refine 的平均 Spearman 相关分别为 0.946、0.715、0.786、0.894。

**主要创新或优化点**

把零成本代理的跨空间排序稳定性与低保真学习曲线精修结合，为代理评估/架构排序提供可复用的两阶段协议与四空间 Spearman 基线，对代理评测方法论有参考价值。

**关键结果**

最差空间相关 0.715，为对比方法中最高；在 NAS-Bench-201/CIFAR-100 上选中架构达 73.32%，接近报告的 ground-truth 最优 73.37%；在纯 size 空间，精修恢复了静态先验相对参数量基线的不足，同时在噪声范围内与最强容量代理持平；论文称结果给出跨空间排序鲁棒性与低成本架构选择，但未报告线上 A/B、工业部署或生产系统指标。

**与你的关联**

### P2｜[MLLMRec: A Preference Reasoning Paradigm with Graph Refinement for Multimodal Recommendation](https://arxiv.org/abs/2508.15304)

**论文、机构与场景**

MLLMRec 为 arXiv:2508.15304v3（cs.IR，2026-09-11 更新）论文，作者来自国防科技大学系统工程学院（长沙）与电子对抗学院（合肥），通讯作者 Fei Cai、Honghui Chen；场景为 Amazon Baby/Sports/Clothing 商品多模态 top-K 推荐，属离线数据集评测。

## 本周方法趋势

- 跨阶段协同成为精排优化主线：UniRec 把粗排与精排融合模块联合训练，用 stop-gradient 与偏好对齐缓解上游过滤掉下游偏好物料的问题，与上期 TGR 跨阶段共享 SID 属同一方向。

## 本周最值得做的实验

### 上下文级粗排/精排同屏耦合建模实验

- 假设：以请求内同屏候选为 context unit 做双层注意力并加曝光/位置辅助目标，可提升精排 AUC 与线上 RPM；上下文级 TopK 压缩可在 AUC 基本不变下降算力。
- Control：现有精排 DLRM 基线（候选独立打分、无同屏耦合与曝光/位置辅助监督）
- Treatment：在候选打分模型中引入 context unit 组织、intra/inter-context attention 与 Gumbel-TopK 训练/硬 TopK 推理的上下文压缩分支
- 保持变量：相同训练数据与特征体系、相同候选池与分片策略、相同优化器与训练步数
- 离线指标：AUC；GAUC；FLOPs/请求与压缩率；不同候选分片规模（如 64/128/300）下的 AUC
- 线上 Guardrail：线上 P99 延迟不超过 SLA；在线 RPM/CTR 不下降；分片后候选覆盖与业务约束不劣化

### 粗排-精排跨阶段偏好一致性联合训练实验

- 假设：让两阶段融合模块共享 embedding 并联合训练、对粗排输出加 stop-gradient、再用下游 pairwise 偏好做 detached 纵向上游对齐，可降低跨阶段偏好不一致并提升长观看类指标。
- Control：现有粗排 pXTR 与精排 pXTR 独立训练、两阶段融合模块不共享梯度
- Treatment：共享输入 embedding 的联合训练 + 跨阶段 stop-gradient 注入 + 纵向 cross-stage consistency 项 + CPPA 聚合多 pairwise 目标
- 保持变量：相同特征、相同两阶段候选压缩比、相同 backbone 与训练数据
- 离线指标：NDCG@K；ASH 跨阶段一致性；rank_AUC；Kendall tau 与训练吞吐
- 线上 Guardrail：服务延迟不增加；粗排候选分布不异常坍缩；核心消费与互动指标 A/B 不下降

### 可缓存超长序列分支替换两阶段长期信号实验

- 假设：用固定长度可缓存用户 sketch 加短后缀双时间尺度建模替代现有 10K STCA + 终身两阶段模块，可在不增服务成本下提升时长与完播并降负反馈。
- Control：现有 STCA 10K 短序列 + 独立长期两阶段抽取模块
- Treatment：端到端超长历史分支（如 100K）+ 可缓存低秩 sketch + 双时间尺度 STCA 与融合层
- 保持变量：相同候选集与精排位置、相同目标集、相同在线资源预算
- 离线指标：AUC/UAUC 分目标；Finish/Duration 类目标 AUC；Dislike 类目标 AUC；训练与推理 FLOPs
- 线上 Guardrail：端到端 P99 延迟不超预算；缓存命中率与容量受控；Dislike 与举报率不上升


## 一句话总判断

本期方法趋势集中在三条主线：一是级联系统内部的跨阶段协同，UniRec 把粗排与精排融合模块联合训练并用 stop-gradient 控制梯度耦合，论文报告 AppUsageTime +0.616%、TotalWatchTime +0.675% 并称全量部署；二是超长用户历史与统一上下文组织，SequenceO1 用可缓存 sketch 将 100K 序列端到端上线，UniCon 把 CTR 建模从 token 拼接收敛为 context unit 并做上下文级压缩；三是工业精排多目标与意图对齐，PTDG 用个性化任务依赖图缓解深层稀疏目标信号衰减，Dear Algo 与 EAGER 把自然语言意图编译为可执行检索计划或查询建议并上线。工程判断上，本期的可信收益仍主要来自已有链路内的结构性改造与系统优化，而非更换骨干，跨平台复制前需按各自日志与位置口径复验。
