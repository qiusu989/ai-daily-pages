## 跨阶段协同与工业效率

### P0｜[Hybrid GPU-CPU Retrieval for Personalized Search at Ultra-Large Scale](https://arxiv.org/abs/2609.21281)

**论文、机构与场景**

- **机构：Meta Platforms, Inc.**
- 作者：Hao Fu、Jichao Sun、Baiting Zhu 等
- 来源：arXiv:2609.21281v1（KDD '27）
- 场景：多万亿文档级用户生成内容上的多语言个性化搜索 embedding 检索与交互预排序

**核心方法**

- 提出 GPU–CPU 异构协同服务系统：GPU 路径在约十亿文档精选池上融合双塔召回与交互预排序，CPU 路径在约二十倍大的独立库存上做轻量个性化检索，两路可独立运行，候选按文档 ID 去重后送入共享下游排序器。
- GPU 路径把双塔检索器与 DeepFM 式交互模块联合训练，使用跨会话/会话内 InfoNCE、Smooth L1 与 BCE 三目标，并沿用 SilverTorch 使 ANN、推理、预排序留在加速器内，稀疏嵌入表经 PCIe Gen5 从主机内存按需取。
- CPU 路径用共享微调 XLM-V 的统一双塔、双向 InfoNCE 产出 384 维多语言向量且仅用点积交互，配备专用 embedding 索引、分布式质心训练（64k→512k）与 eager TAAT 扫描加 AVX-512 hit scanning。

**主要创新或优化点**

- 提供生产验证的 depth–breadth 异构协同架构与线上 A/B 证据，说明超大规模个性化检索可让不同硬件层分工专精，而非由单一层级同时兼顾建模深度与库存覆盖。

**关键结果**

- 九天全系统 A/B 对比 legacy all-CPU：模型打分 DCG@20 +4.51%（保守 95% CI [+3.99%,+5.04%]），GSRR +2.01%（[+1.71%,+2.32%]），每日区间均高于零。
- 独立路径实验：GPU 路径七天 GSRR +1.04%±0.13%、DCG@20 +0.73%±0.15%
- 关闭 GPU 的 CPU 路径九天 GSRR +1.20%±0.11%、DCG@20 +3.16%±0.15%。
- 专用索引与 eager 执行使检索阶段计算降 89.45%（9.48×）
- 512k 质心配 nprobe=256 的十五天在线实验降 CPU 使用 63.5% 且未检出 GSRR 回退。

**收益归因**

- 主要：生产全系统 A/B 提升模型打分相关性（DCG@20 +4.51%）与实质参与（GSRR +2.01%），并给出把建模深度放 GPU、库存广度放 CPU 的容量成本依据。
- 次要：检索阶段计算降 89.45%（9.48×）
- 次要：512k 质心配置降 CPU 使用 63.5% 且无 GSRR 回退
- 次要：两路候选低重叠（Jaccard 约 0.41–0.75%）带来结构多样性

**与你的关联**

- 直接落在搜广推候选生成与预排序的系统架构与工业效率，含可迁移的 GPU/CPU 分工、专用索引、延迟与容量成本权衡。

**风险或局限**

- 全系统 A/B 同时改变硬件、ANN 精度、模型深度、库存与过滤等多组件，线上提升无法归因到单一因素，需对应隔离实验。
- 评估范围限于检索/预排序分支，排除 query understanding、候选聚合、下游排序与客户端渲染
- GPU 与 CPU 路径候选预算不同，延迟不可跨路径直接比较。
- 容量成本比较是独立匹配计划（d=256 SQ8、三区域），不含共享排序、网络与已部署十亿级 GPU 路径，也不证明延迟或检索质量等价。

## 多任务与目标建模

### P2｜[IntHQ: Task-Interactive Hierarchical Query on Dual-Stream Representations for Generative Recommendation](https://arxiv.org/abs/2608.09634)

**论文、机构与场景**

- **机构：DreamX, Alibaba Group**
- 作者：Junjie Sun, Longfei Xu, Huimin Yan, Wei Luo, Kaikui Liu, Xiangxiang Chu
- 来源：arXiv 2608.09634v2
- 场景：Amap 出行推荐多任务排序（UVCTR）

**核心方法**

- 指出现有多任务推荐的三重塌缩：Source collapse（任务信号注入过晚、在共享隐空间被稀释）、Relational collapse（任务依赖被主干隐式吸收或被预设漏斗静态固定）、Hierarchical collapse（不同任务依赖不同尺度特征且随训练阶段漂移）
- 提出 IntHQ，含三个组件：Dual-Stream Decoupling（DSD，尽早注入任务身份，分离共享上下文流与任务专属流）、Task-Interactive Modeling（TIM，用显式跨任务交互替代预设漏斗，任务以前驱已实现结果为条件且强度可学习、输入自适应）、Hierarchical Querying（HQ，让任务在不同训练阶段跨层聚合多尺度信息）
- 离线评估在四种代表性任务头配置下持续优于竞争编码器主干
- 线上部署于 Amap 出行推荐，服务数亿用户，UVCTR 相对提升 1.60%

**主要创新或优化点**

- 把多任务建模从共享单表征+预设漏斗迁移到双流解耦、显式跨任务交互与分层查询，并给出大规模线上 UVCTR 增益，属于精排多任务方向的机制性更新。

**关键结果**

- 离线评测：IntHQ 在四种代表性任务头配置下一致优于对比编码器主干（具体数值未在摘要披露）
- 线上部署：Amap 出行推荐服务数亿用户，UVCTR 相对提升 1.60%

**收益归因**

- 主要：多任务联合建模中的任务信号稀释与任务依赖静态化问题，通过双流解耦与显式跨任务交互缓解
- 次要：分层多尺度特征聚合
- 次要：线上多任务排序指标提升

**与你的关联**

- 直接对应精排多任务/多目标联合建模环节，双流解耦与输入自适应任务交互可迁移到短视频、电商等推荐链路的排序模型。

**风险或局限**

- 摘要仅给出 1.60% 相对 UVCTR 单一线上指标，缺少绝对值、置信区间与实验周期等细节
- 离线四种任务头配置的具体数值与消融未在摘要披露，需正文核验
- 生产结论来自厂商自述，未见第三方复现或独立基准

- **机构：University of Electronic Science and Technology of China（Chengdu, China）、Taobao & Tmall Group, Alibaba（Beijing, China）、Hainan University（Haikou, China）**

- 在大规模 auto-bidding benchmark 上报告 ADAPT 持续取得更优性能（具体数值未在摘要中给出）
- 消融实验报告各模块均有效（具体数值未在摘要中给出）

**收益归因**

- 主要：未核实
- 次要：个性化出价

**与你的关联**

- 属于广告出价与竞价机制方向，与搜广推广告链路中的出价策略建模相关，可作为画像条件化出价的参考。

### P2｜[OneBid: A Unified Auto-Bidding Foundation Model for Diverse oCPX Advertising Scenarios](https://arxiv.org/abs/2609.21550)

**论文、机构与场景**

- **机构：Kuaishou Technology（首页 affiliation 及作者邮箱均为 @kuaishou.com）**
- 作者：Yewen Li、Peng Jiang、Yitian Li、Pengfei Lv、Xialong Liu、Peng Jiang、Qingpeng Cai
- 来源：arXiv:2609.21550v1（ACM Preprint 版式）
- 场景：快手 oCPX 广告自动出价，覆盖 Form Submit、Purchase、ROAS、Activation、Leads Submit 等 7 类转化场景

**核心方法**

- 预训练在 Decision Transformer 上把单一 Return-to-Go 拆为 RTG（转化价值）与 CTG（成本比）两路原子控制信号，并在动作头外增加 Q/V 辅助价值预测，用于表征正则化与后训练 critic 预热。
- 提出序列级 MoE（S-MoE）：按 oCPX 场景身份对整条出价序列硬路由，每块 4 个共享专家 + 28 个路由专家、每序列激活 4 个，保持单请求激活计算量固定以适配严格延迟。
- 后训练提出 CROP：对每个状态由旧策略采样 5 个候选出价动作，用 critic 做组内相对优势打分，并以 KL 约束靠近预训练参考策略，避免 GRPO 式线上探索。

**主要创新或优化点**

- 把“一场景一模型”的 oCPX 出价管线统一为可复用出价基座，并给出序列级 MoE 低延迟扩容与纯离线策略改进（CROP）方案；已在快手全量部署并报告跨场景线上 A/B 增益，是广告出价由单场景 RL 走向基座模型的重要工业证据。

**关键结果**

- 自 2026 年 5 月起在快手 oCPX 广告全量部署，整体 ADVV +2.2%，ROAS 场景最高 +13.1%（CI 5.0%–28%）。
- Form Submit 场景线上 A/B（33% 流量、≥5 天、含 AA 校验）：微调 OneBid 相对生产 DT 基线 ADVV +1.9%（CI 1.0%–2.8%）、Valid Ratio +2.8pp
- 仅预训练版本 ADVV +1.0%（CI 0.1%–1.8%）、VR +1.7pp。
- 服务延迟：60M 参数 OneBid 端到端 52ms vs 10M DT 40ms（1K QPS、150 CPU）
- S-MoE 相比 256 专家 token-level MoE 延迟 1.71ms vs 22.18ms（>13x 更快），峰值显存低约 40%。

**收益归因**

- 主要：未做独立收益拆分；论文归因于跨场景共享预训练基座、S-MoE 场景专家扩容与 CROP 离线后训练三者叠加
- 次要：工程管线统一：单基座 + 场景后训练替代一场景一模型
- 次要：低延迟容量扩容：S-MoE 1.71ms vs token-level MoE 22.18ms，显存降约 40%
- 次要：纯离线策略改进框架（critic 组内相对打分 + KL 约束）可复用到其他禁止在线探索的决策场景

**与你的关联**

- 出价与成本控制是广告链路核心组件：多场景统一建模、序列级 MoE 的延迟控制、离线策略改进三点可迁移到广告/推荐的多目标统一建模工作；对召回与精排模型结构本身无直接增量。

**风险或局限**

- 训练与评测全部基于快手私有 oCPX 日志，无公开数据，外部无法复现或独立验证。
- 线上 A/B 为单平台自报结果，部分场景置信区间很宽（ROAS 达 5.0%–28%），且无第三方或同期其他工业出价基线对比。
- 离线仅报告 NAP MSE 与 Q 回归等替代指标，缩放律拟合 R²=0.82 仅为指示性证据
- 收益未拆分到各组件归因。
- 不满足 Foundation Feature 定义：必须是离线基础模型为多个线上模型统一产出可复用特征。

## 今日最值得立项的实验

### 序列级 MoE 出价模型在广告出价场景的离线替代验证

- 假设：以场景身份硬路由的序列级 MoE（每块共享+路由专家、每序列激活固定专家数）相比 token-level MoE 或单场景模型，能在不增加单请求激活计算量前提下保持或提升出价决策质量。
- Control：现有生产出价基线（单场景决策模型）或同参数规模 token-level MoE。
- Treatment：按场景身份整条序列硬路由的 S-MoE 出价策略，动作头输出竞价乘子。
- 保持变量：训练/评测数据切分、状态与动作定义、离线评测窗口、请求 QPS 与 CPU 预算、激活参数量上限。
- 离线指标：出价动作离线价值/回报估计；成本比（CTG）控制误差；端到端推理延迟与峰值显存
- 线上 Guardrail：线上广告消耗与预算超投率；成本偏离度/ROAS 回退不超过预设阈值；延迟 P99 不劣于现网基线

### 召回-预排序双路候选低重叠的结构多样性收益验证

- 假设：在召回侧引入建模深度不同的两条互补路径（深度交互路径 vs 轻量库存覆盖路径），其候选低重叠可带来下游排序相关性与参与度提升。
- Control：现有单一路径召回/预排序候选集合。
- Treatment：双路候选按文档 ID 去重后合并送入同一排序器。
- 保持变量：下游排序器与特征、去重与过滤规则、请求流量切分、候选总预算上限。
- 离线指标：候选集合 Jaccard 重叠度；离线 DCG@K 与召回覆盖率；检索阶段计算量/延迟
- 线上 Guardrail：线上排序相关性不下降；端到端延迟与资源用量不超预算；过滤与合规规则命中率不劣化

### 显式跨任务交互替代预设漏斗在多任务排序中的离线对照

- 假设：用输入自适应的显式跨任务交互（任务以前驱实现结果为条件、强度可学习）替代共享单表征+固定漏斗，可缓解任务信号稀释并提升多目标排序效果。
- Control：共享底层表征 + 预设任务漏斗的现有多任务排序模型。
- Treatment：分离共享上下文流与任务专属流的双流结构，叠加显式跨任务交互层。
- 保持变量：训练数据与样本、任务头数量与定义、特征集合、训练步数与算力预算。
- 离线指标：各任务头 AUC/GAUC；多任务加权排序指标；不同任务头配置下的一致性
- 线上 Guardrail：线上主转化指标不下降；单次请求推理延迟与显存不超上限；训练稳定性（不出现任务间负迁移）


## 一句话总判断

本期 6 篇呈现两条清晰工程趋势：一是把单一主干/单场景模型改造为可解耦、可路由的模块化结构（IntHQ 的双流解耦与跨任务交互、OneBid 的序列级 MoE、ADAPT 的静态/动态与公共/私有画像解耦），二是把建模深度与库存广度分派到异构硬件与服务路径（GPU/CPU 协同检索）。可信度分层明显：Hybrid GPU-CPU Retrieval 与 OneBid 有 PDF 核验加线上 A/B，但前者多组件同时变更、后者为单平台私有日志自报且部分置信区间很宽，增益均无法归因到单一因素；IntHQ 仅有 1.60% 相对 UVCTR 的单一线上指标；ADAPT、DSRec、AutoRecLab 停留在摘要级证据，不能作为部署结论。
