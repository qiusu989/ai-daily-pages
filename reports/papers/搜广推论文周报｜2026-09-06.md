## 生成式召回

### P1｜[CoFiRec: Coarse-to-Fine Tokenization for Generative Recommendation](https://arxiv.org/abs/2511.22707)

**论文、机构与场景**

CoFiRec 论文由 UIUC、Meta、UCSD 研究者合作提交 arXiv (2511.22707v2)，面向电商/内容推荐的生成式召回场景。

**核心方法**

CoFiRec 将 item 拆成 category/title/description 三个语义层级并追加 CF token，每层独立向量量化，自回归模型按粗到细顺序生成语义 ID；论文在 Instruments/Yelp/Beauty 三个公开数据集及 T5/LLaMA-3.2-1B/3B 骨干上报告平均提升 7.27%，并给出分层解码期望不相似度更低的理论证明；代码已开源在 github.com/YennNing/CoFiRec；AHC 变体可用 GPT-4o 从 title/description 自动构建 4 级语义层级。

**主要创新或优化点**

为生成式推荐提供可学习的粗到细结构化 token 方案，保留 category/title/description 层级的可解释性并把 CF 信号作为最细粒度 token，提升准确率和冷启动泛化。

**关键结果**

CoFiRec 在 Instruments、Yelp、Beauty 上 Recall@10 分别 0.1118/0.0395/0.0679，优于 TIGER、IDGenRec 等基线；作者称平均提升 7.27%；冷启动场景下相比 TIGER，R@10 提升 10.0%（0.0943 vs 0.0801），warm 提升 4.7%；在 T5/LLaMA-1B/LLaMA-3B 三种 backbone 上均稳定超过 TIGER；tokenization 显存小于 1.8GB，生成阶段小于 4GB，耗时与 TIGER 相当。

**与你的关联**

对生成式召回和 SID tokenization 路线有直接参考价值，可迁移到具备层级元数据的电商或内容推荐场景；AHC 方案还支持元数据缺失时用 LLM 自动构建层级。

**可信度**

technical_report

**风险或局限**

仅 Instruments/Yelp/Beauty 三个公开数据集离线验证，无工业规模 A/B 或在线部署证据；语义 tokenizer 与自回归生成模型分两阶段训练，未端到端联合优化；AHC 实验仅使用 1% 用户子样本；性能依赖 category/title/description 等元数据；完全缺失时需额外 IE 或 GPT-4o 自动构建层级。


### P1｜[EPIC: Explicit Posterior Item Conditioning for Semantic ID Diffusion Recommendation](https://arxiv.org/abs/2609.03522)

**论文、机构与场景**

EPIC 是面向语义 ID 生成式推荐的学术论文,作者来自 VinUniversity、Griffith University 与 Aalborg University,场景是电商商品顺序推荐中的全目录下一物品预测,评估用 Amazon Beauty/Sports/Toys/Musical Instruments 四个 5-core 数据集。

**核心方法**

方法核心:在冻结的 masked-diffusion SID 骨干上,每步去噪中由已解析部分 SID 求可行候选集,用候选与用户近端历史构造个性化物品后验,再边缘化回未解析 SID 位并经模糊感知门残差融合进 token logits,只训练 0.391M 参数的 item adapter；作者报告在 16 个数据集-指标组合上全部超过最强基线,相对第二优提升 1.2%–16.8%,paired t-test 经 Holm 校正后 p<0.05,五次独立运行标准差最多 0.0011；归因实验显示增益主要来自去噪过程中的内联个性化 transition evidence:移除 transition 使 Beauty NDCG@5 下降约 15%,替换成另一用户历史使其下降 12.4%–17.9%。

**主要创新或优化点**

把 item-level 竞争显式引入 masked SID diffusion 去噪,弥补 token 级预测与完整物品选择之间的 gap;冻结 backbone 加零初始残差模块设计轻量,并用受控 inline/post-hoc 对照和轨迹级诊断把收益归因到去噪过程而非最终打分。

**关键结果**

推理时内联注入 item 证据比同一打分器放到生成后 rerank 在 Beauty/Sports/Toys 上 NDCG@5 高 15.7%/26.6%/26.8%,并可恢复部分 control 最终池外的目标；训练参数量比 LLaDA-Rec 全量适配少 94.3%,吞吐提升 42.7%,峰值训练内存下降 55.9%;推理延迟从 93.0 增至 124.8 ms/user,增幅 34.2%；只解析两个 SID 位即可接近最优质量且比解析全部四位快 1.72 倍,Beauty NDCG@5 约 0.0439。

**与你的关联**

对做生成式召回或 SID/item-token 空间候选产出的团队有直接参考价值;EPIC 以冻结 backbone 加轻量后验注入,可作为现有 masked-diffusion SID 生成器的即插即用增强,但当前仅为学术离线评测,线上 A/B 未核实。

**可信度**

technical_report

**风险或局限**

仅在公开 Amazon 5-core 学术基准离线评测,无工业规模数据与在线 A/B 证据；每步需精确扫描全目录计算可行集,复杂度 O(|I|H),大规模上线依赖额外的倒排 SID 索引,文中未做实现验证；SID 冲突下同一完整 SID 的物品不可区分,EPIC 设计上未加入物品身份特征。


### P1｜[HypRQ-VAE: Hyperbolic Item Indexing for Long-Tail-Aware Generative Recommender Systems](https://arxiv.org/abs/2609.03369)

**论文、机构与场景**

HypRQ-VAE（arXiv:2609.03369v1，cs.IR）由 Virginia Tech、Amazon、Meta AI、Google 与 Dartmouth 作者合作提出，面向生成式推荐系统的语义 ID 索引与长尾召回。

**核心方法**

方法核心：将基于文本的 item embedding 经指数映射进入 Poincaré 球，用 Möbius 减法做多层残差量化并输出序列化 semantic ID（如 a_1 b_3 c_2 d_9），弥补欧氏 RQ-VAE 对长尾 item 表征不足；两阶段流程：先训 HypRQ-VAE（语义 ID 生成，4 层×256 码本），再用 LLaMA2-7B+LoRA 微调生成式推荐模型，将历史交互 ID 序列作为 prompt 并以 NLL 预测下一项；推理用 beam=20 与 Trie 受限解码；对碰撞 item，用各层 codebook 距离张量做级联 token 重分配，末层码不够时逐层向上，给每个 item 唯一 ID；并分析 codebook 分布、初始化对表示效果的影响。

**主要创新或优化点**

首个在双曲空间做 item semantic ID 索引的通用框架；离线证据显示能实质拉近头部与长尾 item 的表示差距，可将 RQ/SID 类生成式召回直接升级，减少热门偏差与 LLM 幻觉候选。

**关键结果**

与最强 baseline 相比，三个数据集整体指标提升：Instruments 的 Hit@10/NDCG@10 相对提高 6.4%/14.0%，MovieLens Hit@10 +4.8%，Arts Hit@10 +4.3%；相对欧氏 TIGER(RQ-VAE)，长尾 T80 提升大：MovieLens Hit@10 +52.71%、Instruments +36.23%、Arts +17.24%；MovieLens NDCG@10 +43.43%；AQE 对比显示双曲码本头尾误差更均衡：MovieLens 尾部 AQE(0.00104) 低于头部(0.00109)，且无需额外正则即可获得较均匀 codebook 分配。

**与你的关联**

对生成式召回/TIGER 类候选管线：可替换 Euclidean RQ-VAE 为 HypRQ-VAE 复现语义 ID 层，代码与数据开源；重点观察真实商品/视频长尾召回对偏差与多样性的影响，需补 latency/成本评估。

**可信度**

technical_report

**风险或局限**

仅公开数据集离线验证（MovieLens、Amazon Instruments/Arts，item 规模为 0.28万–2.1万），无工业部署、A/B 或线上指标；大规模目录外推未验证；生成式 LLM（LLaMA2-7B+beam20）推理延迟与成本、以及更长 semantic ID 带来的解码开销未报告，直接上线的 serving 可行性不足；AQE 只宜在同一几何内比较，论文未报告曲率等超参敏感性；不同数据集和 head/tail 定义下增益差异大，泛化有待独立复现。


### P1｜[ICEGR: An Intent-Coherent End-to-End Generative Retrieval Framework for E-commerce Search](https://arxiv.org/abs/2608.29652)

**论文、机构与场景**

WSDM 2027 论文 ICEGR（arXiv 2608.29652），作者来自中国科学技术大学、百度、北京航空航天大学与中国人民大学，应用场景为百度电商搜索的生成式检索通路。

**核心方法**

ICEGR 三阶段框架：IA-SID 将查询点击共现图与历史查询画像注入 SID 构建；SQE-SFT 用多粒度合成查询统一到 query-to-SID 监督；RCPO 用相关性约束与动态 margin 校准商业偏好优化；离线基于百度约三个月电商日志（1280 万查询、1460 万商品），Recall@20 从 0.4247 提升至 0.5169（+21.7%），NDCG@20 +26.6%；在线部署为与现有 MCA 并行的端到端通路（0.5B 骨干、beam=50），20% 流量两周 A/B：CTR +3.52%、订单量 +15.96%、GMV +7.53%。

**主要创新或优化点**

把查询意图一致性作为统一准则贯穿生成式检索的 SID 构建、监督与偏好优化，解决长尾监督稀疏和商业偏好损害相关性两大落地障碍；并以端到端 GR 通路与 MCA 并行方式在百度电商搜索取得业务级提升，是该范式的工业落地实例。

**关键结果**

离线 Recall@20 +21.7%、MRR@20 +26.6%、NDCG@20 +26.6%；Recall@50 +16.1%；在线 A/B（20% 流量、两周）：Show PV +8.84%、CTR +3.52%、长点击率 +5.27%、订单量 +15.96%、GMV +7.53%；消融：SQE-SFT 占累计 Recall@20 增益 76.7%、RCPO 17.7%、IA-SID 5.6%；动态 beta 校准使人工 top-5 相关率由 0.58 回升至 0.87。

**与你的关联**

与搜广推团队直接相关：生成式召回通路、意图感知 SID、合成查询增强长尾监督以及相关性校准偏好的设计均可迁移到电商搜索或广告检索链路。

**可信度**

online_ab

**风险或局限**

离线基线为百度内部生产模型 ProdGR，且仅在同骨干、同数据设置下可比，无法与其他工业 GR 系统直接横向对比；在线仅报相对增益，模型与部署细节（如插入位置、与精排交互）因保密披露有限；离线指标以点击商品为相关 ground-truth，人工评估仅 50 条查询，业务偏好依赖点击/支付/GMV 加权，存在流行度偏置风险。


### P1｜[TGR: Advancing Industrial Recommendation from Generative-Paradigm Ranking toward Unified Generation and Reasoning](https://arxiv.org/abs/2609.00986)

**论文、机构与场景**

腾讯PCG发表TGR技术报告(arXiv:2609.00986)，在新闻/视频/小说等场景服务数亿用户的工业生成式推荐框架。

**核心方法**

TGR含三个方向：TGR-GenRank(精排CCFormer)、TGR-GenRec(BARGE生成式召回与HiGR整slate生成)、TGR-Reason(离线reason token注入)，共享SID tokenizer与Numerous-Torch训练设施；CCFormer用field分离交叉注意、子空间token mixing与分层序列压缩替代精排，5个Tencent场景A/B，其中2个已全量上线；BARGE经OSQ-VAE双通道SID与层级路径重排生成检索候选，HiGR经PCRQ-VAE+层级slate解码与ORPO对齐生成整列表；TGR-Reason由LatentRec导出的reason token注入在线解码。

**主要创新或优化点**

展示工业推荐从级联架构走向生成式范式的完整落地路径：Transformer精排、SID生成召回、整slate生成与离线推理注入统一在共享SID与训练设施上，并在Tencent多场景获得稳定线上增益。

**关键结果**

CCFormer：视频场景CTR +3.57%、广告收入+1.71%，训练比HSTU快2.21×且GFLOP约一半，5个场景A/B均显著；BARGE：Hit@5较OneRec提升10.2%与16.9%，全量后CTR +0.60%、阅读时长+1.70%，长期评估增益趋于增长；HiGR：离线slate质量提升15.9-21.3%，5×推理加速且P99低于50ms，线上watch time+1.22%、video views+1.73%；TGR-Reason新用户Hit@1 +477.8%，有效消费+1.75%。

**与你的关联**

对搜广推架构演进有直接参考价值，尤其是跨阶段共享语义ID、离线reason token注入、整slate生成及单次候选打分等思路，可在中文大流量推荐与广告场景借鉴。

**可信度**

technical_report

**风险或局限**

报告为厂商自报结果，A/B与部署数字未经第三方独立复现，OneRec等对比基线为自建实现；实验集中于腾讯PCG多业务场景，结论向其他平台的泛化性未知，且涉及内部业务规则和下游级联细节；线上长周期增益被归因于训练分布随全量上线演进，缺少对累计效应机制的独立消融验证；未提供公开代码或权重。


### P2｜[Off-Policy Evaluation for Semantic ID Recommenders: Does the Model's Own Code Hierarchy Help?](https://arxiv.org/abs/2608.28905)

**论文、机构与场景**

arXiv 论文《Off-Policy Evaluation for Semantic ID Recommenders: Does the Model's Own Code Hierarchy Help?》，作者 Artem Betlei，机构未披露，研究生成式推荐系统中语义 ID 的离线评估方法。

**核心方法**

论文提出在生成式推荐（SID）场景下，对语义 ID 的 code-prefix 聚类进行边际化以支撑离线策略评估（OPE），并分析此收益来源；论文指出在 near-argmax 日志数据下，item 级别 OPE 因有效样本量过小而失效，而聚类到 code-prefix 可恢复估计支持并降低误差。

**主要创新或优化点**

为生成式推荐（语义 ID）提供 OPE 方法框架，明确了 SID 树作为行动抽象的可行性与边界，有助于离线评估其优化效果。

**关键结果**

item 级 OPE 在生成式推荐的 production logs 上效果差，因有效样本量小；按 code-prefix 聚类边际化可降低 OPE 误差，收益主要来自粗粒度化而非 SID 层级本身；分支深度是操作旋钮：数据稀疏时更粗的分支有效，存在条件偏差界连接粗粒度偏差与量化器最坏重构残差。

**与你的关联**

若用于评估生成式召回（SID）的离线实验，可为决策提供方法论参考，但未提供可直接迁移的具体实现细节。

**可信度**

peer_reviewed_paper

**风险或局限**

PDF 正文未核验，核心结果未提供具体数字或工业 A/B 结果；SID 树作为抽象依赖特定生成式系统假设，泛化性待验证；结论基于理论分析和模拟场景，缺乏线上实证。

### P2｜[TAAL: Mitigating Early Beam Pruning in Generative Recommendation via Temporal Autoregressive Alignment](https://arxiv.org/abs/2608.29179)

**论文、机构与场景**

论文《TAAL: Mitigating Early Beam Pruning in Generative Recommendation via Temporal Autoregressive Alignment》来自arXiv，作者Lianjie Li、Zhiying Tu、Dianhui Chu、Hongliang Sun，机构未披露，属于生成式推荐技术研究，应用于电商推荐场景。

**核心方法**

TAAL针对生成式推荐中标准next-token预测未覆盖交互序列中的多模态转移，导致早期beam搜索分支中ground-truth SID被不可逆剪枝的问题，提出时间自回归对齐方法；训练阶段构建联合(c1,c2)软目标，用前向KL散度对齐早前缀分布；推理阶段用点互信息校准候选分数，降低全局频繁前缀的影响；在Amazon Beauty、Instruments和Yelp上，TAAL相较标准基线提升NDCG@10分别39.5%、6.7%、28.6%，全SID存活率提升3.9%-16.6%。

**主要创新或优化点**

针对生成式推荐中早期beam剪枝导致候选丢失的关键问题，提出训练与推理双向优化方法，改善生成式召回质量，为SID空间生成的效率与准确性提供新思路。

**关键结果**

仅在三类 Amazon 数据集评估，缺少工业 A/B 验证；未披露与大规模在线系统结合的计算成本与部署细节；鲁棒性提升幅度缺乏量化对比细节。


## 本周 Top 论文

- **ReST（字节广告CVR精排长序列）**：广告精排中行为序列缩放的系统性证据，AUC+1.31%与Advv+11.93%线上A/B显著且已全量，提供训练吞吐5.8x与序列饥饿解法，直接可用于电商/广告排序改造。
- **TGR（腾讯生成式排序全栈）**：工业级生成式范式统一精排、召回与整slate生成，多场景线上A/B且2场景全量，跨阶段共享SID与离线reason注入是架构级参考。
- **HubMixer（快手精排特征交互）**：以潜在hub路由降低特征交互复杂度，参数量减少仍获AUC提升，在线简历提交转化+5.48%全量部署，是可快速复用的精排模块替换选项。
- **ICEGR（百度电商生成式检索）**：意图一致SID与合成查询解决长尾监督，线上两周CTR+3.52%/订单+15.96%，生成式召回落地标杆，且SQE-SFT贡献76.7%增益可启发训练数据策略。
- **CAMIE（Snap广告多模态I2I召回）**：co-engagement行为监督是主要增益来源的严格控制归因，单checkpoint多模态召回服务，线上CVR+10.8%~13.1%显著，对广告多模态召回基建有直接迁移价值。

## 本周方法趋势

- 生成式召回工业落地提速：TGR、ICEGR、Pailitao均带线上数据或已部署，SID从学术token表示转为跨阶段可复用语义层。
- SID索引创新转向几何与量化：HypRQ-VAE（双曲空间）与上期PRQ-KMeans（投影残差）都在缓解长尾与碰撞，生成词表设计进入精细调优期。
- 精排侧出现两个实用升级方向：字节ReST将行为序列作为主要缩放轴，快手HubMixer用参数高效交互替代全量token mixing。
- 工业召回与精排开始统一利用行为监督（CAMIE co-engagement）与自适应算力分配（SetMIR presence gating），检索不再单点优化。
- LLM与Agent介入系统调优（RecEvolve）并暴露reward hacking漏洞，评估协议安全成为新议题。

## 今日阅读顺序

- TGR（腾讯生成式排序全栈）：跨阶段共享SID统一精排、生成式召回与整slate生成，多场景线上A/B且已全量，对短视频/电商/广告架构演进参考最大。
- ReST（字节广告CVR精排长序列）：广告CVR精排中行为序列Transformer缩放，AUC+1.31%与Advv+11.93%在线验证，直接可对照长序列精排改造。
- HubMixer（快手精排特征交互）：潜在hub降低交互复杂度并提参效，线上简历提交转化+5.48%全量部署，可作DCN/AutoInt替代模块。
- ICEGR（百度电商生成式检索）：意图一致的SID与合成查询监督解决长尾与偏好漂移，线上CTR+3.52%/订单+15.96%，生成式召回落地范本。
- CAMIE（Snap广告多模态I2I召回）：co-engagement监督统一LLM多模态embedding，线上CVR显著提升且归因严谨，广告多模态召回可直接借鉴。
- SetMIR（Snap广告多兴趣召回）：集合预测缓解兴趣坍缩并降低约33% ANN查询，线上CVR+3.11%，召回服务效率与质量兼顾。
- RecEvolve（Google agent自动调Two-Tower召回）：LLM agent闭环迭代生产召回模型，NDCG@50+19.9%且揭示reward hacking，对自动调优与评估安全有预警价值。
- HypRQ-VAE（双曲SID长尾生成召回）：首个双曲item索引减少长尾量化误差，可升级RQ/SID类召回，缓解热门偏差。

## 本周最值得做的实验

### HubMixer特征交互模块替换精排DCN实验

- 假设：以潜在hub路由替代全量token mixing，可在参数量更少时提升离线AUC并带动线上转化。
- Control：现有多任务精排（DCN/AutoInt交叉模块）
- Treatment：同骨干中嵌入HubMixer的hub归纳-交互-readout模块
- 保持变量：相同训练数据、特征体系、优化器、候选集构建逻辑
- 离线指标：AUC；GAUC；参数效率（AUC/FLOPs）
- 线上 Guardrail：在线CTR不下降；延迟增量<10%；pCTR校准不劣化

### 单级大语义码本+曝光感知动态更新实验

- 假设：以单级大码本加固定消歧码替代三级残差码本，并加入动态更新，可提升生成式召回效果与解码效率。
- Control：现有三级残差SID码本（RQ-KMeans）+静态更新
- Treatment：两级SID（语义码+消歧码）+曝光加权EMA动态码本更新（参考本期快捷两级SID设计）
- 保持变量：相同生成式模型骨干、训练语料、beam宽度、推理配置
- 离线指标：Recall@10；NDCG@10；码利用率；全SID碰撞率；重建相似度
- 线上 Guardrail：解码延迟不高于control；消费指标A/B不降；异常刷新率受控

### ReST风格共享前缀多候选精排实验

- 假设：采用用户级共享前缀训练与请求级KV共享，可降低长序列精排算力并保序质量。
- Control：现有长序列精排（单候选独立编码）
- Treatment：ReST式重计算编码器+共享前缀多候选解码（参考字节ReST）
- 保持变量：相同骨干维度、特征与训练数据、服务预算
- 离线指标：AUCΔ；NE；训练吞吐提升；序列饥饿缓解（梯度范数）
- 线上 Guardrail：P99延迟≤50ms；端到端算力不增；核心收入指标A/B不降


## 一句话总判断

本周生成式召回进入工业落地密集期：TGR、ICEGR、Pailitao-MMSearch在不同场景线上收益显著，SID从生成词表扩展为跨阶段共享语义层；精排侧出现长序列缩放（ReST）与参数高效特征交互（HubMixer）两个可靠升级点。但多数离线提升在0.0015-0.01 AUC量级、线上收益多为作者自报，无独立复现，跨平台外推需谨慎。
