## 生成式召回

### P0｜[VARG: Value-Aware and Ranking-Aligned Generative Retrieval for Dynamic E-commerce Search](https://arxiv.org/abs/2609.14493)

**论文、机构与场景**

- **机构：中国科学技术大学、阿里巴巴淘天集团、南开大学**
- 作者：Xiaopeng Chu、Jianbo Zhu、Mingmin Jin、Jing Wang、Xing Fang、Wenyi Zhang
- 来源：arXiv:2609.14493v1
- 场景：Tmall App电商搜索召回与预排序整合，生成式检索直接向现有精排输送候选

**核心方法**

- VARG-ID用RQ-VAE构建两级语义前缀，并以经验贝叶斯CVR排序生成第三token，形成无冲突的物品地址与业务价值先验
- 双向query-item对比学习将搜索相关性注入前缀。
- 三阶段SFT依次学习Item→SID、Query→SID、User+Query+History→SID
- 个性化阶段用Q2I样本加权、层级token加权、扩展用户上下文和LO-SFT局部序数监督。
- Prefix-GRPO用合法性、行为、精排优势和相关性的门控多源奖励，结合前缀感知token加权做GRPO对齐
- Trie约束beam搜索保证生成SID合法并映射为物品候选。

**主要创新或优化点**

- 把生成式召回作为额外通道直接接入精排并跑出电商GMV正收益，验证了value-aware SID与RL对齐在工业搜索候选生成中的可行性。

**关键结果**

- 14天线上A/B覆盖20%搜索流量：GMV +1.45%，人均IPV +0.22%，PCTR +0.31%，UCTR与UCTCVR各+0.13%。
- 相对SFT Base，Prefix-GRPO将GMV Recall@1提升5.47个百分点、Q2I-GMV Recall@1提升2.48个百分点、HR@1提升0.05个百分点。
- VARG-ID SFT Base相比三级RQ-VAE标识符，Q2I-GMV Recall@1/10/20分别提升15.50/13.65/0.93个百分点
- Trie约束使合法率从93.73%升至100%。

**收益归因**

- 主要：生成式召回通道提升候选价值覆盖与线上GMV
- 次要：GMV
- 次要：Q2I-GMV Recall
- 次要：候选配额效率

**与你的关联**

- 与用户关注的生成式召回、SID设计、RL对齐候选生成、电商搜索召回-精排一体化直接相关，方法与在线结果可复用或对照。

**风险或局限**

- 轻量并行解码器仅探索：平均延迟从10.41ms降至0.94ms、单卡QPS约11.1倍，但HR@1/20/100分别下降1.13/8.38/10.77个百分点，未上线主链路。
- 每日商品更新会冻结已有SID并允许新商品复用槽位，产生受控SID共享
- 每月重建SID版本，长期标识稳定性与新商品冷启仍受约束。
- 线上收益来自VARG-ID、三阶段SFT、Prefix-GRPO和配额策略的组合，未做组件级线上归因
- A/B仅14天20%流量，无外部复现。


### P1｜[OneLA: Scaling Linear-Attention Decoding to Large Beams in Generative Recommendation](https://arxiv.org/abs/2609.12399)

**论文、机构与场景**

- **机构：香港大学、快手科技与北京大学**
- 作者：未单列
- 来源：arXiv:2609.12399v1
- 场景：快手工业级生成式推荐（SID 序列大 beam 解码）的解码系统优化

**核心方法**

- OneLA 用单个共享 post-prefill 循环状态 Sctx 加紧凑 append-only 的 GDN Transition Record（GTR，含 α、δ、k）表示所有 beam 状态，只按投影重放分支特有转换，不物化每条 beam 的 d_v×d_k 完整状态矩阵。
- 用轻量 ancestry index 解耦逻辑 beam 演化与物理记录位置，beam 剪枝/重排/扇出只复制索引而不搬移 GTR
- 并实现 fused shared-context GPU kernel，将投影重放保持在片上并跨 beam 复用 Sctx。
- 评测基于 0.8B Qwen3.5（6 层 full attention + 18 层 GDN），全模型设 R=4、W=256、prompt 1K/5K、输出 3–7 token
- 算子套件覆盖 405 个形状（R=4/8/16、W=128/256/512、T=2–6、九种循环几何）。

**主要创新或优化点**

- 生成式推荐需大 beam 解码产生数百候选，使线性注意力的循环状态存储与带宽成为新的扩展瓶颈；该工作给出共享状态+紧凑转换记录+祖先索引+融合 GPU kernel 的可复现系统方案，直接压缩解码时延与显存/DRAM 开销。

**关键结果**

- 全模型 decode-forward GPU 时间相对 Controlled FullState 降低 1.54–2.46×，覆盖全部评测 prompt 与输出长度，且一致优于 vLLM FullState/ReplaySSM。
- 算子级中位加速：相对 vLLM 与 SGLang FullState 为 40.5×/42.5×，相对两条 ReplaySSM 路径为 17.5×，相对 FlashInfer 与 TensorRT-LLM 为 41.5×/46.3×
- 405 个算例相对 FP32 FullState 最大绝对输出误差 4.88e-4。
- R=4、W=512 的 Qwen 几何下循环状态路径延迟降低 39.7×/35.4×，持久状态容量降低 56.5×/20.3×，状态写入降低 127×，DRAM 流量 161 MiB（相对 FullState 76.9×、ReplaySSM 39.9×）。

**收益归因**

- 主要：推理侧效率收益：大 beam 解码端到端时延与循环状态显存/DRAM 流量下降；业务指标未核实
- 次要：降低 GR serving 显存与带宽占用
- 次要：线性注意力/SSM 推理引擎与 GPU kernel 实现参考

**与你的关联**

- 对生成式召回线上服务的大 beam 解码、线性注意力/SSM 推理引擎实现、显存与带宽瓶颈优化有直接参考价值，可作为 GR serving 侧的复现基线。

**风险或局限**

- 仅离线评测，无线上 A/B、生产部署或 QPS/成本指标
- 基线为受控实现与开源 serving 框架。
- 输出长度仅 3–7 token，强依赖“长共享 prompt + 短分歧后缀”假设，长解码、多轮或 prompt 极短场景未验证。
- 未披露业务侧指标（CTR/GMV/召回质量）与端到端成本变化，收益归因集中在时延、显存与 DRAM 流量。


### P1｜[Recommendation Retrievers Need Verifiers: Universal Generative Reranking for Sequential Recommendations](https://arxiv.org/abs/2609.12270)

**论文、机构与场景**

- **机构：未披露**
- 作者：未单列
- 来源：arXiv:2609.12270v1
- 场景：未披露

**核心方法**

- 冻结召回器、只对其 top-K 候选池（Amazon 100、YaMBDa 1000）重排：2 层 2 头宽 128 因果 Transformer verifier 按物品标识 token（4 级 RQ 语义 ID + 4 头 hash ID）的自回归对数似然打分，再以加权 RRF（κ=60）与原序融合并保留原序尾段。
- 训练只用 next-token 交叉熵监督每个非 padding 前缀位置，不需要采样负样本、in-batch 负样本或候选池
- 召回器冻结以避免破坏其广召回目标，推理只对池内候选重算并与其他阶段解耦。
- 结果：Amazon Industrial Recall@10 提升 SASRec +6.2%、GRU4Rec +8.1%、NextItNet +8.4%，Office 为 +9.9%/+10.8%/+14.5%
- YaMBDa-5B 上三者 +25.3%/+27.3%/+29.8%。

**主要创新或优化点**

- 在召回与精排之间插入轻量输出侧验证器，不改召回器、不重建索引即可把被下游消费的小前缀 Recall@k 抬高，为多阶段链路提供低成本的召回池重排/短名单提升方案。

**关键结果**

- YaMBDa-50M/500M/5B 上 NextItNet 的 Recall@10 相对提升 +14.4%/+24.2%/+29.8%，作者归因于目录稀释：目录越大，召回池内可回收的相关物品越多。
- Amazon 上同一 verifier 配方提升全部三个序列召回器与 LLM 生成式召回器 MiniOneRec，但强召回器提升最小（MiniOneRec 仅 +2.6%/+4.6%）。
- 标识通道消融：YaMBDa-500M 上 hash-only 已接近全量（SASRec 4.75 vs 4.88 Recall@10，语义-only 4.38）
- 小目录 Amazon 上语义 ID 更好
- 内容对照中 +C 召回器单独更差（3.47 vs 4.16），内容-only 召回器被 verifier 提升 +247–289%。

**收益归因**

- 主要：提升首阶段召回转发前缀的 Recall@k（离线评测，未见线上指标）
- 次要：无需重训召回器或重建索引，可后接异构召回模型
- 次要：verifier 训练无需负采样与候选池，训练成本低
- 次要：融合用 RRF，避免跨模型/跨 token 化分数校准

**与你的关联**

- 直接对应推荐系统首阶段召回短名单质量与召回-粗排衔接问题；接口仅需召回器状态与固定物品 token 化，可复用到现有自注意力/RNN/卷积/生成式召回模型，评测与消融设计也可借鉴。

**风险或局限**

- 全部为离线 Recall@k 评测，无在线 A/B、生产部署、时延或成本数据，多阶段收益未在生产链路验证。
- verifier 只重排冻结召回器的 top-K 池，无法召回池外物品
- 池大小 K 与融合权重 w 依赖验证集调参，强召回器上提升有限。
- Amazon 目录仅数千物品且未过滤已看历史项，YaMBDa 无文本、MiniOneRec 无法适用
- 未与完整精排或价值模型对比。


### P1｜[Self-Evolving Memory for Generative Recommendation](https://arxiv.org/abs/2609.15598)

**论文、机构与场景**

- **机构：National University of Singapore、Meta AI**
- 作者：Xinyu Lin 等
- 来源：arXiv:2609.15598v1
- 场景：在 Amazon Reviews 的 Games/CDs/Toys 上做流式持续生成式推荐（next-item prediction）

**核心方法**

- 识别出 evolution conflict：在完全共享的自回归参数空间中持续适应，主导行为模式会逐步压制 underrepresented 偏好模式。
- 提出 LION：在 T5/TIGER 生成式推荐骨干的中间层插入 sparse Key-Value memory layer，通过 query 驱动的 Top-K 稀疏激活隔离不同行为模式。
- 设计 consolidation loss 对 memory-enhanced representation 施加辅助监督，总损失为 L_rec+λL_con
- 并用 full-sequence memory query 路由，骨干只处理近期序列。

**主要创新或优化点**

- 指出生成式推荐持续演化中的 evolution conflict，并用稀疏 KV 记忆隔离不同行为模式，为长尾/非活跃用户召回退化提供新解法；若成立对持续学习式生成式召回有参考价值。

**关键结果**

- 在 Games 数据集上，LION 的 R@10/N@10 达 0.0724/0.0454，较 TIGER 的 0.0558/0.0336 提升 29.8%/35.3%。
- 在 CDs 数据集上，LION 的 R@10/N@10 达 0.0449/0.0306，较 TIGER 的 0.0331/0.0213 提升 35.5%/43.7%。
- 在 Toys 数据集上，LION 的 R@10/N@10 达 0.0769/0.0495，较 TIGER 的 0.0666/0.0418 提升 15.6%/18.4%。

**收益归因**

- 主要：未核实
- 次要：离线 R@10/NDCG@10 提升
- 次要：非活跃用户组长尾收益更明显
- 次要：记忆参数不随用户规模增长，具备可扩展性

**与你的关联**

- 与生成式推荐、召回侧持续学习、长尾/冷门偏好建模直接相关；可评估稀疏记忆隔离是否适用于当前工业生成式召回架构。

**风险或局限**

- 仅在 Amazon Reviews 离线数据集上评估，无线上 A/B 或生产部署结果，无法确认工业收益。
- 实验只在 T5/TIGER 骨干上验证，未覆盖 LLM-based 或其他生成式推荐架构。
- 记忆路由采用固定 Top-K 激活，自适应路由仍为未来工作
- Theorem 4.1 的隔离效果依赖后续经验验证（Corollary 4.1 非保证）。

**主要创新或优化点**

**关键结果**

- 摘要声称 NarraLite 在续写准确率、叙事连贯性与鲁棒性上持续优于现有方法，但未给出具体数值
- 摘要声称取得较优的准确率—效率权衡，但未披露具体效率或延迟数字

**收益归因**

- 主要：未核实
- 次要：隐式推理替代显式理由生成以降低计算开销
- 次要：多模态叙事证据压缩

**与你的关联**

- 与生成式召回（SID/token 生成）和多模态表征方向相关，但面向短剧叙事续写而非电商/广告/短视频主推荐链路，迁移性需自行评估。

**风险或局限**

- 只有 arXiv 摘要证据，无 PDF 正文核验，也未见同行评审或线上 A/B
- 所有关键结果均无具体数值，准确率与效率收益无法量化核验

- 作者：Yuchen Guan、Jiaye Liu、Yifei Han、Zhenxi Zhang、Yixuan Weng、Bin Li
- 来源：arXiv:2609.14565v1（cs.CL 预印本，2026-09-13）
- 场景：Amazon Reviews 2023 三个类目上的 LLM 序列推荐全目录 top-K 排序

**核心方法**

- TATK 复用同一份由商品元数据（store/category/main category，类目组上限 350）构建的物品图，分别承担提示侧上下文接地、训练侧位置感知奖励、推理侧结构感知重排三个角色。
- Top-K Learning 的位置感知奖励 rpos(r)=(K−r+1)/K（r≤K，否则 0），在 batch/rollout 组内中心化为相对优势，并与 token 级损失、item 级推荐损失结合
- 训练用 LoRA rank 4/alpha 128、3 epoch、lr 1e-5、batch 4、group size 4。
- KGV 在单次 LLM 前向产出的 top-M=100 候选上，用同一物品图计算支撑度 raw=min(γ, m+βn)（γ=2.5、β=0.15）并归一化后以 λ=0.01 加回生成分，按历史长度/KG 支持/band/不确定性门控，重排不增加 LLM 前向次数。

**主要创新或优化点**

- 指出 LLM 序列推荐把全目录 top-K 排序当作文本生成的三个错配（输入弱接地、训练目标与排序指标错配、生成候选缺验证），并用同一元数据图在训练奖励与推理重排两端对齐排序效用，且不增加 LLM 前向。

- 在 Gemma-2-2B-It 与 Qwen2.5-3B-Instruct 两个 backbone（5 seed，mean±std）上，TATK 相对匹配协议下自跑的 R2ec 在全部 36 个报告指标上提升
- NDCG@10 提升幅度 Qwen 为 8.05%/4.26%/3.78%，Gemma 为 27.03%/10.52%/10.23%（MI/CDs/VG）。
- 3 seed 组件消融（Gemma）平均 N@10：Base RecPO 0.0317，仅上下文 KG 接地 0.0338，仅位置感知奖励 0.0334，仅结构重排 0.0329，完整 TATK 0.0358（TKL +0.0029，KGV 再 +0.0012）。
- 效率：Base RecPO 单次 LLM 前向 420 ms/用户，完整 TATK 490 ms/用户（1.17×），显存 14.8 GB→15.0 GB
- M 从 100 增至 200 平均 N@10 仅 0.0359→0.0361，延迟 490→540 ms/用户。

**收益归因**

- 主要：top-K 排序质量提升（NDCG@10/HitRate@10），主要来自训练目标与排序位置对齐以及用元数据图对 top-M 候选做结构化重排
- 次要：训练目标与 top-K 指标对齐（位置感知奖励）
- 次要：同一元数据图同时服务提示、训练与推理，复用成本低
- 次要：重排引起的候选升降级可追溯到 store/category 关系

**与你的关联**

- 与 LLM 排序链路改造相关：位置感知 top-K 奖励可用于对齐训练目标，top-M 候选的元数据图重排可在不增加 LLM 前向的前提下接入现有链路，但收益依赖元数据质量与覆盖率。

**风险或局限**

- 仅有离线全目录评测，没有线上 A/B、用户满意度、多样性或业务指标
- MovieLens-1M 只是初步可移植性检查（NDCG@10 +4.5%，3 seed）。

### 可缓存目标无关用户长序列表征替代per-candidate检索

- 假设：用目标无关、可离线缓存的分段合并用户token（近端保留、中远段多粒度压缩）替代SIM/ETA式逐候选超长序列检索，可在精度基本持平下显著降低训练与serving成本。
- Control：现有精排模型：逐候选target-attention长序列检索（SIM/TWIN式），训练与推理均在线计算用户长历史。
- Treatment：在精排中接入与候选无关的压缩用户token（含近端1:1保留与中远段kernel合并），按用户缓存复用，仅排序头处理候选交互。
- 保持变量：相同候选池与特征体系、相同训练数据与步数、相同序列长度上限与采样口径。
- 离线指标：GAUC/AUC；训练显存峰值与单步耗时；推理p99延迟；Full-Attn精度差距
- 线上 Guardrail：线上p99延迟不超过SLA；缓存写入/存储成本在预算内；核心排序指标A/B不下降；冷启动与低活用户GAUC不劣化

### SID标识能力对照：value-aware第三token与hash/语义通道消融

- 假设：在SID中加入业务价值先验token或并行保留hash与语义标识通道，可在重排/召回前缀Recall@k上优于单一语义前缀构造。
- Control：现有语义SID（如三级RQ-VAE）作为唯一标识通道。
- Treatment：在召回器冻结前提下，用带价值先验的SID或hash+语义双通道作为轻量verifier打分依据并入RRF融合。
- 保持变量：相同召回器与top-K候选池、相同下游排序模型、相同训练监督（next-token交叉熵）。
- 离线指标：Recall@10/20前缀覆盖率；MRR@20；SID合法率；标识通道消融对比
- 线上 Guardrail：重排延迟增量在预算内；强召回器上不引入负增益；候选池外召回不下降；标识版本切换期线上指标稳定

### 作者/内容级rationale特征与负反馈SID集成

- 假设：将LLM/MLLM生成的正向rationale embedding与负向rationale层次SID作为精排附加特征，可同时提升参与指标并抑制负反馈。
- Control：现有精排模型，不含rationale类文本特征与负反馈专用SID通道。
- Treatment：新增正向rationale embedding做用户-作者交互建模，负向rationale的层次SID与ID拼接做target-aware拒绝记忆。
- 保持变量：相同特征主干与多头输出、相同训练数据窗口、相同A/B流量分配。
- 离线指标：AUC/GAUC；负反馈类目标AUC；rationale质量评分（holistic/specificity/grounding）
- 线上 Guardrail：举报率/负反馈不上升；在线延迟增量可控；冷启动作者覆盖不劣化；正负特征冲突时参与指标不下降


## 一句话总判断

本期工业证据集中在两条路线：一是把生成式预训练或大Transformer推向精排，LazFormer以16M用户/11B token预训练、零初始化残差适配与非对称多epoch训练拿到线上GMV+9.85%（单机吞吐-12.1%），ChronicleRec以可缓存时间锚定token把超长序列建模与线上候选打分解耦；二是生成式召回的SID质量与偏好对齐，VARG、UniPolicy、LION分别从价值先验SID、多目标策略解耦与稀疏记忆隔离入手，但除VARG外多为离线或作者自报。工程判断上，本期最可信的增量是链路内结构性改造（缓存式用户表征、精排序列化、标识通道增强），端到端联合训练多模态编码器在NMR中出现明确负面证据，迁移前需按各自日志与分流口径复验。
