## 生成式召回

### P1｜[Grounded Token Initialization for New Vocabulary in LMs for Generative Recommendation](https://arxiv.org/abs/2604.02324)

**论文、机构与场景**

论文《Grounded Token Initialization for New Vocabulary in LMs for Generative Recommendation》(arXiv:2604.02324v2) 由 UW-Madison、LinkedIn、东北大学与 UC Davis 合作，一作在 LinkedIn 实习；应用场景为 LinkedIn 招聘场景的生成式候选检索与公共衣物租赁生成式推荐。

**核心方法**

论文诊断均值初始化令 SID 新词嵌入坍缩到低秩子空间，提出 GTI：冻结 LM backbone，仅用文本描述与 SID 配对监督训练新 token 嵌入，之后再做标准 SFT；基座为 Qwen3-0.6B 与 RQ-VAE；工业数据集为 2025 年招聘平台岗位要求-候选人配对，按内部 LLM 评估分为 good/good&maybe/not match；RQ-VAE 为 L=3、K=8192。公共 Vibrent 用 Qwen3-Embedding-0.6B 特征，L=4、K=256；GTI grounding 阶段训练 8000 步、batch 128，仅更新 Enew；之后解冻再 8000 步并接 SFT；LC-Rec 基线为均值初始化加多任务辅助 SFT。

**主要创新或优化点**

系统指出生成式推荐中 SID 新词嵌入初始化的坍缩瓶颈，并提出轻量 grounding 阶段，显著优于均值初始化与现有辅助任务方法；将词表扩展与语义对齐分离，可复用到多种生成式检索场景。

**关键结果**

招聘候选检索上，GTI+Multi-task SFT 相对 vanilla SFT 的 P@5 提升 +21.63%（Good Match），LC-Rec 为 +6.38%，GTI 额外增益 +15.25%；NDCG@5 +17.88% vs +6.94%；公共 Vibrent 上，GTI+Vanilla SFT 的 Recall@20 相对 SFT 提升 +26.02%，LC-Rec 为 +13.41%；Recall@10 +22.03% vs +11.86%；谱与几何分析显示 GTI 初始化后 SID 嵌入有效秩更高、保留 RQ-VAE 分块层级结构，且该结构在 SFT 后仍持续。

**与你的关联**

若负责生成式召回或 SID token 训练，可在现有 pipeline 中插入 grounding 阶段，无需改动推理结构；对招聘、电商、短视频等候选生成的冷启动和收敛质量有参考价值。

**可信度**

technical_report

**风险或局限**

工业数据集因数据共享限制只报告相对增益，无绝对指标，且无线上 A/B 或部署验证；公共验证仅 Kaggle 衣物租赁数据集，场景与规模有限，通用性证据不足；论文为 arXiv 预印本，未经同行评审，结论主要来自离线评测与内部 LLM judge。


## 召回

### P2｜[Planning over Matrix-Factorization MDPs for Candidate Generation](https://arxiv.org/abs/2607.02115)

**论文、机构与场景**

Mikhail Trapeznikov（AI VK 与莫斯科国立大学）和 Maksim Utushkin（AI VK）发表于 KDD 2026 端到端客户旅程优化工作坊，面向推荐服务的 top-K 候选召回，离线数据覆盖 MovieLens-1M、KuaiRec/VK-LSVD 短视频和 YAMBDA 音乐。

**核心方法**

方法将 top-K 召回建模为隐式 ALS 后验 (A^-1,u) 上的 MDP，动作是候选物品，转移用 Sherman-Morrison 秩一 fold-in 闭式更新，单步成本 O(d^2)；轨迹奖励为相关性相似度加后验对齐项，比较 Static、Plan-1 与 horizon-K MCTS；在固定同一套 MF 嵌入、不重训练不改表征的条件下，LLN 协议下 Plan-1 在五个数据集 Recall@10 全部超过 Static；GTS 协议下增益只在 MovieLens-1M 与 VK-LSVD 切片保持，KuaiRec/YAMBDA 上失效；结论是单步 lookahead 已获得大部分收益，建议优先部署 cosine 相关性下的 Plan-1，仅当验证集显示序列结构时才用 Plan-K；内积相似度会放大流行度，是增益不成立的原因。

**主要创新或优化点**

在固定 MF/iALS 嵌入上额外加一层轻量规划即可把静态 top-K 召回变成有序轨迹决策，并给出了何时值得做动力学感知规划的判据，对短视频/音乐等工业召回有低成本增量优化参考。

**关键结果**

LLN 下 Plan-1 Recall@10 全面优于 Static：VK_IP 0.0201→0.0294、VK_UP 0.0161→0.0260，显著水平达到 p<0.001 级；KuaiRec 上 Plan-K 达 0.1107（p<0.01）；GTS 下 VK_UP Recall@10 0.0115→0.0162（p<0.01）、ML-1M nDCG@10 0.1446→0.1552（p<0.05）；KuaiRec 与 YAMBDA 上 Static 反而最优，作者归因于时间漂移下乐观 fold-in 失准；dot 相关下 Plan-1 基本不优于 Static，cosine 是规划增益的前提；Plan-K 相对 Plan-1 的额外收益仅在个别 LLN 数据集出现。

**与你的关联**

若线上召回基于隐式 ALS/MF 或 ANN 检索，Plan-1 单步 fold-in 重排无需重训练即可尝试提升 Recall/nDCG；落地前需用全局时间切分验证漂移，并确认线上相关性是 cosine 而非内积。

**可信度**

peer_reviewed_paper

**风险或局限**

环境是乐观且确定性的，假设所选物品一定被接受并折入正历史，未建模拒绝、会话终止和延迟反馈；GTS 下在 KuaiRec/YAMBDA 上失效，对时间漂移敏感；若线上使用内积相似度，规划增益消失；仅有离线 Recall/nDCG 评估，VK/YAMBDA 被限制在 top-5000 候选池，无在线 A/B 或生产部署证据。


## 多任务与目标建模

### P2｜[Beyond a Single Story: Meta-Reviewing Sparse and Incomplete User-generated Contents for Recommendation](https://arxiv.org/abs/2608.26728)

**论文、机构与场景**

论文《Beyond a Single Story: Meta-Reviewing Sparse and Incomplete User-generated Contents for Recommendation》来自 arXiv，作者机构未在元数据中披露，场景为推荐系统中基于用户生成内容的评分预测。

**核心方法**

提出MOSAIC框架，通过聚合邻居用户评论中的属性-情感证据为每个目标用户构造元评论，解决评论缺失和不完整问题；采用多门混合专家（MMoE）架构联合优化评分预测和元评论属性-情感预测，并利用注意力机制个性化聚合信号；在四个真实数据集上实验，MOSAIC在推荐准确性和解释质量上优于现有基线，尤其对交互历史少的用户有稳定提升。

**主要创新或优化点**

该工作针对UGC稀疏和不完整问题提出元评论聚合方法，通过多任务学习增强评分预测和解释能力，在工业推荐中可缓解冷启动并提升可解释性。

**关键结果**

MOSAIC在四个真实数据集上一致优于最先进基线（具体数值未在摘要中披露）；在推荐准确性和解释质量两方面均有提升；对交互历史有限的用户带来一致增益。

**与你的关联**

适用于电商、短视频等依赖用户评论的推荐场景，可提升对低活跃用户的推荐效果和解释质量。

**可信度**

peer_reviewed_paper

**风险或局限**

摘要未披露具体性能数字和数据集细节；未说明与工业规模系统集成时的计算开销；未提供真实线上实验验证。


## 偏差与校准

### P1｜[Incremental Recommendation via Causal Models](https://arxiv.org/abs/2608.26804)

**论文、机构与场景**

arXiv 2608.26804v1《Incremental Recommendation via Causal Models》，作者来自 Spotify、帝国理工和 UCL，在 Spotify Home 推荐表面做增量推荐效率优化。

**核心方法**

将生产多任务共享躯干模型扩展为 Deep Twin Network，新增 holdback head 预测有机流媒体概率，用既有随机 holdback 数据以 partitioned loss 训练，无需新数据采集；双阈值投放策略：仅当 treated stream 概率高且 organic 概率低时投放推荐，即 pi=1[p1>=theta1]*1[p0<=theta0]；A/B 测试覆盖数百万 Spotify 用户，推荐曝光减少 7.1%（CI [-7.2%, -6.9%]），推荐内容消费下降 0.37%（CI [-0.86%, +0.21%]），无统计显著差异。

**主要创新或优化点**

首个在生产级 Spotify Home 用既有 holdback 基础设施构建因果增量推荐系统，解决归因窗口不匹配的结构性障碍，A/B 证实可节省 7% 曝光且不损失消费，方法可迁移至其他有 holdback 实验的推荐/广告系统。

**关键结果**

在数百万 Spotify 用户的生产 A/B 中，双阈值策略减少 7.1% 推荐曝光（95%CI [-7.2%, -6.9%]），推荐内容消费无显著变化（-0.37%，CI [-0.86%, +0.21%]）；联合 holdback 数据训练显著改善 treated head 校准，尤其在高预测概率区间，并被视为因果模型表征更泛化的证据；结果表明生产基线中约 93% 的曝光本身就是增量的，双阈值策略精确移除约 7% 的非增量 always-takers。

**与你的关联**

对有随机 holdback 实验数据且关心增量价值的搜广推团队可直接复用：在现有模型加 holdback head 和双阈值策略，无需新数据采集，可节省曝光资源并改善校准。

**可信度**

online_ab

**风险或局限**

A/B 仅报告曝光和推荐消费两个指标，未给出总消费、满意度等 guardrail 的具体数字；阈值 theta1/theta0 的取值和离线调优流程未披露，缺少敏感性分析；treated 与 holdback 样本存在约 30% 分布偏差（serving vs client-side impressions），论文未提供修正措施。


## LLM 增强与对话推荐

### P1｜[When Memory Takes Gradients: Collaborative Vector Memory for Agentic Recommender Systems](https://arxiv.org/abs/2608.26895)

**论文、机构与场景**

CoVeMem（arXiv 2608.26895v1，cs.IR）由深圳技术大学 Hanchong Chen 等撰写，面向 LLM 驱动的 agentic 推荐系统，在 InstructRec 的 Books/Goodreads/MovieTV/Yelp 四个指令化基准上对每个含 10 个候选的集合打分排序

**核心方法**

核心方法：用 LightGCN 在训练交互图上预训练并冻结 64 维用户/物品状态作记忆库；决策时以候选集质心检索 K=5 个历史状态，经门控投影器映射为 soft token 与 LoRA 一起注入冻结的 Qwen2.5-7B；训练分两阶段：物品语义锚点对比对齐（τ=0.07）加候选标题按 p=0.5 掩蔽的 listwise 排序损失（hinge margin=1.0）；推理用逐点 Yes/No logit 打分，指令位置由零样本规则卡按数据密度选择；与文本记忆方法对比：对最强基线 MemRec 在 20 个指标格中 19 个达到或超越；记忆维护零额外 LLM 调用，每用户决策 token 成本四系统最低

**主要创新或优化点**

首次把协同表征当 agentic 推荐系统的持久记忆载体：记忆内容与读取方式都可被排序梯度训练，突破文本记忆串行改写和无法保留全目录协同几何的局限，用零额外维护 LLM 调用取得对文本记忆 agent 的全面超越

**关键结果**

对最强文本记忆 agent MemRec：20 个指标格中 19 个达到或超越；Goodreads Hit@1 0.7730 vs 0.3087，Yelp 0.5400 vs 0.5173，MovieTV 0.5799 vs 0.5371，Books 在 H@3/H@5/N@5 领先；效率：相比文本记忆 agent 每交互或每决策的 LLM 维护调用，CoVeMem 记忆维护零额外 LLM 调用，每用户决策 token 成本为四系统最低，处于准确率-成本 Pareto 前沿高准确率端；消融与背骨：去掉 LoRA 读取器后 Goodreads Hit@1 从 0.7730 跌至 0.1001（约随机）；记忆银行可换 SASRec/BPR-MF/GRU4Rec/SVD++，最强背骨 SVD++ 在 Yelp Hit@1 0.5569 超过默认 LightGCN 的 0.5400

**与你的关联**

对推荐链路 LLM 增强精排有直接借鉴：给出协同向量以 soft token 注入、LoRA 读取接口、候选掩蔽 listwise 训练与逐点 logit 打分的完整配方，可迁移至对话推荐或 LLM judge 精排；但仅离线 10 候选小集证据，落地需先验证更大候选规模和线上 A/B

**可信度**

technical_report

**风险或局限**

评测仅在 N=10 的离线小候选集上进行，未覆盖大规模候选集或线上部署；负样本为固定种子均匀采样，依赖既定评测协议；记忆银行在完整训练交互图上以传递方式估计且训练期冻结，需离线一次性构建，不支持在线实时更新；实验只跑在单张 A800 GPU 上；收益受协同背骨质量限制：Yelp 上最弱背骨 SASRec 相对文本-only 无明显优势；指令不参与训练、仅在推理引入，与 InstructRec 数据设定强耦合

### P2｜[REPREC: Representation Driven Parameter-Efficient Recommendation System](https://arxiv.org/abs/2607.24845)

**论文、机构与场景**

REPREC 论文由 Harshini Kavuru 等人提交至 arXiv，机构未披露，研究 LLM 序列推荐中的参数高效调整问题。

**核心方法**

REPREC 将冻结序列编码器的固定大小用户嵌入，经轻量 MLP 注入器映射为少量软 token，条件化冻结 LLM，仅训练注入器；REPREC 兼容不同预训练序列编码器和 LLM 骨干，支持模块化推荐流水线，无需修改任一预训练组件；代码已在 GitHub 公开，地址为 https://github.com/phdbotcode/REPREC。

**主要创新或优化点**

展示冻结双骨干加轻量注入器的参数高效范式，兼顾推荐质量与部署效率，为 LLM 序列推荐提供更低成本的替代方案。

**关键结果**

REPREC 在多个基准数据集上一致优于 LoRA，尤其对 casual 和 core 用户提升明显；短提示训练、长上下文评测时，REPREC 保持 LoRA 性能的 85-100%；相比 LoRA，REPREC 每 epoch 训练时间平均减少 1.51 倍。

**与你的关联**

该方法可降低 LLM 推荐系统的训练与部署开销，适合工业场景中需要模块化、兼容现有编码器的应用。

**可信度**

technical_report

**风险或局限**

输入仅含摘要，无 PDF 正文，无法核验实验细节与基准环境；作者所属机构未披露，无法确认工业来源或独立验证；性能优势依赖基准数据集，泛化性未证实。


## 出价与竞价机制

### P2｜[Strategy-Aware Parameter-Efficient Adaptation for LLM-based Auto-Bidding](https://arxiv.org/abs/2607.24232)

**论文、机构与场景**

arXiv 预印本《Strategy-Aware Parameter-Efficient Adaptation for LLM-based Auto-Bidding》由电子科技大学、阿里淘宝天猫集团与海南大学研究者合作提出，面向广告自动出价场景。

**核心方法**

提出 SAGE 框架，包含位置增强（时间-语义位置编码）、文本对齐（门控交叉注意力）与约束门控 LoRA（MoE 路由）三个模块，冻结 LLM 骨干仅训练少量参数；在阿里巴巴公开 AuctionNet-dense/sparse 基准上，100% 预算下 score 较最强传统基线 DT-score 提升 4.49%/7.83%，较最强 LLM 基线 LLM-DT 提升 6.40%/10.15%；相比全微调，SAGE 可训练参数减少 91.70%（31.6M vs 380.6M），冻结骨干效果优于全微调；代码仅声明将发布。

**主要创新或优化点**

为 LLM 参与广告出价提供参数高效与约束感知的适配框架，避免全量微调成本，在开放 AuctionNet 基准上稳定超越离线 RL、生成式与 LLM 基线，对出价策略的工业部署有直接参考价值。

**关键结果**

在 AuctionNet-dense/sparse 各预算档（50%-150%）均取得最佳 score；100% 预算相对 DT-score 提升 4.49%/7.83%，相对 LLM-DT 提升 6.40%/10.15%；参数效率：可训练参数为 31.6M，全微调为 380.6M，降幅 91.70%，小于全微调可训练参数的 10%；消融：移除位置增强使 score 下降 30.37%，移除文本对齐下降 7.16%；冻结骨干优于全微调（349 vs 144）。

**与你的关联**

**可信度**

**风险或局限**

### P2｜[Token-Level Advertising](https://arxiv.org/abs/2608.27382)

**论文、机构与场景**

arXiv 预印本 2608.27382v1（cs.GT/cross），作者来自中国人民大学、百度与斯坦福大学，研究生成式搜索中 token 级广告机制，实验使用 Webis Generated Native Ads 2024 的 Workout/Vacation/Car 查询拆分。

**核心方法**

提出 LAMA：广告主在每个前缀报告局部续值，诱导广告主特定下一 token 策略，平台按贝叶斯分配后验做潜混合采样生成 token，终止后按后验收割单一赢家并结算支付；LAMA 在 Bellman 一致消息空间下满足 Markov DSIC 与 IR，KL 正则福利与最优的差距不超过 β log|N|，β 趋于 0 时趋向一阶最优；学习实现采用广告主共享预训练骨干（如 Qwen3-14B 参考策略加 LoRA 头），用 Bradley-Terry 权重学习局部优势并由残差锚定根值，在线重构报告，仅需小广告主候选集和少量额外前向开销。

**主要创新或优化点**

将广告机会从预定义 slot 内生化到生成过程：广告主可在 token 级影响生成并参与分配，同时具备激励兼容性、个人理性与近最优 KL 福利保证，为生成式搜索和对话式广告的拍卖与结算提供新范式。

**关键结果**

在三个商业搜索查询垂直域的仿真中，LAMA 取得最高平台福利 0.5205、平台收入 0.8305、广告主价值 0.8568、用户质量 66.5239，全面超过六种启发式基线与 MOSAIC；相对于 allocate-after Policy 基线，LAMA 收入从 0.7501 提升到 0.8305，福利从 0.5080 提升到 0.5205，广告主价值从 0.8253 提升到 0.8568；理论结果：LAMA 同时实现 Markov DSIC 与 IR，福利损失上界为 β log|N|，随 β 趋于 0 趋向一阶最优；仿真采用赢家后验收割，非赢家零支付且期望弱预算平衡。

**与你的关联**

若业务涉及 LLM 生成式搜索、对话式广告或 token 级商业化，可作为竞价机制与平台代报服务（类 auto-bidding）的参考；尚无线上部署验证。

**可信度**

technical_report

**风险或局限**

实验为仿真且 impression value 来自模型预测，非真实线上点击或转化反馈，也未做在线 A/B；仅覆盖单赢家分配，未处理多广告位、曝光约束或多商品同时分配；学习实现依赖完整比较分布与在线实验反馈数据，冷启动或数据不足时恢复性未验证；实验中每垂直域仅三个广告主。

### P1｜[Astar: Learning to Propose Evolution Directions for Self-Evolving Industrial AI Systems](https://arxiv.org/abs/2608.27287)

**论文、机构与场景**

Astar 是阿里巴巴集团与浙江大学合作的 arXiv 技术报告（2608.27287），面向 Lazada 广告平台的在线召回模型做进化方向自动提案。

**核心方法**

方法：从历史 git 提交与训练日志构建进化语料，经配对样本扩展、规则与 LLM 去噪、三层层次化提示，再经 mid-training、SFT、GRPO-RL 训练 Qwen3 基座（0.6B/4B/8B），并训练奖励模型作秒级替代评估；Astar-8B 单提案成功率 S@1=0.6786，超过人类专家 0.3229 与最强通用 LLM GPT-5.5 的 0.3071；奖励模型 AUC 0.8487 也远超人类 0.6142 与最佳通用 LLM 0.5997；在 Lazada 广告平台连续 20 轮迭代，离线 Hitrate@200 提升 23.6%；在线 A/B 中 GMV +4.86%、广告收入 +1.82%、点击 +0.84%、订单 +1.79%。

**主要创新或优化点**

把最依赖资深专家的进化方向提案变成可训练的模型，并与代码代理、训练评估形成全自动闭环；在真实广告召回模型上大幅超过人类专家，是工业 AI 自我进化的重要实证。

**关键结果**

Astar-8B S@1=0.6786，对比人类 0.3229、GPT-5.5 0.3071；20 轮连续迭代离线 Hitrate@200 +23.6%；在线 A/B：GMV +4.86%、广告收入 +1.82%；奖励模型 AUC=0.8487（0.6B 即 0.8094）；已验证方向吞吐提升一个数量级，人工成本从小时级降至分钟级。

**与你的关联**

可迁移到搜广推模型日常迭代：用内部 commit 与实验日志训练改哪里、怎么改的指导模型和奖励模型，能减少方向试错与人工成本；前提是已有结构化实验记录与闭环验证基建。

**可信度**

technical_report

**风险或局限**

仅在 Lazada 广告召回场景部署验证，泛化到排序、内容推荐、基础模型微调等仍属未来工作；效果与在线 A/B 均由作者自报，无外部复现；基线基于内部历史记录，通用 LLM 未接触系统迭代经验；依赖大规模历史 commit、训练日志及规则+LLM 清洗，冷启动和跨系统迁移成本高。


### P1｜[Scaling Graph Neural Networks for Friend Recommendation: Multi-Hash User Embeddings and Temporal Neighbor Sampling](https://arxiv.org/abs/2608.27413)

**论文、机构与场景**

CIKM 2026 接收论文，作者所属 VK AI（莫斯科，俄罗斯）；场景为生产社交网络 VK 的好友推荐（People You May Know）精排阶段，对上游候选集中的用户对打分，独立于内容信息流排序栈。

**核心方法**

设计一 multi-hash ID embedding：k=3 个哈希把用户 ID 映射到 B=2^21×d=256 的 2GB 共享表，替代全量 ID 表（约 202.88GB），表体积降>98%，离线 ROC-AUC 0.6278 不低于全量表 0.6246；设计二时序邻居采样：CSR 邻接表按边时间戳排序，二分查找切出有效历史前缀，单点采样成本由 O(deg+K) 降至 O(log deg+K)；同质量下每 mini-batch 采样 1473ms→595ms，训练开销约降 2.5 倍；系统与部署：194M 用户、28B 边、1.4B 训练交互，单台 8×A100 主机 63h 收敛，全量 1.94 亿用户 embedding 刷新 6.57h；框架开源（github.com/makut/VK-GNN）。

**主要创新或优化点**

少有的带生产 A/B 验证的百亿边图 GNN 排序系统：multi-hash 将高基数用户 ID 表压缩>98% 不掉点，二分查找时序采样降低约 2.5 倍训练采样开销，两个设计对大规模 GNN 精排落地有直接借鉴价值且代码开源。

**关键结果**

离线 per-user ROC-AUC：本方案 0.6278，前生产方案 WalkGNN 0.5572，MF 0.5316，Top-pop 0.5050；线上 A/B（两周，p<0.01）：推荐带来好友添加+16.0%、去重添加用户+11.5%、信息流总时长+0.28%，rank 延迟无回归；工程指标：CSR 图内存约 225GB（CPU 侧），GPU 侧 multi-hash 表 2GB、参数+优化器 6.03GB；全量 embedding 重算 6.57h，单 8-GPU 主机可运维。

**与你的关联**

技术栈相关但场景为社交好友推荐，非内容信息流/电商/广告主链路；multi-hash 高基数 ID 压缩与时序 CSR 采样方法可迁移至大规模用户/物料 embedding 与图特征精排，降本增效路径值得参考。

**可信度**

peer_reviewed_paper

**风险或局限**

仅覆盖好友推荐精排：GNN 分数作为特征供下游 GBDT ranker 使用，非端到端，未联合优化召回/粗排；冷启动受限：快照后新增用户无图边，需周期性重训兜底；embedding 离线定时刷新，两次刷新间存在陈旧性；结果为论文自报的单一平台生产实验（VK，两周 A/B），未披露护栏指标与整体成本收益比，跨平台可迁移性未验证。

## 今日最值得立项的实验

### holdback head 双阈值增量推荐验证

- 假设：在现有多任务模型上增加 holdback head 预测有机流媒体概率，并用双阈值策略，可减少非增量曝光而不损失推荐消费。
- Control：现有生产精排模型直接投放推荐。
- Treatment：在共享躯干上增加 treated/organic 双 head，用随机 holdback 数据以 partitioned loss 训练，线上按 pi=1[p1>=theta1]*1[p0<=theta0] 投放。
- 保持变量：候选集、排序架构、流量分配、训练数据窗口不变。
- 离线指标：treated/organic 概率校准误差；双阈值策略离线留存率；增量 lift 估计
- 线上 Guardrail：推荐内容消费不显著下降；总消费与满意度不下降；线上 p95 延迟增幅 <5%

### multi-hash 高基数 ID 压缩与候选重排验证

- 假设：multi-hash ID embedding 以极小显存占用保持排序质量，时序 CSR 采样可显著降低训练开销，且不损失离线指标。
- Control：全量 ID embedding 表与均匀邻居采样。
- Treatment：k=3 哈希共享表（B=2^21*d）替代全量 ID 表，CSR 邻接表按时间戳排序并用二分查找切片采样。
- 保持变量：图结构、模型架构、训练步数与评估协议不变。
- 离线指标：ROC-AUC；Recall@K；训练吞吐（样本/秒）；embedding 表内存
- 线上 Guardrail：离线指标不下降；训练总时长增幅 <10%；线上推理延迟无回归

### 协同向量记忆注入 LLM 精排实验

- 假设：以协同向量 soft token 注入冻结 LLM，并配合 LoRA 读取与 listwise 训练，可提升精排排序准确率且记忆维护零额外 LLM 调用。
- Control：文本记忆 agent（如 MemRec 风格）或现有多任务精排。
- Treatment：用 LightGCN 预训练冻结状态作记忆库，候选集质心检索 K=5 状态经门控投影映射为 soft token，与 LoRA 一起注入 Qwen2.5-7B，推理用逐点 Yes/No logit 打分。
- 保持变量：候选集大小、LLM 骨干、评估协议与负采样方式不变。
- 离线指标：Hit@1/3/5、NDCG@5/10；每用户决策 token 成本；训练显存开销
- 线上 Guardrail：对比现有精排上线指标不下降；记忆读取额外延迟 <5ms；训练成本不超预算

本期方法趋势明显从单点模型优化转向可复用表示与系统级闭环：既有协同向量记忆注入 LLM 精排、生成式 SID token 初始化的 token 级对齐，也有 VK 的 multi-hash ID 压缩、Spotify 的 holdback 增量推荐与阿里 Astar 的进化方向自动提案。工业在线证据仍多为自报，VK 与 Spotify 是少数带生产 A/B 的可信案例；采纳前需自验与复现。
