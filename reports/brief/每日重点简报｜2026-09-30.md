# AI 与算力重点简报｜2026-09-30

## ① 今日最重要的 3 件事

### 1. [CodeScaler: Scaling Code LLM Training and Test-Time Inference via Reward Models](https://arxiv.org/abs/2602.17684)

改变对代码 RL 反馈来源的判断：奖励模型可同时充当训练奖励与测试时选择器，替代对单元测试执行与沙箱的强依赖，使 RL 训练数据可扩到 44K 问题而无需测试用例。

证据：arXiv 预印本 2602.17684v3，已核验 PDF 正文，含离线基准 Avg@8 与延迟对比；无独立第三方复现、无线上 A/B 或生产部署证据。

### 2. [DISCO: Distributed Long Context Scaling with Grounding-Reasoning Disaggregation](https://arxiv.org/abs/2609.33485)

改变对百万级长上下文实现的判断：把证据抽取与全局推理结构性解耦、由 RL 训练的 Driver 做 DAG 规划，可在 1M token 抑制上下文退化并把评测成本显著压低，而非仅靠扩大上下文窗口。

证据：arXiv 预印本 2609.33485v1，已核验 PDF 正文；结果为 LongBench v2、RULER-QA、∞Bench 离线评测，成本与准确率为作者自报，无线上验证，部分评测用 LLM judge 而非精确匹配。

### 3. [Frontier Learning: Training LLM Reasoners at the Edge of Capability](https://arxiv.org/abs/2609.35426)

改变对 RLVR 数据构造的判断：固定问题池在策略变强后必然梯度塌缩，改为在线程序化生成加 regret 引导的难度前沿跟踪，可在长训练下持续提升而基线约 200 步饱和。

证据：arXiv 预印本 2609.35426v1，已核验 PDF 正文；结果为五类合成任务、3B–7B 模型的离线 greedy accuracy（4 种子），无线上 A/B，方法依赖存在可调参数的程序化生成器。


## ② 最新 LLM 论文 / 技术报告

### [CodeScaler: Scaling Code LLM Training and Test-Time Inference via Reward Models](https://arxiv.org/abs/2602.17684)

**机构、作者与来源**

- **机构：LARK, HKUST(GZ)、Kuaishou Technology、HKUST、UCL、UZH、NUS**
- 作者：Xiao Zhu、Xinyu Zhou、Boyu Zhu、Hanxu Hu、Mingzhe Du、Haotian Zhang、Huiming Wang、Zhijiang Guo
- 来源：arXiv:2602.17684v3
- 场景：代码 LLM 的 RL 训练与测试时推理奖励建模

**核心方法**

- CodeScaler 使用基于策略 RL 轨迹构建的高质量偏好对训练 Bradley-Terry 奖励模型，正样本为通过全部测试的代码，负样本为任一测试失败或错配问题的代码
- 提出语法感知代码抽取（单代码块 + AST 校验，失败置空）与保有效性奖励整形（合法代码用 log(1+e^z) 变换，非法代码奖励为 0）来稳定 RM-based RL

**关键结果**

- 在四个代码基准 Avg@8 上，CodeScaler 比执行式 RLVR 平均提升 1.55 分（Qwen3-8B-Base）和 4.23 分（Qwen3-14B-Base）
- 在 44K 混合数据上训练 Qwen3-8B-Base，CodeScaler 相比 base 模型平均提升 14.64 分，无需测试用例

**为什么值得读**

- 奖励模型同时驱动 RL 训练与 Best-of-N 选择，且扩展到 44K 问题无需测试用例执行
- 并给出约 10× 选择延迟优势

**证据边界**

- 全部结果为离线代码基准评测，无线上 A/B、生产部署或真实工业系统指标
- 偏好数据依赖 DeepCoder 等已验证竞赛题，合成数据扩展仍受测试用例质量与覆盖度限制

### [DISCO: Distributed Long Context Scaling with Grounding-Reasoning Disaggregation](https://arxiv.org/abs/2609.33485)

**机构、作者与来源**

- **机构：新加坡国立大学（National University of Singapore）与 Adobe Research**
- 作者：Guanzheng Chen、Viet Dac Lai、Subhojyoti Mukherjee、Branislav Kveton、Seunghyun Yoon、Franck Dernoncourt、Qizhe Xie、Trung Bui
- 来源：arXiv:2609.33485v1
- 场景：百万 token 级长上下文多跳问答推理，非推荐/广告检索排序任务

**核心方法**

- 方法核心是 Grounding-Reasoning Disaggregation：将长上下文切成 K 个分片分给轻量 Worker LLM 并行做局部证据抽取，Driver LLM 不接触原始上下文，只对聚合证据做全局推理
- Driver 用 DAG 做在线规划，把查询拆成 Narrow(Map 原子实体抽取) 与 Wide(Reduce 逻辑综合) 两类动作，迭代重规划直到证据充分

**关键结果**

- Qwen3-8B 下 DISCO 在 RULER-QA 1M token 保持 78.4% 准确率，标准 RAG 基线崩溃到 10.9%
- Qwen3-14B 在 LongBench v2 Long 子集达 48.7%，比 Full Long Context 基线 38.9% 高 9.8 点，GRPO 后提升至 50.9%

**为什么值得读**

- Worker-Driver 分层、DAG 在线规划与 GRPO 训练 Driver 的组合，是把长上下文拆为并行抽取加全局推理的可复用系统范式，适合关注长上下文 Agent 与推理成本结构的团队精读

**证据边界**

- 全部结论来自 LongBench v2、RULER-QA、∞Bench 离线 benchmark，无线上 A/B 或生产部署验证
- 事实丢弃比例 p≥0.3 时规划阶段由约 4 激增至约 7、准确率降至 33%，受 Tmax=10 预算限制，对 Worker 抽取失败较脆弱

### [Frontier Learning: Training LLM Reasoners at the Edge of Capability](https://arxiv.org/abs/2609.35426)

**机构、作者与来源**

- **机构：University of Basel、University College London**
- 作者：Robin Faro、Shyam Sundhar Ramesh、Ilija Bogunovic、Aurelien Lucchi
- 来源：arXiv:2609.35426v1（Preprint）
- 场景：LLM 推理任务（Countdown、Sokoban、Dice、Decimal Arithmetic、Largest Island）的 RLVR/GRPO 后训练课程，非搜广推任务

**核心方法**

- 把程序化生成器的 task-specific 属性组合定义为 level，构成多维难度空间，不假设难度单调或已知排序
- 训练问题在线生成，而非从训练前固定的问题池采样

**关键结果**

- 200 步预算下：Countdown 50.9±0.5%（最强基线 44.7±1.7%），Sokoban 45.2±1.9%（PLR 41.1±3.9%），Decimal Arithmetic 34.7±3.6%（Domain Rand. 31.0±2.8%）
- DICE 500 步：71.8±6.2%，对比 SEC 33.3±1.2%、ACE-GRPO 33.2±2.1%、DAPO 25.4±5.9%，相对增益 +115.6%

**为什么值得读**

- 把后训练问题从选样推进到持续生成难度前沿样本，level-regret 优先级加状态依赖 mutation 机制无需 teacher 模型即可跨任务族迁移，对自演化训练数据与难例课程调度有参考价值

**证据边界**

- 方法依赖任务存在带可调参数的程序化生成器，无法程序化生成的问题实例不适用
- 实验仅覆盖谜题、数学、图推理五类合成任务与 3B–7B 模型
