# AI 与算力重点简报｜2026-11-05

## ① 今日最重要的 3 件事

### 1. [Aligning Training and Rollout Policies for End-to-End FP4 RL on Mixture-of-Experts LLMs](https://arxiv.org/abs/2611.04376)

把 MoE FP4 RL 的失效原因定位到路由器离散 top-k 选择对量化扰动的敏感，双侧对称残差校正可将训练-推理路由一致性恢复到近 BF16，改变了对低精度 RL 是否可行的判断。

证据：NeurIPS 2026 Workshop 论文，已核验 PDF 正文；单模型 Qwen3-30B-A3B、单数据集与数学基准，模拟量化，无真实 FP4 硬件吞吐或线上 A/B。

### 2. [Requests of a Feather Must Flock Together: Batch Size vs. Prefix Homogeneity in LLM Inference](https://arxiv.org/abs/2605.06046)

指出 decode 阶段前缀同质性独立于 batch size 影响 KV 局部性，并在调度层以 O(log W) 拿到显著吞吐提升，改变了共享系统提示与长上下文推理服务的批调度判断。

证据：SIGOPS ATC 2026 论文，已核验 PDF 正文，含 vLLM/SGLang 集成实验；单机 RTX 6000 Ada 与 A100-80GB，Poisson 合成负载，无生产 trace 或多 GPU 验证。


## ② 最新 LLM 论文 / 技术报告

### [Aligning Training and Rollout Policies for End-to-End FP4 RL on Mixture-of-Experts LLMs](https://arxiv.org/abs/2611.04376)

**机构、作者与来源**

- **机构：Huawei**
- 作者：Hei Yi Mak、Hoang Le、Mehran Taghian Jazi、Yunke Peng、Huan Lin、Zhengzhi Tang、Zhexu Liu、Yao Wang、Yaoyuan Wang、Anandharaju Durai Raju、Tanzila Rahman
- 来源：arXiv:2611.04376v2，NeurIPS 2026 Workshop
- 场景：MoE LLM 的端到端 FP4 强化学习后训练

**核心方法**

- 诊断设计：在 Qwen3-30B-A3B 上用 GRPO、vLLM rollout 与 FSDP 训练，比较 BF16、HiF4 及残差校正（RC）在推理侧、训练侧和双侧的 PCC、top-k 专家集合完全匹配率与平均重叠率，以定位 MoE 路由导致的训练-推理失配
- MoEResQ：rollout 与训练前向均对激活施加同一残差校正，反向传播再对输出梯度和输入激活的量化残差做校正，使训练侧和推理侧在相同层上保持对称，减少路由选择分歧

**关键结果**

- 在 Qwen3-30B-A3B、DAPO-Math-17K、GRPO 设置下，MoEResQ 在 AMC23/AIME24/AIME25/MATH500 上达 84.45/44.48/29.69/85.42，相对 BF16 的 85.10/48.23/34.38/86.71 差距缩至 0.65/3.75/4.69/1.29 个百分点
- 仅量化专家投影时，MoEResQ 在上述四项基准上分别为 84.61/46.98/32.92/86.17，相对 BF16 差距 0.49/1.25/1.46/0.54 个百分点，四项均在 1.5 个百分点内

**为什么值得读**

- 为 MoE 低精度 RL 后训练给出可复用的失配诊断（路由 PCC、top-k 匹配率）与对称校正配方
- 并指出仅量化专家投影即可覆盖多数参数，是判断 FP4 RL 能否落地时必须读的材料

**证据边界**

- 所有实验为模拟量化，未在真实 FP4 硬件上报告吞吐、延迟或显存节省
- 仅验证 Qwen3-30B-A3B、DAPO-Math-17K、GRPO 和数学推理基准，未覆盖其他 MoE 模型、任务或 RL 算法

### [Requests of a Feather Must Flock Together: Batch Size vs. Prefix Homogeneity in LLM Inference](https://arxiv.org/abs/2605.06046)

**机构、作者与来源**

- **机构：Indian Institute of Technology Bombay（IIT Bombay，作者邮箱 @cse.iitb.ac.in 佐证）**
- 作者：Saksham Rathi、Preeti、Mythili Vutukuru
- 来源：arXiv:2605.06046v4 / SIGOPS ATC 2026
- 场景：LLM 推理 decode 阶段的批调度与 KV cache 前缀共享

**核心方法**

- CHT 将请求按固定大小 chunk 切分并计算累积前缀哈希向量，维护活动 batch 的 (level, hash) 工作集与按 missing count 排序的 min-heap，选择与当前 batch 重叠最大的等待请求，选择复杂度 O(log W)
- RL 将 batch 构建建模为序列决策：状态含当前 batch 大小、加入候选后的共享前缀损失 Δ、新深度上的等待请求数 w

**关键结果**

- 受控实验：800 个请求、8 组各 100 个共享 10K token 前缀，8×100 同质 batch 的吞吐约为更大异质 batch 的 2×
- 32×25 过小 batch 因计算利用率不足反而变差

**为什么值得读**

- 把前缀同质性作为独立于 batch size 的调度维度，且可在不改 attention kernel 的前提下接入主流推理框架，对在线推理成本优化的技术判断有直接价值

**证据边界**

- 实验限于单卡 RTX 6000 Ada 与 A100-80GB，未验证分布式或多 GPU 部署
- 作者将多 GPU 扩展列为未来工作

### [Adversarial Speculative Reasoning Improves Long Horizon Agents](https://arxiv.org/abs/2611.05345)

**机构、作者与来源**

- **机构：Subconscious Systems Technologies、MIT、Princeton University、Northeastern University**
- 作者：Hongyin Luo, Wei Fang, Lijie Yang, Owen Stepan, Daniel Suit, Jeff Krapf, Dana Wensberg, Jack O'Brien
- 来源：arXiv:2611.05345v1
- 场景：长时程软件工程智能体任务（DeepSWE、NL2Repo-Bench）

**核心方法**

- 作者在同一前缀上重复执行验证 forward，发现验证块内数值噪声随 slot 近似每槽增长 4%，末槽比首槽高 34%（GLM-5.3, 8-token DFlash），并测量了长程 KV 写入后的极端偏差
- 方法用目标模型作为 judge 定位 committing sentence，构造 fork pairs，仅对 draft 做反向 DPO，使其在关键决策点偏向应被拒绝的 framing（likely/risk/simpler 或不做测试）

**关键结果**

- 在 DeepSWE 113 个任务上，GLM-5.3-nvfp4 使用对抗 draft 后 pass rate 由 60.6% 升至 67.6%（+7.0 点，95% CI 2.6-11.4，5 次独立运行）
- 在 DeepSWE 上，DeepSeek-V4.1-Flash 由 67.8% 升至 71.8%（+4.0 点，95% CI -1.3-7.3，5 次运行

**为什么值得读**

- 把投机解码从纯加速手段重定义为上下文精度分配器，仅训练极少参数即可提升长时程编码成功率，值得评估
- 但一条主结果置信区间跨零，增益稳健性需要独立验证

**证据边界**

- DeepSWE 上 DeepSeek-V4.1-Flash 的 +4.0 点 95% CI 为 -1.3 到 7.3，统计上未显著
- NL2Repo-Bench 增益也仅 1.4 点
