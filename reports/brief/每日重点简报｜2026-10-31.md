证据：arXiv 原始论文，PDF 已核验，Apple 署名；评测为作者自建基准与 AndroidWorld 跨分布测试，依赖云设备快照与 Gemini judge，独立复现缺失，且在跨分布基准上仍显著落后前沿模型。


## ② 最新 LLM 论文 / 技术报告

### [GAAC: Lossless KV Compression for Bandwidth-Efficient LLM Inference on Personal Devices](https://arxiv.org/abs/2610.38210)

**机构、作者与来源**

- **机构：University of Notre Dame（首页明确标注，作者邮箱后缀 @nd.edu 佐证）**
- 作者：Yipin Guo、Arun M George、Siddharth Joshi
- 来源：arXiv 2610.38210v1
- 场景：在个人设备（NVIDIA DGX Spark、Apple M4）上，对长上下文 LLM 推理的 KV cache 做无损压缩，并加速解码 attention 与端到端服务

**核心方法**

- 把 BF16 的 KV 拆成不变的符号位和尾数位（共 1 字节）以及单独压缩的 8-bit 指数
- 对每个 head–channel 组合离线校准长度 8 和 16 的连续高频指数窗口作为 base，编码时存储偏移量（base-plus-offset），解码时用整数加法还原指数，不使用码本查表

**关键结果**

- 在 Qwen3-4B/8B/27B、Qwen3.6-35B-A3B、Llama-3.1-8B 五个模型上，BF16 KV 无损压缩比为 1.405–1.407×，88.3–89.9% 的 8 元素组使用 3-bit 模式，raw 回退 ≤0.3%
- 计入固定容量 slot 开销后，常驻 KV 内存约下降 26%（如 Qwen3-8B 128K 从 19.3 GB 降到 14.2 GB）

**为什么值得读**

- 值得读其 BF16 符号尾数与 8-bit 指数分离、base-plus-offset 编码与 3-bit/4-bit/raw 分组切换的格式设计，以及 fill-then-finalize 块编码接入 paged KV 的路径
- 为长上下文推理的 KV 带宽优化提供可复现工程样本

**证据边界**

- FP8 缓存上的额外压缩收益明显变小（E4M3 仅 1.09–1.14×），方法依赖 BF16 指数低熵这一前提
- K 经 RoPE 旋转后会出现位置漂移：用 ≤8K 提示校准后，运行 32K 时 K 的每 block 均值溢出字节从 37–38 升到 190（28–32K 段），压缩率下降（虽然仍无损）

### [Online Dense Reinforcement Learning with Planning-Grounding Agent for UI Navigation on Live IOS Apps](https://arxiv.org/abs/2610.39264)

**机构、作者与来源**

- **机构：Apple（作者署名区为 Apple，作者邮箱 @apple.com）**
- 作者：Peitong Duan、Khashayar Gatmiry、Jeffrey Nichols、Samy Bengio、Emmanuel Abbe
- 来源：arXiv 2610.39264v1
- 场景：面向实时 iOS 应用的 UI 导航智能体在线强化学习

**核心方法**

- Planning Agent 输入任务指令、当前截图、历史计划与上一步剩余计划，输出含 CoT 的当前步计划及剩余计划
- Grounding Model 再把当前步计划映射为动作原语与屏幕 x,y 坐标，规划与定位解耦

**关键结果**

- UINavBench 上 PPO Step336 成功率 32.4%，SFT 基线 16.7%，与 Gemini-3.1-Pro 的 32.4% 持平，高于 Gemini-3.5-Flash 的 28.4%
- GiGPPO Step168 为 30.4%

**为什么值得读**

- 值得读其 Planner 与冻结 SFT Grounding 解耦、step-level GAE 与非对称折扣处理稠密奖励、以及用感知哈希在并行轨迹中找近邻状态估计 V(s) 的 GiGPPO 设计
- 可迁移到任何有可并行交互环境的 Agent RL

**证据边界**

- iOSWorld 上最佳 GiGPPO Step336 仅 9.8%，标准 PPO Step336 低至 2.3%，论文归因于合成应用布局和个性化/多应用任务偏离训练分布，跨分布泛化仍有限
- 与 Gemini 等 frontier 模型的比较是在作者解耦架构和相同 grounding 配置下作为 planner 评测，非其原生端到端产品能力

### [H$^2$R: Hierarchical Hint-Based Reward for Mathematical Reasoning via Reinforcement Learning](https://arxiv.org/abs/2610.39934)

**机构、作者与来源**

- **机构：New York University Shanghai（PDF 首页明确列出，作者邮箱 @nyu.edu 佐证）**
- 作者：He Tu、Siye Li、Hongyi Wen
- 来源：arXiv:2610.39934v1
- 场景：数学推理 RLVR 训练与 HiMath 分层基准评测

**核心方法**

- 训练提示同时给出问题与子问题 hint，策略输出 Q3 解答
- 奖励由答案正确性 c_i 与 LLM judge 过程分 p_i∈[1,5] 组成，c_i=1 时 s_i=α+(1−α)min(1,p_i/τ)，否则为 0，取 α=0.6、τ=4

**关键结果**

- HiMath 上 Qwen2.5-Math-7B avg@3：No-Hint 30.43%，Hier.-Hint 39.13%（+8.70pp），Oracle Hier.-Hint 45.65%（+15.22pp）
- 测试时均不提供 hint

**为什么值得读**

- 值得读其把题目子问题结构转成训练期分层 hint、测试期移除 hint 的监督注入方式，以及答案正确性硬门控加 LLM judge 过程分的混合奖励
- 为稀疏结果奖励下的信用分配提供低成本替代路线

**证据边界**

- HiMath 仅 151 题（105 训练、46 测试），作者明确不据此主张广泛推理能力，跨数学外任务未验证
- 正确性与过程分依赖 o3-mini LLM judge，仅做 25 条人工审计
