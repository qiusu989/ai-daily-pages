## ② 最新 LLM 论文 / 技术报告

### [Navalia: Advancing Cowork Agents through Verifiable Task Synthesis and Long-Horizon Post-Training](https://arxiv.org/abs/2610.26887)

**机构、作者与来源**

- **机构：AllSpark Team**
- 作者：Hengqi Liu、Ziyuan Liu、Yang Qin、Wanting Zhou、Zichuan Wang、Jiachen Liang、Xu Chu、Shaowei Chen、Zhaokai Luo、Mu Chuan
- 来源：arXiv:2610.26887v1
- 场景：基于公司财务报告的长程 Cowork Agent 任务合成与后训练，覆盖财务文档检索、证据整合、多步数值推理和工具使用

**核心方法**

- 双视图与算子驱动任务合成：将财报解析为 Markdown 文档视图作为交互环境，并抽取含数值、单位、来源位置、报告期、指标定义和口径的结构化事实视图汇总为全局事实库
- 采样分析算子/复合模板、任务锚点和参数，检查文档覆盖并加入同期/同业干扰文档

**关键结果**

- 五个基准得分为 OfficeQA Pro 62.66、FinSearchComp 55.80、Finance Agent 57.10、APEX-Agents-AA 25.44、Workspace-Bench-Lite 59.27，较 Qwen3.6-35B-A3B 基线分别提升 23.06、14.10、13.91、13.20、13.07 个百分点
- OfficeQA Pro 上，训练后全部支持文档检索比例从 45.4% 升至 69.8%，支持文档召回从 50.8% 升至 74.7%，平均工具轮次从 39.3 升至 47.8、工具调用从 41.5 升至 55.2

**为什么值得读**

- 把可验证性做进任务合成与奖励链路
- 并用 FIFO 上下文分段把每轨迹训练样本压缩约 90%，是长程 Agent 后训练工程化的重要参考，值得对照自身 Agent 数据合成与 RL 基础设施

**证据边界**

- 作者自述仅用固定窗口 FIFO 管理上下文，未引入轨迹压缩、长期记忆或多智能体协作
- 基于最终任务奖励的优势共享不区分各阶段动作贡献

### [Youtu-LLM-2B](https://huggingface.co/tencent/Youtu-LLM-2B)

**机构、作者与来源**

- **机构：腾讯**
- 作者：未单列
- 来源：arXiv:2512.24618 技术报告（Hugging Face 模型卡）
- 场景：通用文本生成、长上下文与 Agent 任务评测

**核心方法**

- 采用稠密 MLA 的自回归因果语言模型，1.96B 参数、32 层，Q/K/V 各 16 个注意力头，Q 的 MLA rank 为 1536、K/V 为 512，上下文长度 131,072
- 发布 Base 与 Instruct 两个版本，Instruct 支持 Reasoning Mode，通过思维链生成回答

**关键结果**

- 模型卡报告 Youtu-LLM-2B 在 DROP 86.7%、HumanEval 95.9%、MATH-500 93.7%，高于表中 Qwen3-1.7B 的 72.5%、84.8%、89.8%
- Agent 基准：GAIA 33.9%、SWE-Bench-Verified 17.7%、τ²-Bench 15.0%、BFCL V3 58.0%，其中 BFCL V3 低于 Qwen3-4B 的 61.7%

**为什么值得读**

- 1.96B 稠密 MLA 加 128k 上下文与原生 Agent 定位，提供小尺寸长上下文 Agent 的部署选项
- 但仅模型卡级证据，值得读以判断低成本 Agent 组件的可行性边界

**证据边界**

- 当前候选仅提供模型卡摘要，未披露训练数据配比、训练目标、对齐流程与完整训练细节，无法核验原生 Agent 能力的形成机制
- 基准结果为厂商自测对比表，当前摘要未给出评测提示、解码参数与重复运行方差，缺少独立复现
