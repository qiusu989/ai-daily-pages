# AI 与算力重点简报｜2026-11-07

## ① 今日最重要的 3 件事

### 1. [FlashOffloading: Low-Latency KV Cache Offloading for Long-Context LLM Serving](https://arxiv.org/abs/2611.07542)

把长上下文服务的瓶颈从「HBM 容量墙」改写为「KV 分层＋索引化加载与计算重叠」的工程问题：预填充四缓冲轮转与解码 cache_slots 反查＋LIM/CopySFA 融合，使批容量与序列长度在同等 HBM 下大幅扩展，改变对卸载代价过高的判断。

证据：arXiv 技术报告，已核验 PDF 正文；结果为 32 卡 Ascend910C 受控集群与 burst 负载，无线上生产 A/B，仅 GLM-5.2 与昇腾平台，P+D 会抬高 TPOT，属系统级但非生产验证。

### 2. [Vector Policy Optimization: Training for Diversity Improves Test-Time Search](https://arxiv.org/abs/2605.22817)

把 RL 后训练的目标从标量奖励改为向量奖励上的集合级期望最优，正面处理 GRPO 的模式坍缩；best@k 随搜索预算扩大而增益扩大，改变“多样性只能靠采样温度或多次采样”的做法判断。

证据：NeurIPS 2026 同行评审论文，已核验 PDF 正文；MuSiQue/LiveCodeBench 上 best@k 优于 GRPO，但计算对齐不严格、pass@1 低于 GRPO，方法依赖向量奖励，属离线基准证据。

### 3. [SKIM: Pruning Large Language Model Agents via Selective Knowledge Informed Masking](https://arxiv.org/abs/2611.07558)

指出标准剪枝/蒸馏与结构化生成部署的错配：语法约束下 format 位置由 formatter 保证，容量应集中在 decision 位置；50% 稀疏度下结构化准确率明显超过 Wanda/FLAP/SlimGPT，改变 Agent 专用小模型压缩可行性的判断。

证据：NeurIPS 2026 同行评审论文，已核验 PDF 正文并核实作者机构；评测仅 Qwen3.5 与 Hammer2.1 离线基准，无线上 A/B，纯 SKIM 模型在无约束自由生成下准确率近零。


## ② 最新 LLM 论文 / 技术报告

### [FlashOffloading: Low-Latency KV Cache Offloading for Long-Context LLM Serving](https://arxiv.org/abs/2611.07542)

**机构、作者与来源**

- **机构：华为技术有限公司、Huawei Ascend Computing Technology Development、上海交通大学**
- 作者：Xuan Wang、Zhuanhao Wu、Tingzhu Fang 等
- 来源：arXiv:2611.07542v1
- 场景：长上下文 LLM 在线服务的 KV cache 分层卸载

**核心方法**

- 预填充阶段把完整 KV 历史放在主机 DRAM，设备只保留 4 个全层缓冲：B0 常驻首层，B1–B3 按层轮转，通过异步 H2D/D2H 和独立流重叠块粒度加载、当前层计算与写回
- 解码阶段 HBM 只保留热缓存 Cb，主机 DRAM 保存完整 KV

**关键结果**

- 在 32 卡/64 die Ascend910C、1P1D、GLM-5.2-w4a8c16+MTP3 上，P+D 相较 P-only 在 64k/128k/256k 输入、8192 输出时输出 TPS 分别提升 67.8%/91.5%/40.5%，TPOT 分别升至 30.2/26.0/22.9 ms（约 30 ms 约束附近）
- 预填充卸载把 P 节点 KV 预分配从 36.75 GB 降至 9.04 GB，最大可服务序列约从 368k 提升到 1.6M，max-num-batched-tokens 从 16384 到 131072

**为什么值得读**

- 长上下文推理成本的核心约束是可服务并发而非单卡算力
- 该文给出可复用的缓存索引、槽位驱逐与核内加载重叠设计

**证据边界**

- 端到端结果来自 32 卡/64 die Ascend910C 受控集群与 burst 负载，没有线上生产 A/B，统计显著性与真实流量分布未验证
- 只评测 GLM-5.2-w4a8c16+MTP3 与昇腾平台，向 GPU、其他模型或注意力实现迁移需重新验证

### [Vector Policy Optimization: Training for Diversity Improves Test-Time Search](https://arxiv.org/abs/2605.22817)

**机构、作者与来源**

- **机构：MIT、Improbable AI Lab、MIT-IBM Computing Research Lab、Sakana AI**
- 作者：Ryan Bahlous-Boldi、Isha Puri、Idan Shenfeld、Akarsh Kumar、Mehul Damani、Sebastian Risi、Omar Khattab、Zhang-Wei Hong、Pulkit Agrawal
- 来源：arXiv:2605.22817v2（NeurIPS 2026）
- 场景：LLM 强化学习后训练，面向代码生成、多跳问答、逻辑推理和工具调用等测试时搜索任务

**核心方法**

- VPO 在一个自回归 rollout 内依次生成 m=3 个候选答案，用分隔符隔开，后续答案可条件于前文已生成答案，以提供上下文内探索容量
- 以向量奖励 r(x,y) 为基础，从 Dirichlet(1) 采样标量化权重 w，集合奖励定义为 R(S)=E_w[max_{y∈S} w^T r(x,y)]，奖励集合覆盖不同奖励权衡的候选

**关键结果**

- 在 MuSiQue 300 题留出集上，VPO best@30=0.832，高于 scalar GRPO 0.728 和 Multi-RLVR 0.633
- F1@30=0.678 对 0.447

**为什么值得读**

- 对依赖 best-of-N、verifier 或进化搜索的系统，它说明候选同质化是训练目标问题而非采样参数问题
- 集合级向量奖励目标与 m 答案链设计可直接迁移到代码、多跳问答与工具调用路径

**证据边界**

- 训练计算难以完全对齐：VPO 每个 rollout 生成 m=3 个答案，作者用 3 倍 rollout 的 GRPO/GDPO 对照，但仍不是严格的 FLOPs 或墙钟时间对齐
- 方法依赖向量奖励

### [SKIM: Pruning Large Language Model Agents via Selective Knowledge Informed Masking](https://arxiv.org/abs/2611.07558)

**机构、作者与来源**

- **机构：KAIST、University of Wisconsin–Madison**
- 作者：Moonseok Choi、Jongwon Jeong、Minki Kang、Giung Nam、Juho Lee
- 来源：arXiv:2611.07558v1（NeurIPS 2026）
- 场景：工具调用 Agent 在结构化生成下的剪枝与蒸馏，评测 BFCL-v3、API-Bank L1 与 HotpotQA

**核心方法**

- 方法按解码时合法 token 集合划分位置：|V_t|>1 的输出位置为 decision，|V_t|=1 为 format
- context 仅取工具签名、参数描述、用户查询等工具相关输入，其余输入不计入三类

**关键结果**

- Qwen3.5-2B 在 BFCL-v3、25% 稀疏度下结构化准确率为 80.8，高于 FLAP 75.9、SlimGPT 73.6 和 Wanda-sp 63.5（同等蒸馏预算）
- Hammer2.1-3B 在 BFCL-v3、50% 稀疏度下结构化准确率为 82.8，高于 FLAP 73.0、Wanda-sp 72.2 和 SlimGPT 46.4

**为什么值得读**

- 把 token 位置角色引入剪枝显著性与约束分布蒸馏，为结构化输出 Agent 模型的小型化提供可操作配方与吞吐数据，是评估 grammar 约束场景专用小模型部署代价时应读的材料

**证据边界**

- 蒸馏语料为单轮 function-calling 轨迹
- 多步 Agent 能力只能间接恢复，HotpotQA 需额外 128 条任务轨迹将 F1 从 20.2 提到 59.7，仍略低于微调稠密模型 60.2
