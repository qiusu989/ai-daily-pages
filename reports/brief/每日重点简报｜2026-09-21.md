### P1｜[Alibaba Open Sources OpenCodeReview for AI-Assisted Code Review](https://www.infoq.com/news/2026/09/alibaba-opencodereview/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering-news)

**判断影响**

展示确定性流水线+LLM agent 的工程化 harness 设计：用确定性约束文件选取、工具调用与评论定位，换取精度与 token 效率，而非追求模型本身更强。

**关键变化**

来源：InfoQ 新闻（2026-09-20）；作者：Renato Losio；机构：阿里巴巴（项目方）；场景：AI 辅助代码审查 CLI；OpenCodeReview 以 Apache-2.0 开源，Go 语言 CLI，将文件选择、打包、规则匹配与评论定位交给确定性流水线，LLM agent 只做动态代码分析；内置检查覆盖空指针异常、线程安全、XSS、SQL 注入等问题，可审查 Git diff、分支或整文件；支持 OpenAI 与 Anthropic 兼容模型，可本地运行或集成 GitHub、GitLab、Ge…

**数据与证据**

阿里称内部 200 个 PR、10 种语言的 benchmark 上精度与 F1 高于 Claude Code，token 消耗约为其九分之一；独立评测方称目前唯一独立 benchmark 在 10 个 Martian-benchmark PR 上精度约 12%，维护者称是 tool-call 异常并已修复，但缺少修复后的独立验证；AACR-Bench 最佳配置召回率 20%，即专家识别问题中 80% 未被发现；媒体或社区报道。厂商自报 benchmark 结果缺乏独立复现，token 与 F1 优势均为阿里内部数据；唯一独立评测精度约 12% 且修复后无独立验证，结果可信度低；召回率被有意压低（最佳 20%），跨文件与架构级问题发现能力受限
