# AI 与算力重点简报｜2026-11-17

## ① 今日最重要的 3 件事

### 1. [HARDTESTGEN: A High-Quality RL Verifier Generation Pipeline for LLM Algorithmic Coding](https://arxiv.org/abs/2505.24098)

把代码 RL 瓶颈从策略侧转到奖励侧：现有 TACO/CodeContests 在难题上精度仅约 18–52%，假阳性奖励污染训练；本文用程序化造例加多 oracle 共识把难题精度提到约 56–79%，并在同题集 GRPO 上把 pass@1 从 38.48 提到 39.42。验证器质量应作为训练系统的一等变量纳入评估。

证据：arXiv 预印本，输入标注已核验 PDF 正文；作者自测，数据集含人工 oracle，下游仅 Qwen3-4B 与 LiveCodeBench-105 子集，无第三方复现；拒绝采样实验 pass@1 未超基线。

### 2. [Fuse-All MoE Inference Kernel with Load Balancing on TPUs](https://arxiv.org/abs/2611.17857)

把 MoE 推理效率问题定位为核内中间数据物化与专家负载倾斜，融合单次专家启动加负载均衡使偏斜 EP16 prefill 内核时间从 2.3 倍降至 1.09 倍；说明 MoE serving 优化需联合计算融合与放置调度，而非只调 batch 或并行切分。

证据：arXiv 预印本，Meta SuperIntelligence Lab 作者自测，PDF 已核验；端到端 12%–34.5% 吞吐提升包含服务栈改动，未隔离内核贡献；仅在特定 TPUv7 切片与路由分布下测得。


## ② 最新 LLM 论文 / 技术报告

### [HARDTESTGEN: A High-Quality RL Verifier Generation Pipeline for LLM Algorithmic Coding](https://arxiv.org/abs/2505.24098)

**机构、作者与来源**

- **机构：卡内基梅隆大学、UC Santa Barbara、UT Austin、Meracode**
- 作者：Zhongmou He、Yee Man Choi、Kexun Zhang、Jiabao Ji、Junting Zhou、Dejia Xu、Ivan Bercovich、Aidan Zhang、Yixiao Zeng、Lei Li
- 来源：arXiv:2505.24098v2
- 场景：为算法竞赛编程题合成测试用例，用作代码生成的 RL 验证器与拒绝采样过滤器，并不属于搜索、推荐或广告链路

**核心方法**

- 四类测试输入生成：LLMGen 直接让 LLM 仿照样例生成约 10 条小规模输入
- RPGen 让 LLM 写无参 Python 生成函数，按数据类型与范围随机产输入并执行 20 次

**关键结果**

- 在 1253 题（Codeforces 600 + AtCoder 653）综合评测集上，用 Qwen2.5-Coder-7B 生成程序测试：HardTests 平均精度 79.21%、召回 91.69%，TACO 为 61%/78.97%，CodeContests 为 51.64%/85.98%
- 难度 4+ 子集 HardTests 精度 55.88%，TACO 仅 17.83%

**为什么值得读**

- 值得读在于它给出可复用的可执行验证器构造路径：四类输入生成、LLM 生成约束校验函数、多人工 oracle 共识过滤
- 并量化测试精度与下游 RL/拒绝采样收益的耦合，为任何依赖可执行验证的 Agent 与 Coding 训练提供设计模板

**证据边界**

- 方法假设每题存在人工 oracle 程序（数据集中 68% 题目有），无 oracle 情形仅在附录给出初步设想，未形成可验证方案
- 全部生成使用 GPT-4o，平均每题测试用例生成成本约 0.23 美元

### [Fuse-All MoE Inference Kernel with Load Balancing on TPUs](https://arxiv.org/abs/2611.17857)

**机构、作者与来源**

- **机构：Meta SuperIntelligence Lab**
- 作者：Rupeng Liu、Bangsheng Tang、Zongwei Zhou、Chengji Yao、Yejin Lee
- 来源：arXiv:2611.17857v1
- 场景：TPU 上 MoE 大模型推理的 prefill-decode 分离服务优化

**核心方法**

- 核心内核将 token 收集、gate/up 投影、门控激活、down 投影和按 token-slot 的直接写回融合为单次专家启动，中间结果留在 VMEM，路由与上游交换仍在核外
- 负载均衡包含行桶调度、热专家交错、芯片内 chipmate 专家迁移、输出目标交错及静态放置/预载热专家副本

**关键结果**

- 实测偏斜 EP16 prefill 工作负载，负载均衡将内核运行时间从平衡参考的 2.3 倍降至 1.09 倍，两个比值使用同一固定平衡工作量内核时间
- 在 32 至 512 个 decode token 上，对称 EP8TP2 相比 fused EP16 内核操作延迟最高降低 21.3%

**为什么值得读**

- 值得读在于它同时处理融合、写回、专家倾斜三件事
- 并区分 prefill 与 decode 的不同最优切分（EP16 与对称 EP8TP2），对 MoE 推理栈的 kernel 级与放置级联合设计有直接参考价值

**证据边界**

- 结果来自单篇 arXiv 预印本且为作者自测，非同行评审或独立复现，提升幅度依赖特定 TPU 切片、模型宽度、精度配置和路由分布
- 端到端 12% 至 34.5% 吞吐提升包含 serving-stack 优化，论文未给出受控后端替换来隔离内核贡献

### [Alignment with Reflect-Reasoning: Learning How To Follow Principles](https://arxiv.org/abs/2611.17398)

**机构、作者与来源**

- **机构：Duke University、Independent Researcher（USA，据首页 affiliation）**
- 作者：Henry Bell、Caroline Zhang、Dhaval Potdar、Mohammed Mobasserul Haque、Brandon Fain
- 来源：arXiv:2611.17398v1
- 场景：LLM 宪法对齐后训练与推理时原则注入，非搜广推任务

**核心方法**

- 阶段1 SFT：用 gpt-4.1 执行改进版 Reflect-ICL 生成带标签反思轨迹，训练提示随机配对从 125 条人类启发原则中采样的宪法（每条含 8–15 条原则），并把 KEEP 下采样到 1/3，使 REVISE 占 2/3，让模型学到推理流程而非固定原则
- 推理格式为单次生成内三段：先输出 base_response，再在 rating/critique 中逐原则评估并给出 KEEP 或 REVISE 决策，最后给 revised_response，形成可审计的自然语言推理轨迹

**关键结果**

- held-out 原则上对宪法系统提示（Base-ICL）胜率 82.5–94.7%，对显式 in-context Reflect（Reflect-ICL）66.8–86.9%，五个模型 95% 置信区间均不跨 50%（Claude Opus 4.8 作 judge）
- 分布外域仍为正胜率：金融对 Base 51.5–82.4%、对 RIC 57.2–80.2%

**为什么值得读**

- 值得读在于把对齐目标从遵循哪些原则改为如何推理原则，使推理时注入新宪法无需再训练
- 两阶段 SFT 加 LLM-judge 成对奖励（含与冻结 base 对比防退化）是可比照的后训练配方

**证据边界**

- 核心指标依赖 LLM judge 且无 ground truth：人类验证仅覆盖 Tulu-3-8B-SFT、n=158（人类多数 85.1% vs judge 91.3%），金融域人类-人类一致性仅 52.2%，存在边际 judge 偏好
- 法律域因 judge 无法验证被排除主文：12 原则子集与 53 原则全集结果差异大（Qwen 15.8% vs 48.7%），说明长宪法条件下评测不稳定
