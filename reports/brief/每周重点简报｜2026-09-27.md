# AI 与算力重点周报｜2026-09-27

## ① 本周最重要的 3 件事

### 1. [Towards Full Pipeline FP8 Reinforcement Learning for LLMs](https://arxiv.org/abs/2609.22870)

首次系统解释全流水线 FP8 RL 训练中期熵激增与输出崩坏的机制（重要性比值噪声放大导致负优势 token 被过度裁剪），并给出低开销边界校准修复，改变「FP8 只适合前向/rollout、RL 全流程必须 BF16」的判断，为 RL 后训练吞吐与稳定性提供可复用路径。

证据：arXiv 预印本，PDF 正文已核验，含 GRPO/DAPO 与 Qwen3-8B/14B 的对照实验；但无同行评审、无线上 A/B 或生产部署证据，评测限于数学与代码推理基准，吞吐基准还排除了周期性 BF16 参考前向开销。

### 2. [Grow the Harness, Not the Context: From Strategy-Free Scaffolds to Reusable Specialist Agents](https://arxiv.org/abs/2609.26760)

把 harness 本身而非上下文或模型权重作为唯一学习对象，用失败反馈将重复控制固化为可执行代码，在五个 benchmark-model 设置上取得最高平均成功率同时把 LLM 调用与部署推理成本降低一个量级，改变「Agent 提效主要靠堆上下文与更大模型」的判断。

证据：arXiv 预印本，PDF 正文已核验，基于 BrowseComp-Plus 与 WebArena-Verified 的离线实验；局限是每个 benchmark 仅 50 个任务、每配置 3 次运行导致置信区间较宽，成本统计不含离线优化器与评测重试，无生产 A/B。

### 3. [Alibaba Open Sources OpenCodeReview for AI-Assisted Code Review](https://www.infoq.com/news/2026/09/alibaba-opencodereview/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=AI%2C+ML+%26+Data+Engineering-news)

展示确定性流水线承担文件选择、规则匹配与评论定位、LLM agent 只做动态分析的分工架构，可改变 coding agent harness 中「上下文与工具边界交给模型自行决定」的判断；但厂商自报优势与唯一独立评测的 12% 精度严重冲突，需以降级方式采纳。

证据：来源为 InfoQ 第三方新闻报道，含阿里内部 200 PR/10 语言 benchmark 自报精度与 token 约为 Claude Code 九分之一，但独立评测在 10 个 PR 上精度约 12% 且修复后无独立验证，AACR-Bench 最佳召回率仅 20%；属社区观察级证据。


## ② 本周 LLM 论文 / 技术报告

### [Towards Full Pipeline FP8 Reinforcement Learning for LLMs](https://arxiv.org/abs/2609.22870)｜近两日补录

**机构、作者与来源**

- **机构：University of Wisconsin–Madison 与 ByteDance Seed（第一作者为实习期间完成）**
- 作者：Fanchao Chen, Ziheng Jiang, Ziyun Wei, Zheng Zhong, Du Li, Chi Zhang, Haibin Lin, Shivaram Venkataraman
- 来源：arXiv:2609.22870v1（cs.LG, cs.AI）
- 场景：大模型全流水线 FP8 强化学习（GRPO/DAPO，数学与代码推理），非搜广推场景

**核心方法**

- 指认失效模式：全流水线 FP8 训练中单 token 概率量化误差虽小，但重要性比值放大 1.7×–2.9×，使负优势 token 在 1−ε 下界被过度裁剪、梯度被错误置零，垃圾输出未被惩罚并累积，引发训练中期熵激增
- 提出 Calibrated Clipping：用 BF16 影子前向得到负优势 token 的目标裁剪分位 α_low = F_BF16,−(1−ε)，反解 FP8 分布下界 L

**关键结果**

- Qwen3-8B-Base GRPO：blockwise FP8 加 Calibrated Clipping 平均分 58.6，高于 BF16 基线 57.6
- tensorwise/rowwise 分别从 46.1、47.0 回升至 55.9、56.5

**为什么值得读**

- 把 FP8 全流程 RL 的失败归因到重要性比值对量化误差的放大
- 并给出下界分位校准与上下界重平衡的具体配方，是低精度训练与 RL 后训练交叉方向上少见的机制级解释加可复现修复，直接影响大规模 RL 训练的稳定性和吞吐预算

**证据边界**

- 仅有 arXiv 预印本，无同行评审
- 也无任何线上 A/B 或生产部署证据
- 评测局限于数学与代码推理基准（AIME/AMC/MATH/Gaokao/Minerva/Olympiad/TACO/APPS 等），未覆盖其他任务类型与更大模型规模

### [PACT: From Credit Assignment to Critic Alignment](https://arxiv.org/abs/2609.26355)

**机构、作者与来源**

- **机构：AllSpark Team；据邮箱域名推断 Dongyan Zhao 为北京大学、Mu Chuan 为小红书**
- 作者：Jiayan Fu、Hang Xu、Yong Zhang、Zhaokai Luo、Yao Hu、Dongyan Zhao、Mu Chuan
- 来源：arXiv:2609.26355v1
- 场景：LLM RL 后训练 token-level credit 与 actor-critic 训练，在 agentic 数学推理和 SWE-bench Verified 上评估

**核心方法**

- 论文提出 Completeness、Prefix Consistency、Neutrality 三个正则条件，并证明 token-level credit 唯一表示为 C_i=E[R|F_i]-E[R|F_{i-1}]，即条件奖励预测的鞅差
- PACT 采用 Actor-then-Critic 更新顺序，在 actor 更新后用重要性采样修正 critic 目标，并用 BCE 替代 MSE 训练 critic

**关键结果**

- 数学推理：PACT 在 AIME 2025、AIME 2026、BeyondAIME、HMMT Nov. 2025 上 Avg@16 平均 72.87%，比 GRPO 高 8.80 个百分点，比 PPO(λ=1.0) 高 13.16 个百分点，比 SAO 高 21.73 个百分点
- SWE-bench Verified：PACT pass@1 67.4%，比 GRPO 高 2.0 个百分点，比 PPO(λ=1.0) 高 2.4 个百分点，比 SAO 高 3.8 个百分点

**为什么值得读**

- 在完备性、前缀一致性与中性三个条件下把 token-level credit 唯一表示为条件奖励预测的鞅差
- 并据此设计 Actor-then-Critic 更新、重要性采样修正与 BCE critic，为 LLM RL 后训练中 credit 定义混乱、critic 目标不匹配的问题提供了可对齐的算法范式

**证据边界**

- credit 唯一性依赖作者提出的三个正则条件，换条件可得到不同表示
- credit 是统计而非因果，不等同于 token 的反事实因果效应

### [Learning Generalizable Behaviors for Terminal Agents](https://arxiv.org/abs/2608.22631)

**机构、作者与来源**

- **机构：Salesforce AI Research、Carnegie Mellon University（通讯邮箱 @andrew.cmu.edu）**
- 作者：Yihang Yao、Bo Pang、Xuan Phi Nguyen、Ding Zhao、Shafiq Joty、Semih Yavuz
- 来源：arXiv:2608.22631v3（cs.LG，2026-09-24，Preprint）
- 场景：终端（命令行/软件工程）Agent 的 RL 后训练环境与验证器质量研究

**核心方法**

- 提出 Agentic Compositional Generalization 假设：预训练与 SFT 提供低层原子技能，RL 主要塑造组合、路由这些技能的高层多轮行为，因此验证器质量比单纯扩大环境数量与多样性更关键
- RIVER 配方：先用不执行沙箱的 rubric 过滤（八类质量问题，TMax 中超过 60% 环境至少命中一类），再用 GPT-5.4+Terminus-2 harness 做 pass@k=2 oracle 过滤剔除 pass@k=0，得到 RIVER-TMax-3.5K（约 3.5K 环境，<30% TMax）

**关键结果**

- River-8B（Qwen3-8B，SFT+RL）在四个终端 Agent benchmark 平均 19.4±1.2（×10^2），优于 OpenThinker-8B-RL 的 17.8±0.7 与 TMax-RL-8B 的 14.6±1.2
- 仅用不到 30% 的 TMax 环境，RIVER 在 Terminal-Bench-Lite 与 Terminal-Bench-v2.1 上平均 RL 增益分别提升 106% 与 30%（2B–27B 模型）

**为什么值得读**

- 把 agentic RL 的收益来源从「更多环境」转向「更好验证器」，用行为特征 AUC-ROC 与表征相似性分析给出 RL 主要塑形高层组合而非学习新技能的机制证据
- 并给出可复现的环境过滤与行为级 advantage shaping 配方

**证据边界**

- 全部结果为离线终端 benchmark（OpenThoughts-TBLite、Terminal-Bench-v2.1/Pro、TerminalWorld-Verified），无线上 A/B 或生产部署验证
- 行为验证器消融中只有重复惩罚带来明显整体提升，奖励 verify-before-done 无额外收益，说明行为与任务成功可能只是相关而非因果
