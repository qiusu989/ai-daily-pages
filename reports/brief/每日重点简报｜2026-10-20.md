# AI 与算力重点简报｜2026-10-20

## ① 今日最重要的 3 件事

### 1. [LoongSage: A Production-Grade, High-Efficiency Agentic RL Framework for Frontier LLMs with Validated Recipes](https://arxiv.org/abs/2610.16352)

把多轮工具调用轨迹一致性、全异步采样、拓扑感知权重同步与多教师蒸馏统一进同一 agentic RL 框架，为 coding/browser Agent 后训练基础设施提供可复用的工程配方，改变的是 agentic RL 训练效率与轨迹一致性的判断，而非算法本身。

证据：arXiv 技术报告，PDF 正文已核验；吞吐 1.35–1.40× 来自同框架 colocated 与 async 对比，未与 verl、AReaL 等外部框架同条件比较，无线上 A/B，四项训练各仅一条 run。

### 2. [DLite: History-free Speculative Decoding for Agentic AI](https://arxiv.org/abs/2610.23787)

把草稿器的全局历史建模转交目标模型、只做局部推测，同时缓解 Agent 长上下文负载下接受长度下降与草稿 KV cache 开销，改变的是 Agent 推理加速路线的取舍判断：历史无关也可维持高接受长度。

证据：arXiv v1 原始论文，PDF 正文已核验；全部结果为作者自测，限于 Qwen3-4B/8B 与 H800，未见第三方复现、生产集成成本或线上 A/B。

### 3. [Lean4AgenticRL: Advancing Agentic RL with Verifiable Multi-level Process Rewards](https://arxiv.org/abs/2610.22448)

用 Lean4 可验证工作流把过程奖励拆成结果、阶段与工具调用三层，消融显示负向工具 guard 对抑制重复命令与 reward hacking 有可观幅度，改变的是开放式 agentic RL 过程奖励可验证性的判断。

证据：arXiv v1 预印本，PDF 正文已核验；核心数字为作者自测，轨迹分段与 β 奖励依赖 LLM 标注与 LLM-as-judge，标注失败率低于 10% 但非全量人工核验，无独立复现或生产 A/B。


## ② 最新 LLM 论文 / 技术报告

### [LoongSage: A Production-Grade, High-Efficiency Agentic RL Framework for Frontier LLMs with Validated Recipes](https://arxiv.org/abs/2610.16352)

**机构、作者与来源**

- **机构：未披露**
- 作者：LoongSage Team、Bowei Song、Caiwei Zhao 等
- 来源：arXiv:2610.16352v2（技术报告）
- 场景：前沿 LLM 的 agentic RL 后训练，覆盖 SWE、数学推理、黑盒编码 Agent 与多教师蒸馏

**核心方法**

- AgentFlow 以 OpenAI Chat Completions 接口接入白盒/黑盒 Agent，采用 Token-In, Token-Out 保存采样 token、logprob 和 loss mask，避免训练前重分词造成轨迹偏差
- 全异步模式通过 train-rollout buffer 解耦采样与优化，并提供 no-window、window-gated、windowed-fifo 三种滑动窗口策略来限制策略版本陈旧度

**关键结果**

- 在 Qwen3-30B-A3B、16 张 H20 的 100 步对比中，全异步 windowed-fifo（S=2.0）把平均步时从 580.79s 降到 428.76s（1.35×），剔除首步后为 414.58s（1.40×）
- DAPO 数学推理完整运行中 rollout reward 约从 0.45 升至 0.80，K3 训练-推理差距峰值 5.3e-4 后稳定在约 4.5e-4

**为什么值得读**

- 值得读在于它给出 agentic RL 的完整工程分解决策：Token-In/Token-Out 保证多轮工具轨迹一致、滑动窗口控制策略版本陈旧、教师权重卸载到主机内存，这些是自建 Agent 后训练栈时最先撞上的瓶颈，可直接对照取舍

**证据边界**

- 四项训练各只报告一条完整 run，未给多 seed 方差
- 吞吐对比是同框架 colocated vs async，未与 verl、AReaL 等外部框架同条件对比

### [DLite: History-free Speculative Decoding for Agentic AI](https://arxiv.org/abs/2610.23787)

**机构、作者与来源**

- **机构：上海交通大学、上海创智学院、清华大学、Infinigence-AI**
- 作者：Jiaming Xu, Hanzhen Wang, Tianlang Zhao, Jiewen Xiao, Chengze Yuan, Jiayi Pan, Yongkang Zhou, Jiancai Ye, Yu Wang, Guohao Dai
- 来源：arXiv:2610.23787v1
- 场景：面向 Agent 长上下文多轮负载的 LLM 推测解码加速

**核心方法**

- DLite 不维护草稿模型的历史 KV cache，直接复用目标模型 12/14 层隐藏状态，并用可学习深度嵌入区分来源层，围绕当前锚点并行预测 K=7 个草稿 token
- 轻量低秩 RNN 式顺序头仅在隐藏空间恢复块内因果依赖，避免对每个草稿位置先做全词表投影，降低高并发下的草稿开销

**关键结果**

- Qwen3-8B 在 GSM8K 上接受长度 6.48，高于 DSpark 的 6.36
- Qwen3-4B 为 6.38 对 6.27

**为什么值得读**

- 值得读在于它挑战推测解码需维护草稿历史 KV 的默认假设
- 并给出低秩顺序头与两阶段蒸馏的处理方式

**证据边界**

- 仅 arXiv v1，未见同行评审或第三方复现，全部结果来自作者自测
- 评测限于 Qwen3-4B/8B 与 NVIDIA H800，未覆盖其他模型族、硬件或真实生产 Agent 服务

### [Lean4AgenticRL: Advancing Agentic RL with Verifiable Multi-level Process Rewards](https://arxiv.org/abs/2610.22448)

**机构、作者与来源**

- **机构：Amazon Web Services、University of Illinois Urbana-Champaign**
- 作者：Ruida Wang, Gerald Friedland, Tong Zhang, Chris Kong
- 来源：arXiv:2610.22448v1
- 场景：软件工程与终端使用 agentic 任务（SWE-Bench-Verified、TerminalBench-2.0/2.1）

**核心方法**

- 提出 problem-specific workflow 的 plan-then-execute 流程：规划 agent 先探索环境并生成任务专属工作流，执行 agent 再按该工作流求解任务
- 将 PSWF 形式化为 Lean4 可验证工作流，按 pre/post-condition 将执行轨迹分段，并联合标注 α 结果奖励、β 工作流阶段奖励和 γ 工具调用奖励

**关键结果**

- LAR-27B 在 TerminalBench-2.1 达 77.3%，在 SWE-Bench-Verified 达 84.2%，在 TerminalBench-2.0 达 68.2%
- 作者报告 LAR 系列平均超过基座模型 9.89%，并超过其已知同规模第二佳模型平均 5.07%

**为什么值得读**

- 值得读在于把形式化验证与分层过程奖励接入 GLPO 式训练
- 并明确把工具调用奖励当作负向 guard 使用

**证据边界**

- 预印本未经同行评审，核心结果为作者自测，尚未见独立复现或生产环境 A/B
- 工作流形式化、轨迹分段和 β 奖励判定依赖 LLM 标注与 LLM-as-judge，形式化边界未覆盖 LLM 内部计算
